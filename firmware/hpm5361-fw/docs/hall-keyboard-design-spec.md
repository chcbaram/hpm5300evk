## 2. 확정 구성 한눈에

```
스위치 (자석 N극 하향)
   ↓  자속 9.0 ~ 67.9 mT
PCB 1.6mm  ─── 관통 ───
   ↓
TMAG5253BA3  x96      ±80mT / 15mV/mT / X2SON 1.54mm² / 2mA
   ↓  (PCB 뒷면 실장)
[0Ω + 1nF] x96        센서별 전하 저장소 (MUX 앞). R 제거 = 시정수 제거 (3.4절)
   ↓
TMUX1308APWR x12      8:1 아날로그 MUX / TSSOP-16 / C_D(ON) 11pF
   ↓  8스텝 x 6변환, 세틀링 **실측으로 확정** (변형 A 목표 0.1~1.0us)
[100Ω, 캡 DNP] x12    ADC쪽 캡 금지 (매 스텝 재충전 부채)

   ↓  DMA (CPU 개입 0)
링버퍼 → 키로직 → HID  인터럽트 1회 / 125us

[RGB] SPI1/SPI2 MOSI ──74AHCT125──► NeoPixel 48 x 2채널
      2.4MHz / 3비트 인코딩 / DMA / 1.44ms per frame
      ⚠ 전류 예산이 최대 제약 — 11.6.4절
```

## 3. 아날로그 프론트엔드

### 3.1 센서 — TMAG5253BA3

| 항목 | 값 |
|---|---|
| 품번 | **TMAG5253BA3** (TI) |
| 방식 | 홀 효과, **양극(bipolar)** |
| 측정 범위 | **±80 mT** |
| 감도 @3.3V | **15 mV/mT** (= 18.6 LSB/mT @12bit·3.3V) |
| 입력환산 노이즈 | **0.023 mT RMS** |
| 동작 전류 | 2mA → **96키 192 ~ 250mA** |
| 패키지 | **X2SON 1.54mm²** (높이 약 0.4mm) |
| 기동 시간 | 60us |
| 실장면 | **PCB 뒷면(bottom)** |
| 단가 | 약 $0.45 @1k (DigiKey) |

**아날로그 게인단은 쓰지 않는다.** op-amp 없이 12bit 직결로 목표 분해능을 만족한다.

**BA3를 고른 이유** — 조사한 스위치 13종의 바텀 자속이 41.3 ~ 67.9 mT인데,
±40mT 이하 변종(BA1/BA2/UA2/UA5)은 **전부 포화**하고 ±160mT(BA4)는 양자화가 노이즈를 추월한다.
**±80mT가 유일하게 맞는 범위다.** → 원본 5-G.6 / 5-H.2

### 3.2 멀티플렉서 — TMUX1308APWR

| 항목 | 값 |
|---|---|
| 구성 | **8:1 x 12개** (ADC 12핀, 8 주소 스텝) |
| 패키지 | TSSOP-16 (시제품용. 양산 시 소형 패키지 검토) |
| 주소선 | 3bit (A0~A2), 전 MUX 공용 |
| **선정 기준** | **C_D(ON) = 11pF** (Ron 아님). Q_INJ 0.8pC @3.3V |
| Ron | 120Ω typ / 330Ω max @3.3V — **판정에 무관** |
| 세틀링 | **3.0us / 스텝** |

MUX 16개 x 6스텝 구성도 가능하며 세틀링 횟수가 줄어 약 6us 빠르다.
대신 ADC 16핀을 전부 소모해 DAC를 못 쓴다. **기본은 12개 구성.**

> **저Ron 부품(TMUX1108, Ron 4Ω)은 오히려 불리하다.** C_D(ON)이 65pF로 6배 크고
> Q_INJ도 2.5배다. 저Ron은 FET를 키운 대가로 용량을 지불한 결과인데, 이 회로에서
> 판정에 들어가는 건 Ron이 아니라 C_D다. → 원본 5-I.3

### 3.3 전원 / 기준전압

| 항목 | 값 | 비고 |
|---|---|---|
| 센서 VCC | **3.3V** | ADC VREFH와 **동일 LDO 공유** |
| ADC VREFH | **3.3V** | 비율계측 드리프트 상쇄 |
| ADC VREFL | **GND 고정** | 상한 미규정 = 미보증. **절대 올리지 않는다** |

VREFH 규격은 **2.4V ~ VDDA**다. 1.8V로 낮추는 안은 규격 위반이므로 폐기됐다.

### 3.4 RC 네트워크 — 확정 상수

```
TMAG5253BA3 ──[R16 0Ω]──┬──────► Sx  TMUX1308A  D ──[R18 100Ω]──┬──► ADC 핀
                        └─[C56 1nF]─ GND                         └─ (캡 없음)
```

| 위치 | 부품 | **확정값** | 수량 | 역할 / 근거 |
|---|---|---|---|---|
| 센서 직렬 | **R16** | **0Ω** | 96 | **시정수를 만드는 주범이라 제거.** 1nF 은 직결 상한 안이라 격리 불필요 |
| 센서 병렬 | **C56** | **1nF** | 96 | **전하 저장소** (C56/C_d = 91배). TMAG5253 **직결 용량 상한**(DS 9.2.3) |
| MUX 출력 직렬 | **R18** | **100Ω** | 12 | ESD·전류제한. τ_s 기여 3.3ns — 유지 |
| MUX 출력 병렬 | ~~C59/C60~~ | **DNP (미실장)** | — | **캡 금지.** 매 스텝 재충전 부채 |

> ### ★ 왜 R16 을 0Ω 으로 바꿨는가 (2026-08-02 개정)
>
> 초판의 세틀링 3.0us 는 `3 x τ_slow`, `τ_slow = R16 x C56 = 100Ω x 10nF = 1us` 였다.
> **시정수를 만드는 것은 C56 이 아니라 R16 이다.** 저항을 빼면 센서가 캡을 직접 채우므로
> 시정수가 `R16 x C56` 에서 `Z_out x C56` 으로 바뀐다 — 센서 출력 임피던스는 100Ω 보다 훨씬 낮다.
>
> C56 을 1nF 으로 낮춘 것은 **직결 상한**(DS 9.2.3) 때문이다. 이 값이면 R16 없이 직결이
> 허용되면서 저장소 비율 91 배를 유지한다.
>
> | 구성 | Q_INJ 영향 | 전하공유 강하 | 회복 시정수 |
> |---|---|---|---|
> | 초판 (10nF + 100Ω) | 0.08mV | 1.1mV | **1us** (R 지배) |
> | **개정 (1nF + 0Ω)** | 0.79mV | 10.9mV | **Z_out x 1nF** |
> | 무캡 | **73mV** | — | Z_out x 11pF |
>
> 무캡은 Q_INJ 0.8pC 가 C_D 11pF 에 73mV 로 실려 **비권장**이다.
> 동일 MCU 상용 보드도 **캡은 두고 저항만 없는** 구성이다.
>
> **세틀링은 센서 출력 임피던스에 달렸다** — 전하공유 강하 10.9mV(최악 코너 38.5mV)가
> 0.1 LSB(0.08mV)까지 빠지는 데 필요한 시간:
>
> | Z_out | τ = Z x 1nF | 필요 세틀링 (6.2τ) | 스캔 |
> |---|---|---|---|
> | 10Ω | 10ns | **62ns** | **21.9us** |
> | 100Ω | 100ns | **620ns** | 26.5us |
> | 300Ω | 300ns | 1.86us | 35.5us |
> | 1kΩ | 1us | 6.2us | 70.7us ✗ |
>
> **★ 확인 필요 — TMAG5253 데이터시트의 출력 임피던스 / 출력 구동 능력.**
> 현재 문서에 이 값이 인용돼 있지 않다. 이 하나로 세틀링이 62ns 인지 6.2us 인지 갈린다.
> `Output impedance` 항목이 없으면 `Output current` / `Short-circuit current` 로 추정하고,
> `Capacitive load stability` 곡선에서 1nF 안정성도 함께 확인한다.

**채널간 크로스토크** (ΔV=1V 최악, 12bit LSB = 0.806mV ≈ 0.0045mm):

| ADC쪽 캡 | R16=1kΩ / 세틀링 1.5us | **R16=100Ω / 세틀링 3.0us** |
|---|---|---|
| 1nF | **99 LSB ≈ 0.44mm** ✗ | 5.7 LSB ✗ |
| 220pF | 25 LSB ✗ | 1.4 LSB △ |
| **DNP** | 1.6 LSB △ | **0.09 LSB** ✓ |

> **ADC 핀에 캡을 달면 안 된다.** 게인단이 없어서 그 캡을 다시 채워줄 저임피던스
> 드라이버가 없다. 유일한 충전원이 센서의 10nF인데 그 뒤에 R16이 있어서,
> 캡을 달수록 매 MUX 스텝마다 이전 채널 전압이 잔류한다.
> 캡을 달면 샘플 시정수 `τ_s = (Ron+R18) x (C_d + C_sh)`도 함께 커져
> **ADC 채널 크로스토크(4.1절)까지 악화**된다 — 220pF에서 4.5 LSB. → 원본 5-I.2 / 5-I.6

> **대안 B** — 밴드제한(fc 16kHz)을 유지하려면 `R16=100Ω + C56=100nF`도 성립한다
> (ε₀ 0.015%, 세틀링 없이 0.19 LSB). 다만 TMAG5253 데이터시트가 **직결 용량 상한 1nF**을
> 명시(9.2.3절)하므로 아이솔레이션 100Ω에 100nF은 스코프 검증 필수.
> 기본안(10nF)은 fc가 159kHz로 올라가 밴드제한을 잃지만, BA3 출력 노이즈가
> 2.3mVpp(0.43 LSB)뿐이라 손실이 0.1 LSB에 그친다.

**시제품 실장 변형** — R16 을 0402 교체 패드로, C56 을 겸용 풋프린트로 두고 아래를 스윕한다.

| 변형 | R16 | C56 | 세틀링 목표 | 스캔 | 판정 |
|---|---|---|---|---|---|
| **A (기본)** | **0Ω** | **1nF** | 0.1 / 0.3 / 1.0us 스윕 | 21.9 ~ 26.5us | 검증 6·7번 통과 시 확정 |
| B (보수 · 후퇴안) | 100Ω | 10nF | 3.0us | 45.1us | A 실패 시 |
| ~~C (무캡)~~ | 0Ω | DNP | — | 21.7us | **비권장** — Q_INJ 73mV |

**A 로 시작해 검증 6·7번으로 판정하고, 실패하면 B 로 후퇴한다.** 부품 값 교체만으로 오갈 수 있다.

## 4. ADC / 타이밍

### 4.1 ADC 설정

| 항목 | 값 |
|---|---|
| 해상도 | **12bit** (`adc16_res_12_bits`) |
| 근거 | 데이터시트 **ENOB = 12비트** 명시. 16bit는 하위 4비트가 전부 노이즈 |
| 샘플 클럭 Ns | **8** (t_conv = (14+8)/50MHz = **440ns**) |
| Ns 근거 | **ADC 채널 크로스토크** 흡수. τ_s = **21.8ns 최악** → 160ns = 7.3τ (아래) |
| ADC 클럭 | 50MHz (ANA 클럭) |
| 채널 분리 | ADC0 = IN0~IN7, ADC1 = IN8~IN15 |
| 오버샘플링 | **1x** |

> ### ADC 채널 크로스토크 — MUX 크로스토크와 **다른 현상**
>
> 하나의 ADC가 6개 핀을 순차 변환하므로, 샘플캡 `C_sh(4pF)`가 핀을 옮길 때
> **이전 핀의 전압을 물고 온다.** 이건 MUX 세틀링(3us)이 끝난 뒤에 발생하므로
> **세틀링으로는 막을 수 없고 오직 샘플 시간(Ns)으로만 흡수된다.**
>
> ```
> τ_s = (Ron_mux + R18) x (C_d + C_sh)  +  Ron_adc x C_sh
>       └ MUX·외부 저항이 노드 전체를 충전     └ ADC 내부 샘플 스위치 (DS 표35: 300Ω)
>   typ : 220Ω x 19pF + 300Ω x 4pF =  4.18 + 1.20 =  5.4 ns
>   max : 430Ω x 48pF + 300Ω x 4pF = 20.64 + 1.20 = 21.8 ns
> ```
>
> | Ns | t_sample | 최악 코너 잔류 (85°C, C_D 40pF, Ron 330Ω, ΔV=1.5V) |
> |---|---|---|
> | 2 | 40ns | **27 LSB** ✗ |
> | 4 | 80ns | **4.0 LSB** ✗ |
> | **8** | **160ns** | **0.10 LSB** ✓ |
>
> 비용은 스캔 41.3 → **45.1us (+3.8us)** 뿐이다. → 원본 5-I.6
>
> **`C_sh = 4pF`와 `Ron_adc = 300Ω`은 데이터시트 표35에서 확인됨**(가정 아님).
> ADC 내부 스위치 저항은 초판 계산에 빠져 있었고, 넣으면 τ_s가 6% 늘어난다.

| 크로스토크 | 원인 | **대책** | 무관한 것 |
|---|---|---|---|
| **MUX 채널간** | 드레인 C_D가 이전 채널 전압 보유 | **세틀링 3.0us** + R16 100Ω | Ns를 올려도 안 줄어듦 |
| **ADC 채널간** | 샘플캡 C_sh가 이전 핀 전압 보유 | **Ns = 8** | 세틀링을 늘려도 안 줄어듦 |

**오버샘플링을 쓰지 않는 이유**: 같은 MUX 주소에서 연속 변환하는 **버스트 오버샘플은
샘플 간격이 320ns**인데 센서 노이즈 상관 시간이 **10us**라 같은 값을 반복해 읽을 뿐이다
(4x로 3% 개선). 노이즈를 실제로 줄이려면 **분산 스캔**(스캔 주파수를 16kHz로 올려
샘플을 상관 시간 밖으로 벌리는 방식)이 맞고, 1x로도 SNR 9.4σ 이상이라 급하지 않다.

> **이 결론은 17차 RC 변경(R16 1kΩ→100Ω)의 영향을 받지 않는다.** 상관 시간 10us는
> RC(구 1kΩ x 10nF = 10us)와 우연히 같은 값이지만 실제 출처는 **센서 자체의
> 대역폭 fBW = 15kHz** (τ = 1/2πf = 10.6us)다. R16을 낮춰도 그대로다.

### 4.2 125us 예산

| 단계 | 시간 | CPU |
|---|---|---|
| 96채널 ADC 취득 (12bit, 1x) — 8 x (**세틀링 3.0** + 6 x **0.44**) | **45.1us** | **0%** (DMA/TRGM 자동) |
| 키로직 96키 (거리변환 5.8 + 래피드트리거 4.3) @400MHz | **12.1us** | CPU |
| HID 리포트 조립 + USB 제출 + ISR @400MHz | **6.2us** | CPU |
| **합계** | **약 63.5us / 125us (51%)** | CPU 18.4us (15%) |

> **세틀링은 미확정이다.** 위 45.1us 는 **변형 B(R16=100Ω, C56=10nF, 세틀링 3.0us)** 기준의
> 보수적 값이다. 3.4 절의 **변형 A(R16=0Ω, C56=1nF)** 가 검증을 통과하면:
>
> | | 스캔 | CPU | 합계 | 점유 |
> |---|---|---|---|---|
> | 변형 B (세틀링 3.0us) | 45.1us | 18.4us | 63.5us | **51%** |
> | **변형 A (세틀링 0.62us)** | **26.5us** | 18.4us | **44.9us** | **36%** |
> | 변형 A (세틀링 0.1us) | 21.9us | 18.4us | 40.3us | 32% |
>
> **시제품 검증 6·7번으로 확정한 뒤 이 표를 갱신한다.**

> **CPU 400MHz 기준이다.** VDD_SOC 를 외부 LDO 1.2V 로 공급하므로 데이터시트 표9 의
> **균형모드(400MHz, 1.15/1.175/1.30V)** 구간에서 동작한다. 480MHz(성능모드)는 최소 1.25V 를
> 요구하는데 고정 LDO 로 1.25~1.30V 창을 맞추기 어렵다 —
> [hpm5361-power-clock-design.md](hpm5361-power-clock-design.md) 3 절.
> ADC 취득 45.1us 는 ANA 클럭 기준이라 **CPU 클럭과 무관**하다.

**여유 충분.** 125us당 **인터럽트 1회**로 설계한다.

> 17차에서 스캔이 27 → 45.1us가 됐다(**+18us**). 내역은 **세틀링 1.5→3.0us(+12us)**,
> **Ns 4→8(+3.8us)**, 그리고 기준값 정정(문서가 Ns=2/320ns로 계산하고 있었다).
> CPU 부하는 불변이고 총 48%다.
>
> 더 필요하면 세틀링을 **4.0us**(4τ)까지 올려도 스캔 53.1us / 총 68.4us(55%)로 예산 안이다.
> **줄이는 방향은 권하지 않는다** — 세틀링과 Ns는 각각 **다른 크로스토크**를 막고 있고
> (4.1절 표), 둘 다 최악 코너(85°C, C_D 40pF max, Ron 330Ω max) 기준으로 잡은 값이다.

### 4.3 하드웨어 파이프라인

```
GPTMR0 CH0 COMP ──DMA req──> DMA: mux_addr_table[N] → GPIO0.DO      (t = 0)
GPTMR0 CH1 COMP ──TRGM0────> ADC0.STRGI + ADC1.STRGI                (t = t_settle)
                               └─ 시퀀스 6변환 x 2 ADC 병렬
                                  DMA → 링버퍼 (384B, 32bit 패킹)

주소 스텝 8회 완료 → 인터럽트 1회 / 125us → 키로직 → HID
```

스텝마다 ISR을 타면 64kHz 인터럽트가 되어 실패한다. **반드시 스텝 8회 완료 후 1회.**

| 장치 | 역할 |

| ADC0 + ADC1 | 시퀀스 모드 + HW 트리거 + DMA (시퀀스 최대 16엔트리) |

## 5. 신호 체인 / 분해능

### 5.1 자속 → LSB

전제: PCB 1.6mm 뒷면 실장, 비선형 계수 **n = 1.65** (`B ∝ g^-n`, 제조사 스펙으로 검증됨)

| 항목 | 값 |
|---|---|
| 바텀 자속 범위 (스위치 13종) | **41.3 ~ 67.9 mT** |
| ΔB (동작 스윙) | **30.3 ~ 58.7 mT** |
| BA3 범위 점유율 | **52 ~ 85%** (공차 최악 92%) |
| 전 스트로크 카운트 | 564 ~ 1,092 |
| 상단 0.1mm 신호 | **0.260 ~ 0.385 mT** |
| **상단 LSB / 0.1mm** | **4.8 ~ 7.2 LSB** |
| 합성 노이즈 σ | 0.52 LSB (센서 0.43 + 양자화 0.29) |
| **상단 SNR** | **9.4 ~ 13.9σ** |

**판정 기준은 LSB가 아니라 SNR이다.** 초기 검토의 "0.1mm당 8~10 LSB"는
σ ≈ 1~2 LSB를 전제로 3σ를 확보하려던 **대리 지표**였다. BA3에서는 σ가 0.52 LSB로
작아졌으므로 요구 LSB도 함께 내려간다. 직접 지표인 SNR로 **9.4σ 이상, 목표(3σ) 대비 3배 여유**다.

### 5.2 키당 처리 파이프라인

```
① DMA 워드 언패킹                  raw → val
② EMA 필터                        ema += (avg - ema) >> 2        [α = 1/4, 지연 0.5ms]
③ 2점 정규화 (역수 곱셈)            n = (ema - rest) * 65535 / (bottom - rest)
④ 선형화 LUT + 선형보간             n → 거리 d (1/256mm 고정소수점)
⑤ 래피드 트리거 상태머신            d → pressed / released
⑥ NKRO 비트맵 갱신 (Zbs bset/bclr)
```

| 항목 | 결정 |
|---|---|
| LUT | **스위치 종류당 1개 공용** (65엔트리 x 2B = 130B). 키별은 rest/bottom 2점만 캘리브레이션 |
| EMA 계수 | **α = 1/4** (시정수 0.5ms) |
| 상단 데드존 | **0.2mm** (분해능이 죽는 구간) |
| 캘리브레이션 히스테리시스 ε | 5 LSB |
| 자동 재캘리브레이션 | 무입력 3초 후 (온도 드리프트 대응) |

**③번(선형 정규화)만으로는 "신호 선형"이지 "거리 선형"이 아니다.
진짜 0.1mm 단위를 원하면 ④번 LUT이 필수다.**

### 5.3 CPU 예산 (480MHz, 125us = 60,000 사이클)

| 항목 | 사이클/키 |
|---|---|
| ADC → 거리 변환 (①~④) | 약 29 |
| 래피드 트리거 + 비트맵 (⑤⑥) | 15~21 |
| **키당 합계** | **45~50** |

| 항목 | 96키 사이클 | 시간 |
|---|---|---|
| 거리 변환 | 2,784 | 5.8us |
| 래피드 트리거 + 비트맵 | 2,040 | 4.3us |
| HID 리포트 + USB 제출 | 2,000 | 4.2us |
| ISR 오버헤드 | 500 | 1.0us |
| **총계** | **7,324** | **15.3us (12%)** |

## 6. 명령어셋 / 빌드

**코어는 Andes D25F, ISA는 RV32-IMAFDCPB** — 배정밀도 FPU(F/D)와 SIMD(P)가 실제로 존재한다.
현재 빌드는 `-march=rv32imac_zicsr_zifencei_zba_zbb_zbc_zbs`로 **F/D/P를 끄고 있다.**

**이 상태를 유지한다.**

| | F/D를 켰을 때 |
|---|---|
| 핫패스 성능 | **이득 없음** — 거리 변환이 전부 정수 LUT 경로 |
| ISR 오버헤드 | **손해** — 컨텍스트 스택 96B → **256B** (레지스터 +40회 접근) |
| 코드 크기 | 이득 (부동소수점을 쓸 때만. soft-float 에뮬레이션 루틴 -8.5KB) |

- 거리 변환은 **고정소수점 + LUT 보간**. FPU가 없어서가 아니라 **LUT이 더 빠르기 때문**이다.
- 나눗셈은 **역수 곱셈 + 시프트**로 대체 (D25F의 DIV는 다중 사이클·비파이프라인).
- **P(DSP) 확장은 xpack GCC 13.4.0이 지원하지 않는다.** 쓰려면 Andes/HPMicro 툴체인 필요.

> **근거**: HPM5300 데이터시트 Rev0.11 (`C49451870.pdf`) 표2 SOC IOMUX 전수 파싱.
> 원본 2.1절의 ADC 매핑(EVK 회로도 역추출)과 **16핀 전부 일치**함을 확인했다.

ADC1 : IN10, IN9, IN13, IN8, IN12, IN14 (PB07,06,05,03,02,01)
```

DAC0과 내장 OPA 경로를 둘 다 살려둔 배치다.

**nTRST(PA08)는 커넥터에 넣지 않는다.** JTAG 규격상 `TMS=1 로 TCK 5 클럭`이면 TAP 리셋이
되므로 필수가 아니다. 대신 **PA08 에 10k 풀업**을 달아 TAP 이 리셋에 갇히지 않게 하고,
필요하면 테스트 패드만 하나 뺀다. (20 핀 헤더를 쓸 여유가 있으면 nTRST 를 3 번에 포함해도 된다.)

**풀 저항** — 리셋 직후 패드가 뜨면 스퓨리어스 TAP 천이가 생긴다.

| 신호 | 저항 | 이유 |
|---|---|---|
| TMS (PA07) | **10k 풀업** | 아이들 하이가 TAP 안전 상태 |
| TDI (PA05) | 10k 풀업 | |
| TCK (PA06) | **10k 풀다운** | 스퓨리어스 클럭 방지 |
| nTRST (PA08) | **10k 풀업** | 미배선 시 TAP 이 리셋에 갇히지 않게 |
| TDO (PA04) | 없음 | 출력 |

> **왜 nSRST 가 필요한가 — 실물 사례**
>
> 동일 MCU 를 쓴 상용 보드(GEONWORKS VENOM60HE)는 앱 동작 중 **`unable to halt`** 로
> 디버거가 붙지 않는다. IDCODE 와 DM 은 응답하는데 하트가 halt 요청에 응답하지 않는다 —
> 저전력/WFI 상태로 보이며, 8kHz 스캔 중인 키보드가 그 상태에 들어갈 경우는 **USB 서스펜드**뿐이다.
>
> **nSRST 로 리셋을 잡은 채 붙으면 펌웨어 실행 전에 코어를 세우므로 앱 상태와 무관해진다.**
> 이것이 1 차 방어이고, 2 차는 디버그 빌드에서 저전력 진입 비활성화, 3 차는 BOOT0 스트랩(USB ISP)이다.

**MUX 주소 테이블** — 3비트 주소가 bit 9~11에 연속으로 놓이므로 DMA 테이블이 단순하다:

```c
/* MUX_EN# = 0 (enable), addr N */
static const uint32_t mux_addr_table[8] = {
    0u << 9, 1u << 9, 2u << 9, 3u << 9,
    4u << 9, 5u << 9, 6u << 9, 7u << 9,
};   /* → GPIO0->DO[GPIO_OE_GPIOA].VALUE */
```

### 11.4 배치 제약 3가지

**(1) DMA 워드에 안 들어가는 PA GPIO 출력을 두지 말 것**

`hpm_gpio_regs.h`의 레지스터 구조는 `DO[port].VALUE`가 **포트 단위 32비트**다.
DMA가 주소 테이블을 `DO[A].VALUE`에 통째로 쓰므로, **그 워드에 포함되지 않은 PA GPIO
출력은 매 스텝 0으로 덮어써진다.**

`DO[].VALUE`는 **OE가 설정된 GPIO 출력만** 구동한다. 따라서 영향 범위는 다음과 같다:

| PA 핀 유형 | 영향 | 해당 핀 |
|---|---|---|
| DMA 워드에 포함된 GPIO 출력 | **의도된 동작** | MUX_A0~A2(PA09~11), MUX_EN#(PA12) |
| 그 외 GPIO 출력 | **매 스텝 0 으로 덮어써짐** ✗ | 두지 말 것 |
| 페리페럴 ALT | 무관 (GPIO DO 가 패드를 잡지 않음) | JTAG PA04~08, UART0 PA00/01, NeoPixel PA29/PA23 |
| 입력 | 무관 (OE 미설정) | BOOT0/BOOT1 (PA02/03) |

**MUX 주소선을 PA 에 둔 것은 이 제약의 예외가 아니라 목적 그 자체다.** bit 9~12 가 연속이라
테이블이 `N << 9` 하나로 끝나고 **스텝당 DMA 전송 1 회**로 주소와 EN# 이 동시에 갱신된다.

> **★ SENS_EN 은 이 제약에 걸려 PA13 → PY04 로 옮겼다.** 초판은 SENS_EN 을 PA13 에 두었는데,
> `mux_addr_table[]` 의 어느 항목도 bit 13 을 세우지 않으므로 **스캔 스텝마다 센서 96 개가
> 꺼진다.** 대안으로 테이블 전 항목에 `| (1<<13)` 을 OR 하는 방법도 있으나, 그러면
> SENS_EN 을 끌 수 없게 되어 USB 서스펜드 시 전원 차단(§14 항목 3)을 잃는다.
>
> GPIO 출력이 필요한 그 밖의 신호(LED 등)도 **PY 포트(PGPIO)** 에 둔다.

> `DO[].SET` / `DO[].CLEAR`를 쓰면 포트를 보존할 수 있으나 임의 3비트 값을 쓰려면
> 전송이 2회 필요해 DMA 디스크립터가 2배가 된다. **PA 전용화가 더 싸다.**

**(2) MUX_EN#은 active-LOW다**

TMUX1308A 진리표(데이터시트 표8-1/8-2): **EN = 0 → 채널 선택, EN = 1 → 전 채널 OFF.**
4051의 INH와 같은 극성이다. 회로도의 `EN#` 표기가 맞다.

| 신호 | 리셋 시 상태 | 외부 저항 |
|---|---|---|
| MUX_A0~A2 | 입력(Hi-Z) | **10k 풀다운** — CMOS 입력 플로팅 방지 |
| MUX_EN# | 입력(Hi-Z) | **10k 풀업** — 부팅 중 전 채널 OFF로 확정 |
| SENS_EN (**PY04**) | 입력(Hi-Z) | 10k 풀다운 (부팅 중 센서 OFF → 돌입전류 회피) |

핀이 부족하면 **MUX_EN#은 GND 직결(상시 인에이블)로 대체 가능**하다. 스캔 중에는 항상
어떤 채널이 선택돼 있으므로 기능상 손실이 없다. 다만 USB 서스펜드 시 전력 차단과
디버깅 편의를 위해 GPIO 유지를 권한다.

**(3) 주소선은 아날로그 뱅크 반대편으로 뺀다**

MUX 주소선은 **64kHz로 스위칭**한다(8스텝 x 8kHz). PA09~PA12는 LQFP100 **4~6, 11번**으로
아날로그 뱅크(45~63, VIO_B01)와 패키지 반대편이다. 주소선이 MAG_CHx 배선과
평행 주행하지 않도록 라우팅하고, 그 사이에 GND를 깐다.

### 11.6 NeoPixel (WS2812 계열) 2채널

**SPI MOSI + DMA 방식**을 쓴다. GPIO 비트뱅잉은 11.4-(1) 제약(PA 포트 GPIO 출력 금지)
때문에 **불가능**하고, PWM+DMA는 800kHz DMA 요청이 필요해 비싸다. SPI는 페리페럴 ALT라
`DO[A].VALUE` 덮어쓰기의 영향을 받지 않는다.

#### 11.6.1 핀 배정

| 신호 | 핀 | LQFP100 | ALT | 담당 |
|---|---|---|---|---|
| **NEOPIX_D0** | PA29 | **79** | SPI1_MOSI (ALT5) | 좌측 48키 |
| **NEOPIX_D1** | PA23 | **88** | SPI2_MOSI (ALT5) | 우측 48키 |
| **LED_PWR_EN** | PY03 | **38** | PGPIO 출력 | 5V 로드 스위치 게이트 |

- **SPI0은 못 쓴다** — PA04~PA07이 JTAG이다. **SPI1 + SPI2를 쓴다.**
  둘 다 MOSI만 쓰므로 SCLK/MISO/CS 패드는 미사용으로 둔다.
- SENS_EN이 PY04로 이동하면서 **PA13이 비었다.** PA13은 `SPI3_MOSI(ALT5)` 이므로
  3 번째 LED 채널이 필요하거나 SPI1/SPI2 중 하나가 배선상 곤란해지면 **예비로 쓸 수 있다.**

> **실물 검증** — 상용 HE 키보드(GEONWORKS VENOM60HE, 동일 HPM5361)를 덤프 분석한 결과
> **정확히 같은 핀·같은 방식**을 쓴다: `PA29 = SPI1_MOSI (ALT5)` + DMA.
> 차이는 인코딩뿐이다 — 본 설계는 24MHz / WS2812 1비트 = SPI 3비트,
> 상용품은 8MHz / 1비트 = SPI 1바이트(8비트). LED 83개, 프레임버퍼 83 x 24B.
> **SPI MOSI + DMA 방식이 양산품에서 동작함이 확인된 셈이다.**
- 두 핀 모두 패키지 **77~100번 변**이라 아날로그 뱅크(45~63)와 반대편이다. 800kHz 신호가
  MAG_CHx 배선과 평행 주행하지 않게 라우팅한다.
- **LED_PWR_EN은 PY 포트**다. PA에 GPIO 출력을 두면 MUX 주소 DMA가 덮어쓴다(11.4-(1)).

#### 11.6.2 SPI 설정 — 3비트 인코딩

WS2812 비트 1개 = SPI 3비트. **SPI 클럭 소스를 24MHz(XTAL 직결)로 두면 분주가 딱 떨어진다.**

```
sclk = spi_clk / (2 x (SCLK_DIV + 1)) = 24MHz / (2 x (4+1)) = 2.4MHz   (SCLK_DIV = 4)
SPI 1비트 = 416.7ns

  WS2812 '0' → 0b100 : T0H = 417ns  (규격 0.4us ±150ns) ✓
  WS2812 '1' → 0b110 : T1H = 833ns  (규격 0.8us ±150ns) ✓
  총 비트 주기 = 1.25us ✓
```

| 항목 | 값 |
|---|---|
| 채널당 LED | 48 |
| 채널당 DMA 버퍼 | 48 x 24bit x 3 / 8 = **432 B** (DLM `.noncacheable`) |
| 전송 시간 | 48 x 24 x 1.25us = **1.44 ms** |
| 최대 갱신률 | 694 Hz (실사용 100~200Hz면 충분) |
| DMA 채널 | SPI1_TX(0x2B) + SPI2_TX(0x2D) — HDMA 32채널 중 2개 |
| CPU 비용 | RGB→SPI 변환은 **256엔트리 LUT**로 바이트당 3B. 144B/채널, 갱신률에서만 발생 |

두 채널을 **동시에 시작**하면 전송 시간이 반이고 피크 전류도 두 급전점으로 갈린다.

> **MOSI 아이들 레벨을 LOW로 확정할 것.** WS2812 리셋은 `>50us LOW`인데 SPI 유휴 시
> MOSI가 마지막 비트를 유지하면 리셋이 안 걸린다. **10k 풀다운 + 프레임 끝에 0x00 패딩**
> 을 넣고 스코프로 확인한다.

#### 11.6.3 레벨 시프트 — 필수

WS2812B의 `VIH = 0.7 x VDD`다. VDD=5V면 **3.5V**가 필요한데 MCU는 3.3V라 **규격 미달**이다.

| 방법 | 판정 |
|---|---|
| **74AHCT125 (쿼드) 1개** — TTL 입력(VIH 2.0V @5V), 3.3V→5V 변환 | **★ 채택.** 2채널 사용, 2게이트 예비 |
| LED 전원을 4.3V로 낮춤 (5V − 쇼트키) | VIH 3.0V로 내려가 동작하나 휘도·색온도가 변한다 |
| 3.3V 직결 | WS2812B 규격 하한 3.5V 미만. **불가** |

첫 LED만 시프트하면 된다(이후는 앞 LED가 5V로 구동). 데이터 라인에 **330Ω 직렬**(링잉 감쇠),
스트립 급전점마다 **1000uF 벌크 + 0.1uF**를 둔다.

#### 11.6.4 ★ 전류 예산 — 이게 진짜 제약이다

| 항목 | 전류 |
|---|---|
| 센서 96개 | 250 mA |
| MCU | 약 100 mA |
| **소계** | **350 mA** |
| **USB 2.0 표준 예산** | **500 mA** |
| **RGB에 남는 것** | **150 mA** |

WS2812B는 **LED를 다 꺼도 IC 정지전류가 약 1mA/개** → 96개면 **96mA**다.
실제 발광에 쓸 수 있는 건 **약 54mA / 96개 = 0.56mA/LED**이고, 풀화이트(60mA/LED) 대비
**약 1%**다. **USB 500mA로는 RGB가 사실상 불가능하다.**

**대책 3가지 (전부 필요)**

| # | 대책 | 내용 |
|---|---|---|
| **1** | **Type-C CC 감지** | Rd 5.1k만 달면 기본 500mA다. 소스가 1.5A/3A를 광고하면 CC 전압으로 감지해서 RGB를 켠다. **감지 못 하면 RGB 비활성** |
| **2** | **펌웨어 전류 모델** | `I = Σ(R+G+B)/765 x 60mA` 를 프레임마다 계산해 예산 초과 시 전역 스케일 다운. 하드 상한 |
| **3** | **LED_PWR_EN 로드 스위치** | RGB 미사용 시 5V를 완전 차단해 정지전류 96mA를 0으로. PY03 제어 |

> 저전류 대안: **WS2812B-2020 / SK6812 mini-E**로 바꿔도 풀화이트 전류는 비슷하다.
> 전류를 줄이는 건 부품이 아니라 **밝기 상한**이다.

#### 11.6.5 아날로그 간섭 — 시간 분리가 아니라 전기 분리로 막는다

원본 5-B.7 #5는 *"RGB가 있으면 ADC 샘플 중 PWM 금지"* 였는데, **NeoPixel에는 적용할 수 없다.**
PWM이 LED 칩 내부(약 1.25kHz)에서 돌아가 MCU가 시점을 제어할 수 없고, 전송 자체도
1.44ms라 125us 스캔 주기 안에 넣을 수 없다.

| 경로 | 상쇄 여부 | 대책 |
|---|---|---|
| **3.3V 레일 변동** | **비율계측이 상쇄** (센서 VCC = VREFH 공유) | LDO PSRR로 충분 |
| **GND 오프셋** | **상쇄 안 됨** ← 위험 | ★ 아래 |
| 데이터선 크로스토크 | — | 800kHz 라인을 아날로그 배선과 이격 |

**LED 리턴 전류(수백 mA~A)가 공통 GND를 흐르면 센서 GND와 MCU VREFL 사이에 IR 강하가
생기고, 이건 비율계측으로 상쇄되지 않는다.** 반드시:

1. LED 5V/GND를 **USB 커넥터에서 별도로 딴다** (스타 접지)
2. 센서 어레이 아래 아날로그 GND 아일랜드는 **한 점에서만** 메인 GND에 연결
3. LED 리턴 경로가 센서 어레이 밑을 지나지 않게 한다

이 항목은 **9절 미확정에 실측 항목으로 추가**한다 — RGB 풀화이트 on/off 시 정지 키의
ADC 값 변화가 **< 1 LSB**여야 한다.
