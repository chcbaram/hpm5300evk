# HPM5361 기반 8kHz 마그네틱(홀) 키보드 타당성 검토

- 작성일: 2026-07-26
- 대상 MCU: HPM5361 (HPM5300 시리즈, RISC-V rv32imac + Zb*, CPU 480MHz)
- 목표: USB HS 8kHz 폴링(125us 주기) 안에서 80키(5x16) 홀센서 ADC 취득 → 키로직 → HID 전송
- 검토 근거: 본 저장소의 HPM SDK 헤더/드라이버, `hardware/HPM5300EVKREVC.pdf` 회로도 파싱
- 상태: **문서 검토 단계. 실측 검증 전.**

> ## ⚠ 개정 이력 — 먼저 읽을 것
>
> | 회차 | 내용 | 영향 |
> |---|---|---|
> | 1차 | 기본 타당성 (3~5절) | — |
> | 2차 | 12bit 채택 (3-A절) | — |

## 1. 요약

125us 예산 안에서

| 단계 | 시간 | CPU 개입 |
|---|---|---|
| 80채널 ADC 취득 — **①안** TMAG5253 UA5(단극), 12bit 1x | **26us** | 0% (DMA/TRGM 하드웨어 자동) |
| └ ②안 BA3(양극) + VREFH 1.8V + 2x | 38us | 0% |
| └ ③안 BA3(양극) + VREF 3.3V + 4x | 70us | 0% |
| 키로직 80키 처리 (거리변환 4.8us + 래피드트리거 3.5us) | 8.3us | CPU |
| HID 리포트 조립 + USB 제출 + ISR | 5.2us | CPU |
| **합계 (①안 기준)** | **약 40us / 125us (32%)** | CPU 부담은 13.6us(11%) |

**결론: 타이밍 여유 충분.** 병목은
(1) **자석 극성 / 센서 변종 선택 (5-D.5)**,
(2) 아날로그 입력 핀이 16개뿐이라는 점, (3) MUX 세틀링, (4) 아날로그 노이즈다.

**0.1mm 분해능**: 12비트로 **아날로그 게인단 없이 달성된다** (상단 10~20 LSB/0.1mm).
6차 개정에서 비선형 계수를 TI 실측 지오메트리로 정정한 결과다. → **5-D절**

125us당 CPU 인터럽트는 **1회**로 설계 가능하다.

## 2. 가장 중요한 하드웨어 제약: 아날로그 입력은 16핀

EVK 회로도의 MCU 핀 정의를 파싱한 결과:

- 아날로그 입력 패드는 **PB00 ~ PB15, 정확히 16개**
- 각 패드가 `ADC0.INx` **와** `ADC1.INx`를 **동시에** 갖는다 (예: PB04 = ADC0.IN0 = ADC1.IN0)
- 즉 ADC0/ADC1은 **같은 16개 패드를 공유**하는 별개의 SAR 변환기 2개다.
  아날로그 채널이 32개가 아니라 **핀 16개 + 변환기 2개**.

### 2.1 ADC 입력 핀 매핑

| INx | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 핀 | PB04 | PB09 | PB10 | PB11 | PB12 | PB13 | PB14 | PB15 |

| INx | 8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |
|---|---|---|---|---|---|---|---|---|
| 핀 | PB03 | PB06 | PB07 | PB08 | PB02 | PB05 | PB01 | PB00 |

### 2.2 파생 결론

- 8:1 MUX 기준 최대 **16 x 8 = 128키**까지 확장 가능. 80키는 여유.
- PB 전체를 아날로그로 쓰면 나머지 디지털 기능은 PA00~PA31에 배치.
  현재 디버그 UART0가 PA00/PA01이라 **충돌 없음**.
- PB08 = DAC0.OUT, PB09 = DAC1.OUT, PB00/PB01 = OPA0/OPA1.OUT 이므로
  아날로그 보조 기능을 쓰려면 해당 핀을 매트릭스에서 빼야 한다.

## 3. ADC 타이밍 모델

SDK 레지스터 정의에서 나온 실제 식
(`src/lib/hpm_sdk/soc/HPM5300/ip/hpm_adc16_regs.h` CONV_CFG1 주석):

```
1샘플 시간 = (SAMPLE_CLOCK_NUMBER + CONVERT_CLOCK_NUMBER) / f_adc

CONVERT_CLOCK_NUMBER : 16bit=21, 12bit=14, 10bit=11, 8bit=9  [ADC 클럭]
SAMPLE_CLOCK_NUMBER  : 1 ~ 511 (+ 3bit shift)
f_adc = ADC 소스클럭 / CLOCK_DIVIDER(1~16)
```

ADC 클럭 소스는 **AHB(160MHz)** 또는 **전용 ANA 클럭** 중 선택
(`clk_adc_src_ahb0` / `clk_adc_src_ana0` / `clk_adc_src_ana1`).

- 안전 설정: AHB / 4 = **40MHz**
- 상한이 50MHz까지 허용되면 ANA 클럭으로 **50MHz** (데이터시트 확인 필요)

### 3.1 1샘플 시간

| 해상도 | 샘플클럭 | 총 클럭 | @40MHz | @50MHz |
|---|---|---|---|---|
| 16bit | 11 | 32 | 800ns | 640ns |
| 16bit | 4 | 25 | 625ns | 500ns |
| 12bit | 11 | 25 | 625ns | 500ns |
| 12bit | 4 | 18 | 450ns | 360ns |

### 3.2 80키 전체 스캔 (ADC0/ADC1 병렬)

채널 분리: **ADC0 = IN0~IN7, ADC1 = IN8~IN15** (같은 패드 동시 변환 금지)

| 구성 | 사용 핀 | 주소 스텝 | 16bit/40MHz | 12bit/50MHz |
|---|---|---|---|---|
| A: 8:1 MUX 10개 | 10핀 | 8스텝 x 5변환/ADC | **40us** | 22us |
| B: 8:1 MUX 16개(5ch씩 사용) | 16핀 | 5스텝 x 8변환/ADC | **37us** | 19us |

(MUX 세틀링 1us/스텝 가정 포함)

### 3.3 처리량 여유

- ADC 순수 처리량: 2 x 약 2MSPS = **약 4MSPS**
- 실제 필요량: 80채널 x 8kHz = **640kSa/s (약 16%)**
- → **4배 오버샘플링해도 예산 안**에 들어온다.

단, HPM5361은 **하드웨어 오버샘플링(`ADC_LOOP`) 미지원**이므로
시퀀스를 여러 번 돌려 SW 평균해야 한다.

### 3.4 DMA 데이터량

- `DMA_SEQ16BIT` 미지원 → 시퀀스 DMA는 **샘플당 32bit 패킹**
  (`result:16 / seq_num:4 / adc_ch:5 / cycle_bit:1`)
- 80샘플 = **320B / 125us = 2.56MB/s**. 160MHz AHB 대비 무시할 수준.
- 4x 오버샘플링 시 320샘플 = 1280B (더블버퍼 2560B).
- 채널번호가 결과와 함께 들어오므로 **정합성 검증에 유리**하다.

## 3-A. 해상도 선택: 12bit 채택 근거 (2026-07-26 검토)

**결론: 12bit + 4배 오버샘플링 평균을 기본 설계로 한다.**

### 3-A.1 12bit 전환의 순수 절감량

```
16bit: 21 + Ns 클럭 / 12bit: 14 + Ns 클럭  →  Δ = 7 클럭 / 샘플
```

| f_adc | 샘플당 절감 | 80채널(2 ADC 병렬, 40변환/ADC) 절감 |
|---|---|---|
| 40MHz | 175ns | **7.0us** |
| 50MHz | 140ns | **5.6us** |

### 3-A.2 전체 스캔 비교 (세틀링 1us/스텝 포함)

구성 A — 8:1 MUX 10개, 8스텝 x 5변환/ADC

| 설정 | 16bit | 12bit | 절감 |
|---|---|---|---|
| Ns=11, 40MHz | 40.0us | **33.0us** | -17.5% |
| Ns=4, 50MHz | 28.0us | **22.4us** | -20% |

구성 B — 8:1 MUX 16개, 5스텝 x 8변환/ADC

| 설정 | 16bit | 12bit | 절감 |
|---|---|---|---|
| Ns=11, 40MHz | 37.0us | **30.0us** | -19% |
| Ns=4, 50MHz | 25.0us | **19.4us** | -22% |

**변환부만 -33%지만 전체 스캔은 -17~22% (절대 5.6~7.0us).**
MUX 세틀링과 샘플 클럭이 고정 오버헤드로 남기 때문이다.
125us 예산에서 6us 자체는 결정적이지 않다.

### 3-A.3 진짜 이득 — 오버샘플링 여유

같은 MUX 주소에서 연속 N회 변환하면 **세틀링은 스텝당 1회만** 발생한다.
스텝 시간 = `t_settle + N x (채널수/ADC) x t_conv`

구성 A, Ns=4 @50MHz:

| 오버샘플 | 16bit | 12bit |
|---|---|---|
| 1x | 28us | 22.4us |
| 2x | 48us | **36.8us** |
| 4x | 88us (빠듯) | **65.6us (여유)** |

구성 B, 4x: 16bit 85us vs 12bit **62.6us**

→ **16bit로는 4배 오버샘플링이 예산 한계, 12bit면 여유롭게 들어온다.**

12bit + 4x 평균 = **실효 약 13bit + 노이즈 1/2**.
ADC16의 실제 ENOB이 16bit에 한참 못 미치므로
**12bit 4x 평균이 16bit 원시값보다 실측 품질이 더 좋다.**
4mm 스트로크 / 4096 = 약 1um 분해능이라 해상도도 충분하고도 남는다.

### 3-A.4 해상도보다 SAMPLE_CLOCK_NUMBER가 더 큰 레버

| 조합 | 총 클럭 | 대비 |
|---|---|---|
| 16bit + Ns=11 | 32 | 기준 |
| 12bit + Ns=11 | 25 | -22% |
| 16bit + Ns=4 | 25 | -22% |
| **12bit + Ns=4** | **18** | **-44%** |

Ns는 소스 임피던스(MUX Ron x 입력 용량)로 결정된다.
74HC4051(Ron 약 170Ω) 대신 **TMUX1108 / ADG708(Ron 수십Ω)** 을 쓰면
Ns를 4~8까지 내릴 수 있고, 이게 해상도 조정보다 효과가 크다.
**해상도 인하와 저Ron MUX는 같이 가야 한다.**

### 3-A.5 구현 유의점

- `config.res = adc16_res_12_bits` **설정만으로 충분**하다.
  `adc16_init()`이 `COV_END_CNT = 21 - res + 1`을 자동으로 맞춘다
  (`src/lib/hpm_sdk/drivers/src/hpm_adc16_drv.c:216`). 수동 레지스터 조작 불필요.
- **해상도는 ADC 인스턴스 단위**(`CONV_CFG1`),
  **샘플 클럭은 채널 단위**(`SAMPLE_CFG[16]`).
  → 배선이 긴 채널만 Ns를 늘리는 식으로 채널별 튜닝이 가능하다.
- **결과 정렬 확인 필요** — `ADC16_SOC_MAX_SAMPLE_VALUE`가 해상도와 무관하게 65535이므로
  결과가 16bit 필드에 MSB 정렬(좌측 정렬)될 가능성이 높다. 12bit면 값이 `<<4` 된 형태.
  **실측 확인 항목.**

> 분해능이 **키 스트로크 0.1mm 인식**에 충분한지는 별도 검토가 필요하다. → **5-A절**

## 4. 사용할 MCU 내부 장치

### 4.1 핵심 경로 (CPU 개입 0)

| 장치 | 역할 | 비고 |
|---|---|---|
| **ADC0 + ADC1** (ADC16, 16bit SAR) | 시퀀스 모드 + HW 트리거 + DMA | 시퀀스 최대 **16엔트리** |
| **HDMA (32ch) + DMAMUX** | ① ADC 결과 → 링버퍼 ② MUX 주소 테이블 → GPIO DO | DMA 컨트롤러는 1개, 32채널 |
| **GPTMR0** (또는 PWM0) | 125us 마스터 주기 + 스텝 트리거 | COMP 채널 2개로 위상차 부여 |
| **TRGM0** | 타이머 → `ADC0_STRGI` / `ADC1_STRGI` 라우팅 | 프리엠션은 `ADCX_PTRGI0A~3C` |
| **GPIO0 / FGPIO** | MUX 주소 A0~A2 (뱅크 분리 시 6핀) | FGPIO는 코어 로컬버스, 1사이클 |
| **USB0** | HS + 온칩 UTMI PHY, HID Interrupt IN bInterval=1 (125us) | 이미 HS로 동작 확인됨 |
| **ILM 128K / DLM 128K** | 핫패스 코드(`.fast`/ramfunc) + DMA 버퍼 | XIP 플래시 실행은 지터 때문에 금지 |

### 4.2 선택적으로 쓸만한 것

| 장치 | 용도 |
|---|---|
| **PLB** (Programmable Logic Block) | MUX 주소 3bit 카운터를 순수 HW로 → DMA 채널 1개 절약 |
| ~~OPAMP0 / OPAMP1~~ | **채널 2개뿐이라 10~16ch 게인단으로 부적합.** 외부 TLV9064 사용 (5-B.4) |
| **ACMP** | 임계 통과 고속 검출 |
| **DAC0 (PB08)** | **★ 채택 — 게인단 오프셋 기준전압 V_ref 생성** (5-B.5). DAC1(PB09)은 예비 |
| **ADC 워치독** | 채널별 상/하한 임계값 → 통과 키만 인터럽트 플래그 |
| **MCHTMR** | 타임스탬프 |
| **EWDG** | 워치독 |

### 4.3 권장 파이프라인

```
GPTMR0 CH0 COMP ──DMA req──> DMA: mux_addr_table[N] → GPIO0.DO      (t = 0)
GPTMR0 CH1 COMP ──TRGM0────> ADC0.STRGI + ADC1.STRGI                (t = t_settle)
                               │
                               └─ 시퀀스 5~8변환 x 2 ADC 병렬
                                  DMA → 링버퍼 (320B, 32bit 패킹)

주소 스텝 N회 완료 → 인터럽트 1회 / 125us
                     → 키로직 → HID 리포트 → usbd_ep_start_write()
```

**125us당 인터럽트 1회.** 스텝마다 ISR을 타면 64kHz 인터럽트가 되어 실패한다.

## 5. CPU 부하 추정

480MHz → 125us당 **60,000 사이클**

| 항목 | 사이클 |
|---|---|
| 80키 x (베이스라인 차감 + LUT 보간 + IIR 필터 + 래피드트리거 SM) ~60~200 | 4,800 ~ 16,000 |

### 5.1 명령어셋 제약

빌드 플래그: `-march=rv32imac_zicsr_zifencei_zba_zbb_zbc_zbs` (CMakeLists.txt:233)

- **FPU 없음, DSP 확장 없음, 하드웨어 나눗셈 없음**
- 거리 변환은 부동소수점이 아니라 **고정소수점 + LUT 보간**으로 구현
- 나눗셈은 **역수 곱셈 + 시프트**로 대체
- Zba/Zbb/Zbs는 사용 가능 (비트 조작, 시프트-덧셈 주소계산)

### 5.2 메모리 배치

`src/bsp/ldscript/HPM5361_FLASH_XIP.ld` 기준:

| 영역 | 주소 | 크기 | 용도 |
|---|---|---|---|
| ILM | 0x00000000 | 128K | 핫패스 코드 (`.fast`, ramfunc) |
| DLM | 0x00080300 | 128K - 768 | 데이터, DMA 버퍼, `.noncacheable` |
| AHB_SRAM | 0xF0400000 | 32K | 보조 |

- 펌웨어는 **플래시 XIP 실행**이다. 스캔/키로직/ISR은 반드시 ILM으로 옮겨야 지터가 잡힌다.
- D-Cache가 켜져 있으므로 DMA 버퍼는 `.noncacheable.bss`에 두거나 매번 invalidate.

## 5-A. 0.1mm 분해능 타당성 및 거리 계산 (2026-07-26 검토)

**결론: 12비트면 충분하다. 단, 아날로그 게인 8배가 전제조건이다.**
비트 수가 아니라 **센서 출력 스윙이 ADC 풀스케일을 얼마나 채우는가**가 실제 제약이다.

### 5-A.1 공개 자료 실측 앵커

| 출처 | 데이터 |
|---|---|
| Lucca-58HE (오픈소스 58키 HE) | DRV5053VA + ADG732 32ch MUX + RP2040 **12bit / 3.3V**, 센서 스윙 **약 0.4V**, 스트로크 3.5mm → **0.00706mm/LSB** |
| libhmk (8kHz 지원 HE 라이브러리) | 거리 내부표현 **0~255(8bit)**, EMA α지수=4(=1/16), 캘리브레이션 500ms / ε=5 LSB, 무입력 3s 후 재캘리브레이션, `adc_to_distance(filtered, rest, bottom)` |
| minipad-firmware | Rapid Trigger **0.01mm 해상도**, SW 저역통과 필터 |
| TI DRV5053 | VA = **-90mV/mT**(최고감도), Vq=1V, 출력 0~2V |
| TI TMAG5253 | BA2 = **30mV/mT / ±40mT**, BA3 = 15mV/mT / ±80mT |
| ATTACK SHARK 기술 아티클 | "저가 구현은 0.01mm를 표방해도 실제로는 노이즈를 감추려 펌웨어에서 0.1mm로 반올림한다" |

### 5-A.2 함정 — 자기장 비선형성

자기장은 `B ∝ 1/g^n` (실측 기반 n ≈ 1.6~3)으로 감쇠한다.
**바닥 근처는 민감하고 상단(누르기 시작하는 구간)은 둔하다.**

갭 5mm(rest) → 1mm(bottom), 스트로크 4mm, n=1.6 기준:

```
상단 민감도 / 평균 민감도 = r ≈ 0.106   (약 1/9.4)
```

> ⚠ **6차 개정에서 정정됨.** TI SLYA093이 밝힌 실제 스위치 지오메트리는
> 갭 **6.1mm → 2.1mm** 로 여기 가정(5→1mm)보다 훨씬 멀다.
> 실제 값은 **r = 0.227** 이다. 아래 5-A.3 / 5-A.4의 수치는 모두 **2.1배 낙관적으로 상향**된다.
> → **5-D.2절 참조**

→ **액추에이션이 걸리는 상단 구간의 분해능이 평균의 1/10.**
평균값으로 계산하면 안 되고 **항상 상단 최악값으로 판정**해야 한다.

### 5-A.4 판정 기준

노이즈 σ ≈ 1~2 LSB(필터 후) 기준, 채터 없이 0.1mm 변화를 확정하려면
**0.1mm당 8~10 LSB**가 필요하다. 역산하면:

```
필요 전 구간 카운트 = 목표LSB(10) / r(0.106) x (4mm / 0.1mm) ≈ 3,800 카운트
```

**12비트 = 4096. 거의 딱 맞는다 — 충분하지만 여유는 없다.**

- 16비트로 올려도 ENOB가 13비트를 못 넘으므로 해결되지 않는다.
- ~~해결책은 ADC 비트가 아니라 아날로그 게인이다.~~

> ⚠ **6차 개정에서 정정됨.** r = 0.227 로 바꾸면 필요 카운트는
> `10 / 0.227 x 40 = 1,762` — **12비트 4096의 43%면 충분하다.**
> **아날로그 게인단 요구는 철회한다.** → 5-D.3절

### 5-A.5 게인 확보 방법 (권장순)

1. **MUX 출력단 게인/오프셋 제거 단** ★ 권장
   키당이 아니라 MUX당이므로 10~16개(쿼드 op-amp 3~4패키지)면 된다.
   `V_out = (V_sensor - V_rest) x 8`
   고속 RRIO(OPA2365급 50MHz) 사용 시 정착시간 약 0.5us 추가 → 3절 세틀링 예산에 반영 필요.
2. **고감도 센서 + 자석/갭 최적화** — 스윙 자체를 키우는 게 가장 저렴.
   DRV5053VA(-90mV/mT)는 이미 최고감도이므로 자석 세기와 센서 거리로 조정.
3. HPM5361 내장 **OPAMP0/OPAMP1은 2개뿐**이라 16채널을 못 덮는다. 외부 op-amp 필수.
4. 상단 0.2~0.3mm는 데드존 처리 — 상용 키보드가 실제로 쓰는 방식.

### 5-A.6 키당 처리 파이프라인

```
① 4x 오버샘플 평균     raw[4] → avg                                (HW 취득분)
② EMA 필터            ema += (avg - ema) >> k
③ 2점 정규화          n = (ema - rest) * 65535 / (bottom - rest)   [0..65535]
④ 선형화 LUT + 보간    n → 거리 d (1/256mm 고정소수점)
⑤ 래피드 트리거 SM     d → pressed / released
⑥ NKRO 비트맵 갱신     Zbs 명령 (bset/bclr)
```

**③번이 libhmk가 하는 전부**다(rest~bottom 선형 정규화, 0~255).
이건 "신호 선형"이지 "거리 선형"이 아니다.
**진짜 0.1mm 단위를 원하면 ④번 LUT이 필수다.**

- LUT은 **스위치 종류당 1개 공용**(65엔트리 x 2B = 130B)으로 두고,
  키별로는 rest/bottom 2점만 캘리브레이션한다.
- 키별 LUT(80 x 64 x 2B = 10KB)도 DLM에 들어가지만 캘리브레이션 지그가 필요해 비현실적.
- 80키가 같은 LUT을 참조하므로 캐시 히트율 100%.

### 5-A.7 EMA 필터 지연 — 중요한 트레이드오프

libhmk의 α=1/16은 8kHz에서 시정수 **16샘플 = 2ms**다.
8kHz 폴링을 하는 의미가 사라진다.

| α | 시정수 @8kHz | 노이즈 저감 | 판정 |
|---|---|---|---|
| 1/16 | 2.0ms | 4x | 지연 과다 |
| 1/8 | 1.0ms | 2.8x | 보수적 |
| **1/4** | **0.5ms** | **2x** | **★ 채택** |

**하드웨어 4x 오버샘플링이 이미 노이즈를 절반으로 줄이므로 EMA는 가볍게 간다.**
오버샘플링은 지연이 0이고 EMA는 지연이 생기기 때문이다.

### 5-A.8 래피드 트리거 (0.1mm 인식의 실사용처)

0.1mm 분해능이 필요한 진짜 이유. 래피드 트리거의 최소 민감도가 0.1mm다.

```c
// d: 현재 거리 (0=릴리즈 ... FULL=바닥), 1/256mm 고정소수점
if (!k->pressed) {
    if (d < k->valley) k->valley = d;              // 최저점 추적
    if (d >= k->actuation ||                        // 절대 액추에이션
        d - k->valley >= k->down_sens)              // 연속 래피드 트리거
    { k->pressed = true;  k->peak = d; }
} else {
    if (d > k->peak) k->peak = d;                   // 최대 눌림 추적
    if (k->peak - d >= k->up_sens ||                // 상승 감지 → 즉시 릴리즈
        d <= k->release_floor)
    { k->pressed = false; k->valley = d; }
}
```

**설계상 핵심**: 래피드 트리거는 절대값이 아니라 **차분(peak - d)** 으로 판정한다.
따라서 필요한 것은 절대 정확도가 아니라 **차분 분해능**이고,
판정 임계값이 노이즈 3σ보다 커야 채터가 없다.

```
0.1mm에 해당하는 LSB > 3σ   →   σ=2 LSB 이면 0.1mm당 6 LSB 이상
```

5-A.4절의 "8~10 LSB" 기준과 일치한다.

추가 필수 요소:

- **peak/valley 추적 히스테리시스 ε** (libhmk `MATRIX_CALIBRATION_EPSILON = 5`)
- **상단 데드존** — rest 근처 0.2mm는 무조건 릴리즈 (분해능이 죽는 구간)
- **자동 재캘리브레이션** — libhmk는 무입력 3초 후. 온도 드리프트 대응.

### 5-B.1 핵심 발견 — 정밀 MUX가 필요 없다

**op-amp를 MUX 뒤에 두면 MUX의 부하가 op-amp (+)입력(수 pA)이 된다.**
전류가 흐르지 않으므로:

- **Ron이 전압 강하를 전혀 만들지 않는다** (240Ω x 1pA = 0.24pV)
- 세틀링도 Ron x op-amp 입력용량(수 pF) = **수 ns**로 무의미
- 남는 것은 **누설전류**뿐 — 74HC4051 @25도 약 0.1uA x 1kΩ = 0.1mV = **0.12 LSB**, 무시 가능

### 5-B.5 회로 — 게인/오프셋 조정 가능 버전

```
[센서 80개]
HAL9303SO ──[1kΩ]──┬────────────────────► 74HC4051 입력
  (AVDD 3.3V)      └─[10nF]─ AGND
                    ↑ RC fc=16kHz. 노이즈 대역제한 + MUX 차지인젝션 흡수

[MUX 10개 → op-amp 10ch]
74HC4051 OUT ──[Rg]──┬──[Rf]──┐
                     │        │
                  (-)│        │
                TLV9064       │
                  (+)│  ├─────┘
V_ref ───────────────┘  └── OUT ──[100Ω]──┬──► ADC 핀 (PB0x)
 (HPM DAC0, PB08)                          └─[1nF]─ AGND
                                             ↑ ADC 샘플링캡 리저버 + 안티앨리어싱
```

```
V_out = V_ref x (1+G) − V_mux x G ,   G = Rf/Rg
릴리즈 시 V_out = 0 이 되도록 :  V_ref = V_rest x G/(1+G)
  예) G=4, V_rest=1.65V → V_ref = 1.32V   (DAC로 소프트웨어 설정)
```

**RC 상수 근거**: 1kΩ x 10nF = τ 10us.
1m/s 키 속도에서 지연 = 0.01mm(무시 가능). 100nF를 쓰면 τ=100us → 지연 0.1mm로 **분해능과 같아져 안 된다.**

### 5-B.6 "대응 가능한 버전" — 3중 조정 수단

| 조정 대상 | 방법 | 이유 |
|---|---|---|
| **게인 G** | Rf를 0402 패드로 **G=2/4/8/16 저항 교체** | **자석/갭 확정 전에는 최적 G를 알 수 없다.** 필요 G = (VREFH x 0.9)/(감도 x ΔB). ΔB=5mT면 G=12.6, ΔB=25mT면 G=2.5 |
| **오프셋 V_ref** | **HPM5361 DAC0 (PB08)** 소프트웨어 설정 | 센서 개체차/온도드리프트를 재부팅 없이 흡수 |
| **게인단 유무 비교** | MUX OUT → ADC 직결 **0Ω 점퍼 패드** 병설 | 게인단 효과를 실측 검증. **시제품의 핵심** |

**핀 배치가 정확히 맞아떨어진다:**
8:1 MUX 10개 → ADC **10핀** 사용, 남는 6핀 중 **PB08 = DAC0(V_ref 생성)**,
PB09 = DAC1(예비), 나머지 4핀 여유.
(2.1절 매핑: PB08=IN11, PB09=IN1)

## 5-C. 부품 재검증 (2026-07-26 2차 조사)

5-B절의 1순위 선정이 성급했다는 지적에 따라 재검증했다.
**결론: HAL9303SO 1순위를 "잠정"으로 격하하고, MUX는 TMUX1308 계열로 상향한다.**

### 5-C.1 HAL9303SO 저전류는 사실로 확인됨

조이스틱 홀/TMR 센서를 리버스엔지니어링한 Hackaday 프로젝트 로그에서:

| 항목 | 측정값 |
|---|---|
| Ginfull L4B 홀 스틱 소비전류 | **700uA (독립 실측)** |
| 해당 스틱의 칩 | **Hallwee HAL9303으로 추정** |
| 전압 사양 | 1.6~5.5V (typ 3.3V) — HAL9303SO 스펙과 일치 |

데이터시트 값(800uA)과 독립 실측(700uA)이 일치한다. **저전류는 마케팅이 아니다.**
저전력 홀 IC는 홀 소자를 duty-cycle 바이어스하거나 chopper로 저대역 동작시켜 이 수준이 나온다.

### 5-C.2 확인된 대가 3가지 — 정량 검토

**(a) 출력 구동능력 약함 — 검토 결과 문제 없음**

같은 로그의 관찰: *"상승 시간은 빠른데 하강 시간이 매우 느리다 (출력 커패시턴스 때문)"*.
5-B.5의 10nF 필터 커패시터와 충돌할 수 있어 정량 검토했다.

| 상황 | 필요 전류 |
|---|---|
| 키가 눌리는 중 (0.4V / 4ms) | **1.0 uA** |
| 스프링 복귀 최속 (0.4V / 5ms, 0.8m/s) | **0.8 uA** |
| MUX 차지인젝션 회수 (10pC / 125us) | **0.08 uA** |

아무리 약한 출력단도 uA 단위는 나온다. 조이스틱에서 문제가 된 건 그쪽 보드의
커패시터가 100nF~1uF 급이고 스틱 복귀가 스프링으로 훨씬 빠르기 때문으로 보인다.
**우리 조건과 2~3자릿수 차이. 10nF 유지가 맞다.**

> **10nF을 줄이면 안 된다.** 74HC4051 차지인젝션 10pC가 1nF에는 10mV를,
> 10nF에는 1mV를 만든다. 이 오차는 채널마다 결정론적이라 rest/bottom 캘리브레이션이
> 통째로 흡수한다. 커패시터가 클수록 유리하다.

**(b) 노이즈 — 원리적으로 불리한 것은 사실**

```
홀 전압      V_H ∝ I_bias × B
홀 소자 열잡음 √(4kTRΔf)  — 저항에만 의존
→ SNR ∝ 바이어스 전류
```

800uA 부품이 2.4mA 부품(DRV5053)보다 원리적으로 불리하다.
다만 우리 조건에서 상당 부분 상쇄된다:

- 필요 대역폭이 **16kHz뿐**이다(키 움직임은 수백 Hz). 저전력 홀 IC의 좁은 대역폭이
  여기선 오히려 유리하다 — 노이즈는 √Δf로 줄어든다.
- 2x 오버샘플링 + EMA α=1/4가 추가로 깎는다.

**정량 데이터가 없어 실측 전에는 알 수 없다.**

**(c) ★ 진짜 리스크 — 데이터시트 부재**

HAL9303SO의 **노이즈, 비선형성, 출력 구동능력, 대역폭이 전부 미공개**다.
LCSC 스펙 표에도 없고, 데이터시트 PDF는 4개 경로로 시도했으나 봇 차단으로 접근 실패.

LCSC가 공개하는 전부:
> 감도 2.1/4.7mV/Gs · 소비전류 800uA · 1.6~5.5V · ±35mT · 감도 온도계수 ±0.1%/℃ · rail-to-rail

**비선형성 스펙이 없다는 건 0.1mm를 노리는 설계에서 심각하다.**
LUT은 *재현 가능한* 비선형성만 보정한다. 개체차나 온도로 곡선이 흔들리면 대응 불가.

### 5-C.3 TMR 옵션 — 매력적이지만 래피드 트리거에 부적합

| | HAL9303SO | DRV5053VA | TMR2615 |
|---|---|---|---|
| 감도 | 47mV/mT | **90mV/mT** | 프로그래머블 |
| Iq (80키) | **800uA (64mA)** | 2.4mA (192mA) | **215uA (17mA)** |
| **데이터시트** | ✗ **미공개** | ✓ **TI 완비** | ✓ 공개 |
| 비율계측 | 가능성 있음(rail-to-rail) | ✗ 내부 레귤레이션(0~2V) | — |
| **히스테리시스** | **0 (홀 원리상)** | **0** | ✗ **2 Gs** |
| 패키지 | SOT-23-3 | SOT-23-3 | DFN3L 1.6mm, **X축 감지** |

**TMR의 자기이력이 결정적 문제다.** 자기저항 소자의 물리적 특성이다.

```
ΔB = 25mT = 250 Gs 를 4mm에 걸쳐 쓸 때  →  2 Gs = 0.032mm 불감대
```

래피드 트리거는 방향 반전 검출이 전부인데, 반전할 때마다 0.032mm의 죽은 구간이 생긴다.
up_sensitivity 0.1mm면 3배 마진이라 동작은 하지만 **0.05mm 설정은 못 쓴다.**
ΔB가 작아지면 더 나빠진다.

**홀 센서는 히스테리시스가 원리적으로 0이다** — 갈바닉 효과라 자기이력이 없다.
→ **래피드 트리거 키보드에는 홀이 원리적으로 유리하다.**
(조이스틱은 절대 위치만 쓰므로 TMR이 맞다. 용도가 다르다.)

추가로 TMR2615는 **X축(면내) 감지**라 자석이 수직 접근하는 키보드 구조와 방향이 안 맞는다.
SOT-23 홀은 패키지 면에 수직(Z축) 감지다.

### 5-C.4 센서 판단 수정

**1순위를 확정하지 않고 시제품에서 실측 비교한다.**

- 5-B.2의 "1순위 HAL9303SO" → **"1순위(잠정) — 실측 검증 조건부"** 로 격하
- **8키 시제품 보드에 SOT-23-3 풋프린트를 공용으로** 설계하여
  HAL9303SO / DRV5053VA / AH49E 교차 실장
  (세 부품 모두 SOT-23-3. **핀 배열 1=VCC/2=GND/3=OUT 여부는 반드시 확인**)
- 측정 항목: ① 정지 시 ADC 표준편차 σ ② 전 스트로크 출력 곡선(비선형성) ③ 10nF 부하 스텝 응답
- 판정 기준: σ ≤ 2 LSB (게인단 후), 곡선 재현성 ±1 LSB
- **데이터시트를 못 구하면 양산 부품에서 제외**한다

**DRV5053VA 전력 재검토** — 전류 3배는 감당 가능하다:

```
센서 80 × 2.4mA = 192mA + MCU 약 100mA + op-amp 7mA = 약 300mA
USB 2.0 500mA 안에 들어간다 (RGB 백라이트 없을 때)
```

단점은 출력이 내부 레귤레이션(0~2V, Vq=1V)이라 **비율계측 트릭(5-B.7 ①)을 못 쓴다.**
대신 정밀 VREF가 필요하다.

### 5-C.5 MUX 재검토 — TMUX1308 (상용 HE 키보드 채택 실적)

**TMUX1308 상세** (TI 제품 페이지 기준): VDD 1.62~5.5V, Ron typ 59Ω, 대역폭 500MHz,

**상용 제품이 TMUX1308을 고른 이유 (추정)**

1. **SOT-23-THN 8.4mm² — 74HC4051 SOIC-16의 약 1/6.** 80키 보드에서 면적이 곧 비용
2. 1.62~5.5V → 3.3V 직접 구동 (74HC4051은 3.3V에서 Ron이 크게 오름)
3. **Ron 59Ω → 게인단 없이 ADC 직결 가능**
4. 1.8V 로직 호환 → MCU 전압 자유
5. injection current control → ESD/이상전압 견고성

> **시사점: 상용 제품은 게인단 없이 MUX → ADC 직결일 가능성이 높다.**
> Ron이 낮은 MUX를 고른 이유가 그것 말고는 없다.
> 5-B.1의 "Ron 무관" 논리는 **op-amp 게인단을 쓸 때만** 성립한다.

**두 아키텍처 비교**

| 회피책 | 센서 감도↑ / 자석 강화 / 상단 데드존 확대 | 전 구간 확보 |
| MUX 요구 | **Ron·차지인젝션 중요** | **무관** |

**권장: 하이브리드.** TMUX1308(작고 저Ron)을 쓰되 op-amp 게인단도 유지한다.
그러면 5-B.6의 0Ω 우회 점퍼로 **(A)와 (B)를 같은 보드에서 실측 비교**할 수 있다.

### 5-D.1 원문에서 확인된 사실

**① 실제 스위치 지오메트리 (인용)**

> *"For these magnetic switches, the bottom of the magnet sits about **6.1mm** away from the
> top of the sensor when unpressed. The magnet then moves about **4mm** down and sits
> **2.1mm** away when fully pressed. The magnet is an axial cylinder magnet with remanence
> equal to that of a **YX18 samarium cobalt** magnet, diameter roughly **2.818mm**,
> height about **3.387mm**."*

네오디뮴이 아니라 **사마륨코발트(SmCo) YX18** 이다.

**② TI 권장 센서는 양극(bipolar) 변종**

> *"the variant that can allow for the highest sensitivity with no saturation can be the
> **TMAG5253BA3**"* — ±80mT / 15mV/mT
> *"the TMAG5253BA3 provides greater granularity than the TMAG5253BA4"* (±160mT / 7.5mV/mT)

**③ EN 핀 멀티플렉싱**

> *"multiple devices can share the same analog output which helps to reduce system cost by
> reducing the number of required ADCs"*
> *"The TMAG5253 is capable of supporting a capacitive load of 1nF. This means that if the
> load capacitance on each sensor is 20pF, **up to 50 sensors can share the same output**."*

**④ TIMSS** — TI Magnetic Sense Simulator. 자석 형상/재질/이동거리 + 센서 조합의

**⑤ 기타** — TMAG5231(고정밀 홀 스위치, on/off만 필요할 때 샘플링이 더 빠름),
TMAG3001(노브용 3D 홀 + CORDIC 각도 엔진 + 버튼 감지).
§4 예제 설계(4키+노브)는 **실제로 아날로그 멀티플렉서를 쓴다**
(*"uses a multiplexer to switch between the four ADC outputs"*).

### 5-D.2 ★ 비선형 계수 정정 — r = 0.106 → 0.227

축방향 원통 자석 온축 자계식으로 재계산했다.

```
B(z) = (Br/2) [ (z+H)/sqrt((z+H)^2+R^2) - z/sqrt(z^2+R^2) ]
R = 1.409mm, H = 3.387mm, Br(YX18 SmCo) ~ 0.87T
```

| z (자석 바닥 ↔ 센서) | B |
|---|---|
| 6.1mm (미압축) | **6.40 mT** |
| 5.6mm (0.5mm 눌림) | 7.92 mT |
| 2.1mm (완전압축) | **60.13 mT** |

```
ΔB          = 53.7 mT  (스트로크 4mm 전체)
평균 감도    = 13.4 mT/mm
상단 감도    = (7.92-6.40)/0.5 = 3.04 mT/mm
r = 3.04 / 13.4 = 0.227
```

| | 5-A절 가정 | **TI 실측 지오메트리** |
|---|---|---|
| 갭 | 5.0 → 1.0mm | **6.1 → 2.1mm** |
| ΔB | 25mT (추정) | **53.7mT** |
| **r** | 0.106 | **0.227 (2.1배 완화)** |

**자석에서 멀수록 곡선이 완만해진다.** 5-A절 가정이 지나치게 공격적이었다.
ΔB=53.7mT가 BA2(±40mT)를 넘고 BA3(±80mT)에 들어가는 것도 TI 선택과 일치한다 — 계산 검증됨.

### 5-D.3 재계산 — op-amp 게인단 철회

```
상단 LSB/0.1mm = 카운트 x r / 40      (r = 0.227)
목표 10 LSB → 필요 카운트 = 10 x 40 / 0.227 = 1,762   (12bit 4096의 43%)
```

| 안 | 구성 | 스윙 | 카운트 | **상단 LSB/0.1mm** | 오버샘플 후 | 스캔 | 부품 추가 |
|---|---|---|---|---|---|---|---|
| **①** | **TMAG5253 UA5 단극(52mT)** | 2.9V | 3,600 | **20.4** | — (1x로 충분) | **약 26us** | **없음** |
| **②** | BA3 양극 + **VREFH 1.8V** | 0.81V | 1,843 | **10.5** | 14.8 (2x) | 38us | 레퍼런스+SPDT |
| **③** | BA3 양극 + VREF 3.3V + **4x** | 0.81V | 1,005 | 5.7 | **11.4** | 70us | **없음** |
| (참고) | Lucca DRV5053VA 직결 | 0.4V | 496 | 2.8 | 5.6 (4x) | — | — |

**세 안 모두 목표(8~10)를 넘긴다. op-amp 게인단은 필요 없다.**

- 5-A.4 / 5-A.5 / 5-B의 "아날로그 게인 8배 필수" 결론과 **6절 리스크 12번을 철회한다.**
- op-amp는 **시제품 보험**으로만 남긴다 (0Ω 우회 점퍼, 5-B.6).

**부수 효과 — MUX 선택 근거가 바뀐다**

op-amp가 빠지면 MUX가 ADC 샘플링 커패시터를 직접 구동한다.
→ **5-B.1의 "Ron 무관" 논리가 무효가 되고, Ron·차지인젝션이 다시 중요해진다.**
→ **TMUX1308(Ron 59Ω) 채택이 오히려 더 강하게 정당화된다.** 상용 제품 선택과 일치.
→ 센서별 RC(1kΩ+10nF)는 유지한다. ADC 샘플캡은 10nF 리저버에서 Ron 59Ω를 통해
  충전되므로 τ = 0.3ns, 문제 없다.

### 5-D.4 EN 핀 멀티플렉싱 — 8kHz에는 부적합

아날로그 MUX를 없앨 수 있어 매력적이나, 기동시간이 예산을 깨뜨린다.

```
TMAG5253 기동시간 < 25us
 8스텝 x 25us = 200us  >  125us          ✗
16 ADC핀 x 5스텝 x 25us = 125us          → 여유 0
파이프라인 불가 — 같은 출력 라인 공유라 두 센서를 동시에 enable 못 함
```

→ **아날로그 MUX 유지.** EN 핀은 **스캔창 밖 전체 셧다운(전력 절감)** 용도로만 쓴다.
스캔 26~38us + 기동 25us = 약 50~63us 켜짐 → 듀티 40~50% → **평균 전류 절반**.
TI 문서는 배터리 키보드/저속 스캔을 상정한 것으로 보인다.

| 14 | 필터 지연 | EMA α=1/16이면 시정수 2ms로 8kHz의 의미 소멸 | α=1/4 채택 (5-A.7) |

### 6.1 HPM5361에서 **지원하지 않는** ADC16 기능 (확인 완료)

`hpm_soc_ip_feature.h`에 정의된 ADC16 기능은 다음 3개뿐이다:
`ADC16_HAS_MOT_EN`, `ADC16_SEQ_HCFG_EN`, `ADC16_HAS_BUS_MODE_EN`

따라서 아래는 **미지원**:

- `ADC16_HAS_ADC_LOOP` — 하드웨어 오버샘플링 없음 → SW 평균 필요
- `ADC16_HAS_DMA_SEQ16BIT` — 16bit 전용 DMA 없음 → 샘플당 4바이트
- `ADC16_HAS_DIFF_MODE` — 차동 입력 없음
- `ADC16_SEQ_STOP_POS_INT` — 없음

## 7. 다음 단계

1. **EVK 실측 벤치** — ADC0/ADC1 시퀀스 + GPTMR/TRGM 트리거 + DMA 최소 구성을 올리고
   GPIO 토글로 실제 스캔 시간을 오실로스코프 측정.
   위 표의 세틀링 가정만 실측치로 대체하면 설계가 확정된다.
2. **ADC 클럭 상한 / ENOB 확인** — 데이터시트.
   함께 **12bit 결과의 MSB 정렬 여부**도 실측 (3-A.5).
3. **ADC0/ADC1 동시 변환 간섭 검증** — 5번 리스크.
4. **MUX 부품 선정 후 세틀링 실측** — 3번 리스크. 전체 스캔 시간을 좌우한다.
5. **CherryUSB HID 추가** — HS bInterval=1 디스크립터, 더블버퍼 QTD.
6. **★ TIMSS 시뮬레이션 선행** (5-D.1 ④) — 실측 전에 TI Magnetic Sense Simulator로
   우리가 쓸 스위치의 자석(SmCo YX18급, D2.8 x H3.4mm)과 TMAG5253 변종 조합의
   출력 곡선을 계산한다. **ΔB와 포화 여부를 부품 주문 전에 확정할 수 있다.**
   그 다음 실물로 검증한다. (기존 "자석 ΔB 실측"을 대체)
6b. **TMAG5253 UA 극성 확인** — 리스크 22. UA2/UA5가 N극 감지인지.
   N극 변종이 있으면 ①안, 없으면 ②안. **이게 아키텍처를 가른다.**
7. **★ HAL9303SO 데이터시트 확보** — Hallwee 또는 LCSC에 직접 문의.
   비율계측 여부(5-B.7 ①), 출력 노이즈, 비선형성, 오프셋 산포(게인 상한 결정).
   **못 구하면 양산 부품에서 제외한다** (리스크 18).
8. **8키 시제품 보드** — 아래를 모두 실장해 실측 후 80키로 확장:
   - 센서 8개, **SOT-23-3 공용 풋프린트** (HAL9303SO / DRV5053VA / AH49E 교차 실장)
   - **TMUX1308A 1개 + 74HC4051 1개 풋프린트 병설** (둘 다 평가 + 재고 리스크 대응)
   - TLV9064 1개 + 게인 점퍼(G=2/4/8/16) + **ADC 직결 우회 0Ω 점퍼**
   - 측정: ① 정지 σ ② 전 스트로크 곡선 ③ 10nF 부하 스텝 응답
9. **선형화 LUT 생성** — 6번 측정 데이터로 스위치 종류당 65엔트리 LUT 산출.
10. **노이즈 σ 실측** — 정지 상태 ADC 표준편차를 재서 5-A.4의 8~10 LSB 기준 검증.
11. **부품 재고 재확인** — 5-B절 재고/가격은 2026-07-26 기준. 발주 시점에 다시 확인.
