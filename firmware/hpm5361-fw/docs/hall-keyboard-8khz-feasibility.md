# HPM5361 기반 8kHz 마그네틱(홀) 키보드 타당성 검토

- 작성일: 2026-07-26
- 대상 MCU: HPM5361 (HPM5300 시리즈, **Andes D25F / RV32-IMAFDCPB**, CPU 480MHz)
  — 현재 빌드는 `rv32imac + Zb*`로 F/D/P를 끈 상태다. 차이는 5.1절 참조.
- 목표: USB HS 8kHz 폴링(125us 주기) 안에서 **최대 96키(6x16)** 홀센서 ADC 취득 → 키로직 → HID 전송

## 1. 요약

125us 예산 안에서

| 단계 | 시간 | CPU 개입 |
|---|---|---|
| 96채널 ADC 취득 — **①안** TMAG5253 **UA2**(단극 남극, 뒷면실장), 12bit 1x | **27us** | 0% (DMA/TRGM 하드웨어 자동) |
| └ ②안 BA3(양극) + VREFH 1.8V + 2x | 43us | 0% |
| └ ③안 BA3(양극) + VREF 3.3V + 4x | 73us | 0% |
| 키로직 96키 처리 (거리변환 5.8us + 래피드트리거 4.3us) | 10.1us | CPU |
| HID 리포트 조립 + USB 제출 + ISR | 5.2us | CPU |
| **합계 (①안 기준)** | **약 43us / 125us (34%)** | CPU 부담은 15.3us(12%) |

(스캔 시간은 **8:1 MUX 12개 / 8스텝 x 6변환·ADC** / 12bit Ns=2 @50MHz / 세틀링 1.5us 기준.
MUX 16개 x 6스텝 구성이면 세틀링 횟수가 줄어 ①안 24us로 더 빠르다 → 3.2절)

**결론: 타이밍 여유 충분.** 병목은
(1) **실장면과 센서 극성 변종 선택 (5-D.8)** — 뒷면 실장이면 **남극(S) 감지**가 맞다,
(2) **뒷면 실장의 갭 증가량 (리스크 30)** — TIMSS로 주문 전 확정 필요,
(3) 아날로그 입력 핀이 16개뿐이라는 점, (4) MUX 세틀링, (5) 아날로그 노이즈다.

**0.1mm 분해능**: 12비트로 **아날로그 게인단 없이 달성된다** (상단 10~20 LSB/0.1mm).
6차 개정에서 비선형 계수를 TI 실측 지오메트리로 정정한 결과다. → **5-D절**

125us당 CPU 인터럽트는 **1회**로 설계 가능하다.

## 2. 가장 중요한 하드웨어 제약: 아날로그 입력은 16핀

EVK 회로도의 MCU 핀 정의를 파싱한 결과:

- 아날로그 입력 패드는 **PB00 ~ PB15, 정확히 16개**
- 각 패드가 `ADC0.INx` **와** `ADC1.INx`를 **동시에** 갖는다 (예: PB04 = ADC0.IN0 = ADC1.IN0)
- 즉 ADC0/ADC1은 **같은 16개 패드를 공유**하는 별개의 SAR 변환기 2개다.
  아날로그 채널이 32개가 아니라 **핀 16개 + 변환기 2개**.

### 2.1 ADC 입력 핀 매핑

| INx | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 핀 | PB04 | PB09 | PB10 | PB11 | PB12 | PB13 | PB14 | PB15 |

| INx | 8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |
|---|---|---|---|---|---|---|---|---|
| 핀 | PB03 | PB06 | PB07 | PB08 | PB02 | PB05 | PB01 | PB00 |

### 2.2 파생 결론

- 8:1 MUX 기준 **최대 키 수 = 8 x (ADC 사용 핀) = 8 x 16 = 128키.**
  **목표인 96키(6x16)는 여유.**
- 96키는 **MUX 12개(12핀, 8스텝)** 또는 **MUX 16개(16핀, 6스텝)** 로 구성한다.
  전자는 4핀이 남아 DAC0/DAC1을 쓸 수 있고, 후자는 세틀링 횟수가 적어 더 빠르다.
  **본 문서의 기본은 12개 구성이다.**

**참고 — 실물 HE 보드 벤치마크 (64키)**

| 항목 | 값 |
|---|---|
| 키 수 | 64 |
| MUX | **8:1 x 8개** (사진에서 확인) |
| ADC 사용 핀 | 8 (ADC0측 4 + ADC1측 4) |
| 주소선 | 3bit (A0~A2), 전 MUX 공용 |
| 주소 스텝 | **8** |

96키는 **여기서 MUX 4개와 ADC 4핀만 더하면 된다.** 8:1 MUX는 스텝 수가 채널 수(8)로
고정되므로 **스텝은 8회 그대로**이고, 스캔 시간은 스텝당 변환이 4 → 6회로 느는 만큼만
증가한다(12bit Ns=2 @50MHz 기준 22.2us → 27.4us). **세틀링 비용은 늘지 않는다.**
- PB 전체를 아날로그로 쓰면 나머지 디지털 기능은 PA00~PA31에 배치.
  현재 디버그 UART0가 PA00/PA01이라 **충돌 없음**.
- PB08 = DAC0.OUT, PB09 = DAC1.OUT, PB00/PB01 = OPA0/OPA1.OUT 이므로
  아날로그 보조 기능을 쓰려면 해당 핀을 매트릭스에서 빼야 한다.

## 3. ADC 타이밍 모델

SDK 레지스터 정의에서 나온 실제 식
(`src/lib/hpm_sdk/soc/HPM5300/ip/hpm_adc16_regs.h` CONV_CFG1 주석):

```
1샘플 시간 = (SAMPLE_CLOCK_NUMBER + CONVERT_CLOCK_NUMBER) / f_adc

CONVERT_CLOCK_NUMBER : 16bit=21, 12bit=14, 10bit=11, 8bit=9  [ADC 클럭]
SAMPLE_CLOCK_NUMBER  : 1 ~ 511 (+ 3bit shift)
f_adc = ADC 소스클럭 / CLOCK_DIVIDER(1~16)
```

ADC 클럭 소스는 **AHB(160MHz)** 또는 **전용 ANA 클럭** 중 선택
(`clk_adc_src_ahb0` / `clk_adc_src_ana0` / `clk_adc_src_ana1`).

- 안전 설정: AHB / 4 = **40MHz**
- 상한이 50MHz까지 허용되면 ANA 클럭으로 **50MHz** (데이터시트 확인 필요)

### 3.1 1샘플 시간

| 해상도 | 샘플클럭 | 총 클럭 | @40MHz | @50MHz |
|---|---|---|---|---|
| 16bit | 11 | 32 | 800ns | 640ns |
| 16bit | 4 | 25 | 625ns | 500ns |
| 12bit | 11 | 25 | 625ns | 500ns |
| 12bit | 4 | 18 | 450ns | 360ns |

### 3.2 96키 전체 스캔 (ADC0/ADC1 병렬)

채널 분리: **ADC0 = IN0~IN7, ADC1 = IN8~IN15** (같은 패드 동시 변환 금지)

| 구성 | 사용 핀 | 주소 스텝 | 16bit/40MHz | 12bit/50MHz |
|---|---|---|---|---|
| **A: 8:1 MUX 12개 ★기본** | 12핀 | 8스텝 x 6변환/ADC | **46.4us** | **25.3us** |
| B: 8:1 MUX 16개(6ch씩 사용) | 16핀 | 6스텝 x 8변환/ADC | 44.4us | 23.3us |
| (참고) 64키 실물 보드: 8:1 x 8개 | 8핀 | 8스텝 x 4변환/ADC | 33.6us | 19.5us |

(MUX 세틀링 1us/스텝 가정 포함. 16bit는 Ns=11@40MHz, 12bit는 Ns=4@50MHz)

**두 구성의 변환 시간은 동일하다** — 어느 쪽이든 96변환을 2개 ADC가 48회씩 나눠 하기 때문이다.
차이는 오직 **세틀링을 몇 번 무느냐**다. 구성 B는 스텝이 6번뿐이라 2us 빠르다.

대신 구성 B는 ADC 16핀을 전부 쓰므로 DAC0(PB08)/DAC1(PB09)을 못 쓴다. 5-D에서 게인단이
철회되어 DAC 오프셋이 필요 없어졌으므로 실사용에는 문제가 없으나, 시제품에서 게인단 유무를
비교하려면 4핀이 남는 구성 A를 써야 한다. **본 문서의 기본은 구성 A(12 MUX)다.**

### 3.3 처리량 여유

- ADC 순수 처리량: 2 x 약 2MSPS = **약 4MSPS**
- 실제 필요량: 96채널 x 8kHz = **768kSa/s (약 19%)**
- → **4배 오버샘플링(3.07MSa/s, 77%)해도 예산 안**에 들어온다. 80키 때보다 여유는 줄었다.

단, HPM5361은 **하드웨어 오버샘플링(`ADC_LOOP`) 미지원**이므로
시퀀스를 여러 번 돌려 SW 평균해야 한다.

### 3.4 DMA 데이터량

- `DMA_SEQ16BIT` 미지원 → 시퀀스 DMA는 **샘플당 32bit 패킹**
  (`result:16 / seq_num:4 / adc_ch:5 / cycle_bit:1`)
- 96샘플 = **384B / 125us = 3.07MB/s**. 160MHz AHB 대비 무시할 수준.
- 4x 오버샘플링 시 384샘플 = 1536B (더블버퍼 3072B).
- 채널번호가 결과와 함께 들어오므로 **정합성 검증에 유리**하다.

## 3-A. 해상도 선택: 12bit 채택 근거 (2026-07-26 검토)

**결론: 12bit + 4배 오버샘플링 평균을 기본 설계로 한다.**

> ### ★ 13차 확정 — 데이터시트가 ENOB = 12비트를 명시한다
>
> 「HPM5300 DS Rev0.11 표 35: 16位 ADC 参数」 원문:
>
> | 파라미터 | 기호 | 전형값 | 단위 | 조건 |
> |---|---|---|---|---|
> | 신호노이즈왜곡비 | SINAD | **74** | dB | 단일단, VREFH=3.0V |
> | **유효비트수** | **ENOB** | **12** | **비트** | 단일단, VREFH=3.0V |
> | 총고조파왜곡 | THD | 93 | dB | |
> | 미분/적분 비선형성 | DNL / INL | +1/−0.89 / +3.1/−5.2 | LSB | |
> | 오프셋 / 이득 오차 | Vos / GE | 4 / 3 | LSB | |
>
> 검산: `ENOB = (SINAD − 1.76) / 6.02 = (74 − 1.76) / 6.02 = 12.0` ✓ 일관됨.
>
> **"16bit ADC"는 이름뿐이고 실효 분해능은 정확히 12비트다.**
> 3-A절이 "ENOB이 16bit에 한참 못 미친다"고 추정했던 것이 **수치로 확정됐다.**
> 16비트로 설정하면 65,536 코드가 나오지만 **하위 4비트는 전부 노이즈**다.
>
> **핵심 귀결**: ADC 자체 노이즈가 이미 12비트 양자화 바닥(σ = 1/√12 = 0.29 LSB)에 있으므로,
> 16비트로 올려도 **양자화만 1/16이 되고 아날로그 노이즈는 그대로**다.
> 총 ADC 노이즈는 변하지 않는다 → **SNR 개선량이 0이다.** 5-E.15 참조.

### 3-A.1 12bit 전환의 순수 절감량

```
16bit: 21 + Ns 클럭 / 12bit: 14 + Ns 클럭  →  Δ = 7 클럭 / 샘플
```

| f_adc | 샘플당 절감 | 96채널(2 ADC 병렬, 48변환/ADC) 절감 |
|---|---|---|
| 40MHz | 175ns | **8.4us** |
| 50MHz | 140ns | **6.7us** |

### 3-A.2 전체 스캔 비교 (세틀링 1us/스텝 포함)

구성 A(기본) — 8:1 MUX 12개, 8스텝 x 6변환/ADC

| 설정 | 16bit | 12bit | 절감 |
|---|---|---|---|
| Ns=11, 40MHz | 46.4us | **38.0us** | -18% |
| Ns=4, 50MHz | 32.0us | **25.3us** | -21% |

구성 B — 8:1 MUX 16개, 6스텝 x 8변환/ADC

| 설정 | 16bit | 12bit | 절감 |
|---|---|---|---|
| Ns=11, 40MHz | 44.4us | **36.0us** | -19% |
| Ns=4, 50MHz | 30.0us | **23.3us** | -22% |

**변환부만 -33%지만 전체 스캔은 -18~22% (절대 6.7~8.4us).**
MUX 세틀링과 샘플 클럭이 고정 오버헤드로 남기 때문이다.
125us 예산에서 7~8us 자체는 결정적이지 않다.

### 3-A.3 진짜 이득 — 오버샘플링 여유

같은 MUX 주소에서 연속 N회 변환하면 **세틀링은 스텝당 1회만** 발생한다.
스텝 시간 = `t_settle + N x (채널수/ADC) x t_conv`

구성 A(기본: 8:1 x 12, 8스텝 x 6변환/ADC), Ns=4 @50MHz:

| 오버샘플 | 16bit | 12bit |
|---|---|---|
| 1x | 32us | 25.3us |
| 2x | 56us | **42.6us** |
| 4x | 104us (예산 초과) | **77.1us (여유)** |

구성 B(8:1 x 16, 6스텝), 4x: 16bit 102us vs 12bit **75.1us**

→ **96키에서는 16bit + 4배 오버샘플링이 불가**(104us에 CPU 15.3us를 더하면 125us 초과),
**12bit면 여전히 여유롭게 들어온다.** 80키 때 "빠듯"이던 것이 96키에서 "불가"로 넘어갔다.
12bit 채택은 이제 선택이 아니라 전제다.

12bit + 4x 평균 = **실효 약 13bit + 노이즈 1/2**.
ADC16의 실제 ENOB이 16bit에 한참 못 미치므로
**12bit 4x 평균이 16bit 원시값보다 실측 품질이 더 좋다.**
4mm 스트로크 / 4096 = 약 1um 분해능이라 해상도도 충분하고도 남는다.

### 3-A.4 해상도보다 SAMPLE_CLOCK_NUMBER가 더 큰 레버

| 조합 | 총 클럭 | 대비 |
|---|---|---|
| 16bit + Ns=11 | 32 | 기준 |
| 12bit + Ns=11 | 25 | -22% |
| 16bit + Ns=4 | 25 | -22% |
| **12bit + Ns=4** | **18** | **-44%** |

Ns는 소스 임피던스(MUX Ron x 입력 용량)로 결정된다.
74HC4051(Ron 약 170Ω) 대신 **TMUX1108 / ADG708(Ron 수십Ω)** 을 쓰면
Ns를 4~8까지 내릴 수 있고, 이게 해상도 조정보다 효과가 크다.
**해상도 인하와 저Ron MUX는 같이 가야 한다.**

### 3-A.5 구현 유의점

- `config.res = adc16_res_12_bits` **설정만으로 충분**하다.
  `adc16_init()`이 `COV_END_CNT = 21 - res + 1`을 자동으로 맞춘다
  (`src/lib/hpm_sdk/drivers/src/hpm_adc16_drv.c:216`). 수동 레지스터 조작 불필요.
- **해상도는 ADC 인스턴스 단위**(`CONV_CFG1`),
  **샘플 클럭은 채널 단위**(`SAMPLE_CFG[16]`).
  → 배선이 긴 채널만 Ns를 늘리는 식으로 채널별 튜닝이 가능하다.
- **결과 정렬 확인 필요** — `ADC16_SOC_MAX_SAMPLE_VALUE`가 해상도와 무관하게 65535이므로
  결과가 16bit 필드에 MSB 정렬(좌측 정렬)될 가능성이 높다. 12bit면 값이 `<<4` 된 형태.
  **실측 확인 항목.**

> 분해능이 **키 스트로크 0.1mm 인식**에 충분한지는 별도 검토가 필요하다. → **5-A절**

## 4. 사용할 MCU 내부 장치

### 4.1 핵심 경로 (CPU 개입 0)

| 장치 | 역할 | 비고 |
|---|---|---|
| **ADC0 + ADC1** (ADC16, 16bit SAR) | 시퀀스 모드 + HW 트리거 + DMA | 시퀀스 최대 **16엔트리** |
| **HDMA (32ch) + DMAMUX** | ① ADC 결과 → 링버퍼 ② MUX 주소 테이블 → GPIO DO | DMA 컨트롤러는 1개, 32채널 |
| **GPTMR0** (또는 PWM0) | 125us 마스터 주기 + 스텝 트리거 | COMP 채널 2개로 위상차 부여 |
| **TRGM0** | 타이머 → `ADC0_STRGI` / `ADC1_STRGI` 라우팅 | 프리엠션은 `ADCX_PTRGI0A~3C` |
| **GPIO0 / FGPIO** | MUX 주소 A0~A2 (뱅크 분리 시 6핀) | FGPIO는 코어 로컬버스, 1사이클 |
| **USB0** | HS + 온칩 UTMI PHY, HID Interrupt IN bInterval=1 (125us) | 이미 HS로 동작 확인됨 |
| **ILM 128K / DLM 128K** | 핫패스 코드(`.fast`/ramfunc) + DMA 버퍼 | XIP 플래시 실행은 지터 때문에 금지 |

### 4.2 선택적으로 쓸만한 것

| 장치 | 용도 |
|---|---|
| **PLB** (Programmable Logic Block) | MUX 주소 3bit 카운터를 순수 HW로 → DMA 채널 1개 절약 |
| ~~OPAMP0 / OPAMP1~~ | **채널 2개뿐이라 10~16ch 게인단으로 부적합.** 외부 TLV9064 사용 (5-B.4) |
| **ACMP** | 임계 통과 고속 검출 |
| **DAC0 (PB08)** | **★ 채택 — 게인단 오프셋 기준전압 V_ref 생성** (5-B.5). DAC1(PB09)은 예비 |
| **ADC 워치독** | 채널별 상/하한 임계값 → 통과 키만 인터럽트 플래그 |
| **MCHTMR** | 타임스탬프 |
| **EWDG** | 워치독 |

### 4.3 권장 파이프라인

```
GPTMR0 CH0 COMP ──DMA req──> DMA: mux_addr_table[N] → GPIO0.DO      (t = 0)
GPTMR0 CH1 COMP ──TRGM0────> ADC0.STRGI + ADC1.STRGI                (t = t_settle)
                               │
                               └─ 시퀀스 6변환 x 2 ADC 병렬 (8:1 MUX 12개 구성)
                                  DMA → 링버퍼 (384B, 32bit 패킹)

주소 스텝 8회 완료 → 인터럽트 1회 / 125us
                     → 키로직 → HID 리포트 → usbd_ep_start_write()
```

**125us당 인터럽트 1회.** 스텝마다 ISR을 타면 64kHz(8스텝 x 8kHz) 인터럽트가 되어 실패한다.

### 5.1 명령어셋 — 실리콘 능력과 현재 빌드는 다르다

> ⚠ **8차 개정에서 정정.** 이전 판은 "FPU 없음 / DSP 확장 없음 / 하드웨어 나눗셈 없음"이라고
> 적었으나 **셋 다 사실이 아니다.** 빌드 플래그만 보고 실리콘 스펙으로 단정한 오류였다.

**코어: Andes D25F, ISA = RV32-IMAFDCPB**

| 확장 | 내용 | 현재 빌드에서 |
|---|---|---|
| **M** | 곱셈 **및 나눗셈**(DIV/DIVU/REM/REMU) | **사용 중** |
| **F / D** | **단정밀도 + 배정밀도 FPU** (IEEE754) | **비활성** |
| **P** | **패킹 SIMD (DSP 확장)** | **비활성** |
| A | 원자적 연산 | 사용 중 |
| C | 압축 명령 | 사용 중 |
| B(Zba/Zbb/Zbc/Zbs) | 비트 조작 | 사용 중 |

현재 빌드 플래그: `-march=rv32imac_zicsr_zifencei_zba_zbb_zbc_zbs` (CMakeLists.txt:233)
→ **F/D/P를 명시적으로 빼고 컴파일하고 있다.** 소프트 부동소수점으로 동작하며,
하드웨어 FPU와 DSP는 놀고 있다. 이건 **빌드 선택이지 하드웨어 제약이 아니다.**

**설계 판단은 그대로 유지한다 — 다만 이유가 다르다**

- 거리 변환은 여전히 **고정소수점 + LUT 보간**으로 간다.
  FPU가 없어서가 아니라, **LUT 보간이 FPU 연산보다 빠르기 때문**이다
  (5-A.9의 29사이클/키는 정수 경로 기준이고, FDIV는 그 자체로 수십 사이클이다).
- 나눗셈은 **역수 곱셈 + 시프트**로 대체한다.
  DIV 명령이 있긴 하지만 D25F에서 다중 사이클·비파이프라인이라 곱셈이 여전히 빠르다.
- **F/D를 켜면 ABI가 `ilp32f`/`ilp32d`로 바뀌고**, ISR마다 FPU 컨텍스트
  20개 레지스터 저장/복원이 붙는다(`hpm_interrupt.h`의 `SAVE_FPU_CONTEXT`).
  125us당 인터럽트 1회 설계에서 치명적이진 않지만 공짜도 아니다.

### 5.1.1 F/D를 켜면 실제로 무엇이 바뀌나 (2026-07-26 실측)

xpack riscv-none-elf-gcc **13.4.0-1**로 직접 검증했다.

**① 툴체인 — 문제 없음**

```
$ riscv-none-elf-gcc -march=rv32imafdc_zicsr_zifencei_zba_zbb_zbc_zbs \
                     -mabi=ilp32d --print-multi-directory
rv32imafdc_zicsr/ilp32d          ← 멀티립 존재. newlib/libgcc 링크 성공
```

Zb* 확장이 멀티립 이름에 없어도 상위호환이라 정상 선택된다.
링크 후 `fmul.d` / `fadd.d` / `fsqrt.d` 하드웨어 명령 생성까지 확인했다.

**② 코드 크기 — 오히려 줄어든다 (예상과 반대)**

double 연산 + `sqrt()`를 쓰는 동일 소스, `-O2 --specs=nano.specs`:

| 빌드 | .text |
|---|---|
| 현재 (`rv32imac` / `ilp32` soft-float) | **12,276 B** |
| `rv32imafdc` / `ilp32d` hard-float | **3,758 B** |

**-8.5KB (-69%).** soft-float는 `__adddf3`/`__muldf3`/`__divdf3` 같은 에뮬레이션 루틴이
통째로 링크되기 때문이다. **부동소수점을 쓰는 코드가 있다면 hard-float가 크기에서도 유리하다.**
(부동소수점을 전혀 안 쓰면 양쪽 다 해당 루틴이 안 붙으므로 차이 없음)

**③ ★ 진짜 비용 — 인터럽트 컨텍스트가 2.7배**

`__riscv_flen`이 정의되는 순간 SDK의 `CONTEXT_REG_NUM`이 바뀐다
(`arch/riscv/intc/hpm_interrupt.h`):

| 빌드 | 저장 레지스터 | 스택 |
|---|---|---|
| 현재 | 22 워드 | **96 B** |
| `ilp32d` | 22 + 20x2 워드 | **256 B** |

인터럽트마다 **스택 +160B, 메모리 접근 +40회**가 붙는다.
`trap.c`는 `fcsr` 저장/복원을, `start.S`는 `mstatus.FS` 활성화를 추가로 수행한다.
FS를 Off로 두면 이 비용을 피할 수 있지만 그러면 FP 명령이 illegal instruction 예외가 된다.

**8kHz 키보드에서 이건 순손실이다.** 핫패스(거리변환·래피드트리거)는 전부 정수 연산이라
FPU를 쓰지 않는데 ISR 진입/복귀 비용만 늘어난다. 125us당 인터럽트 1회 설계라
치명적이진 않지만(40회 메모리 접근 ≈ 0.2us 수준), **얻는 것 없이 내는 비용**이다.

**④ ABI는 전부-아니면-전무**

`ilp32d`로 바꾸면 모든 오브젝트가 같은 ABI여야 한다. 이 프로젝트는 SDK를 포함해
**전부 in-tree 소스 빌드**라 문제없다. 미리 빌드된 `.a`가 들어오면 그때 깨진다.

**⑤ P(DSP) 확장 — 이 툴체인으로는 불가**

```
$ riscv-none-elf-gcc -march=rv32imafdcp_zicsr ...
Error: cannot find default versions of the ISA extension `p'
$ riscv-none-elf-gcc -mext-dsp ...
error: unrecognized command-line option '-mext-dsp'
```

**xpack GCC 13.4.0은 P 확장을 지원하지 않고, Andes 전용 옵션도 없다.**

### 5-A.2 함정 — 자기장 비선형성

자기장은 `B ∝ 1/g^n` (실측 기반 n ≈ 1.6~3)으로 감쇠한다.
**바닥 근처는 민감하고 상단(누르기 시작하는 구간)은 둔하다.**

갭 5mm(rest) → 1mm(bottom), 스트로크 4mm, n=1.6 기준:

```
상단 민감도 / 평균 민감도 = r ≈ 0.106   (약 1/9.4)
```

> ⚠ **6차 개정에서 정정됨.** TI SLYA093이 밝힌 실제 스위치 지오메트리는
> 갭 **6.1mm → 2.1mm** 로 여기 가정(5→1mm)보다 훨씬 멀다.
> 실제 값은 **r = 0.227** 이다. 아래 5-A.3 / 5-A.4의 수치는 모두 **2.1배 낙관적으로 상향**된다.
> → **5-D.2절 참조**

→ **액추에이션이 걸리는 상단 구간의 분해능이 평균의 1/10.**
평균값으로 계산하면 안 되고 **항상 상단 최악값으로 판정**해야 한다.

### 5-A.4 판정 기준

노이즈 σ ≈ 1~2 LSB(필터 후) 기준, 채터 없이 0.1mm 변화를 확정하려면
**0.1mm당 8~10 LSB**가 필요하다. 역산하면:

```
필요 전 구간 카운트 = 목표LSB(10) / r(0.106) x (4mm / 0.1mm) ≈ 3,800 카운트
```

**12비트 = 4096. 거의 딱 맞는다 — 충분하지만 여유는 없다.**

- 16비트로 올려도 ENOB가 13비트를 못 넘으므로 해결되지 않는다.
- ~~해결책은 ADC 비트가 아니라 아날로그 게인이다.~~

> ⚠ **6차 개정에서 정정됨.** r = 0.227 로 바꾸면 필요 카운트는
> `10 / 0.227 x 40 = 1,762` — **12비트 4096의 43%면 충분하다.**

### 5-A.5 게인 확보 방법 (권장순)

1. **MUX 출력단 게인/오프셋 제거 단** ★ 권장
   키당이 아니라 MUX당이므로 10~16개(쿼드 op-amp 3~4패키지)면 된다.
   `V_out = (V_sensor - V_rest) x 8`
   고속 RRIO(OPA2365급 50MHz) 사용 시 정착시간 약 0.5us 추가 → 3절 세틀링 예산에 반영 필요.
2. **고감도 센서 + 자석/갭 최적화** — 스윙 자체를 키우는 게 가장 저렴.
   DRV5053VA(-90mV/mT)는 이미 최고감도이므로 자석 세기와 센서 거리로 조정.
3. HPM5361 내장 **OPAMP0/OPAMP1은 2개뿐**이라 16채널을 못 덮는다. 외부 op-amp 필수.
4. 상단 0.2~0.3mm는 데드존 처리 — 상용 키보드가 실제로 쓰는 방식.

### 5-A.6 키당 처리 파이프라인

```
① 4x 오버샘플 평균     raw[4] → avg                                (HW 취득분)
② EMA 필터            ema += (avg - ema) >> k
③ 2점 정규화          n = (ema - rest) * 65535 / (bottom - rest)   [0..65535]
④ 선형화 LUT + 보간    n → 거리 d (1/256mm 고정소수점)
⑤ 래피드 트리거 SM     d → pressed / released
⑥ NKRO 비트맵 갱신     Zbs 명령 (bset/bclr)
```

**③번이 libhmk가 하는 전부**다(rest~bottom 선형 정규화, 0~255).
이건 "신호 선형"이지 "거리 선형"이 아니다.
**진짜 0.1mm 단위를 원하면 ④번 LUT이 필수다.**

- LUT은 **스위치 종류당 1개 공용**(65엔트리 x 2B = 130B)으로 두고,
  키별로는 rest/bottom 2점만 캘리브레이션한다.
- 키별 LUT(96 x 64 x 2B = 12KB)도 DLM에 들어가지만 캘리브레이션 지그가 필요해 비현실적.
- 96키가 같은 LUT을 참조하므로 캐시 히트율 100%.

### 5-A.7 EMA 필터 지연 — 중요한 트레이드오프

libhmk의 α=1/16은 8kHz에서 시정수 **16샘플 = 2ms**다.
8kHz 폴링을 하는 의미가 사라진다.

|---|---|---|---|
| 1/16 | 2.0ms | 4x | 지연 과다 |
| 1/8 | 1.0ms | 2.8x | 보수적 |
| **1/4** | **0.5ms** | **2x** | **★ 채택** |

~~오버샘플링은 지연이 0이고 EMA는 지연이 생기기 때문이다.~~

> ⚠ **13차에서 정정됨.** 같은 MUX 주소에서 연속 변환하는 **버스트 오버샘플링은 샘플 간격이
> 320ns**인데 노이즈 상관 시간이 **10us**라 사실상 같은 값을 반복해 읽는다.

### 5-A.8 래피드 트리거 (0.1mm 인식의 실사용처)

0.1mm 분해능이 필요한 진짜 이유. 래피드 트리거의 최소 민감도가 0.1mm다.

```c
// d: 현재 거리 (0=릴리즈 ... FULL=바닥), 1/256mm 고정소수점
if (!k->pressed) {
    if (d < k->valley) k->valley = d;              // 최저점 추적
    if (d >= k->actuation ||                        // 절대 액추에이션
        d - k->valley >= k->down_sens)              // 연속 래피드 트리거
    { k->pressed = true;  k->peak = d; }
} else {
    if (d > k->peak) k->peak = d;                   // 최대 눌림 추적
    if (k->peak - d >= k->up_sens ||                // 상승 감지 → 즉시 릴리즈
        d <= k->release_floor)
    { k->pressed = false; k->valley = d; }
}
```

**설계상 핵심**: 래피드 트리거는 절대값이 아니라 **차분(peak - d)** 으로 판정한다.
따라서 필요한 것은 절대 정확도가 아니라 **차분 분해능**이고,
판정 임계값이 노이즈 3σ보다 커야 채터가 없다.

```
0.1mm에 해당하는 LSB > 3σ   →   σ=2 LSB 이면 0.1mm당 6 LSB 이상
```

5-A.4절의 "8~10 LSB" 기준과 일치한다.

추가 필수 요소:

- **peak/valley 추적 히스테리시스 ε** (libhmk `MATRIX_CALIBRATION_EPSILON = 5`)
- **상단 데드존** — rest 근처 0.2mm는 무조건 릴리즈 (분해능이 죽는 구간)
- **자동 재캘리브레이션** — libhmk는 무입력 3초 후. 온도 드리프트 대응.

## 5-B. 아날로그 프론트엔드 부품 선정 (JLCPCB/LCSC 재고 기준, 2026-07-26 조사)

> 재고/가격은 2026-07-26 조사 시점 기준이다. **발주 시점에 반드시 재확인**할 것.

### 5-B.1 핵심 발견 — 정밀 MUX가 필요 없다

**op-amp를 MUX 뒤에 두면 MUX의 부하가 op-amp (+)입력(수 pA)이 된다.**
전류가 흐르지 않으므로:

- **Ron이 전압 강하를 전혀 만들지 않는다** (240Ω x 1pA = 0.24pV)
- 세틀링도 Ron x op-amp 입력용량(수 pF) = **수 ns**로 무의미
- 남는 것은 **누설전류**뿐 — 74HC4051 @25도 약 0.1uA x 1kΩ = 0.1mV = **0.12 LSB**, 무시 가능

→ 3절에서 걱정했던 "MUX Ron 170Ω 문제"와 "TMUX1108급 저Ron 부품 필요"는 **게인단을 MUX 뒤에 두는 순간 소멸한다.**
TMUX1108을 썼다면 12개 x $1.68 = $20이었을 것을 $1.10으로 대체.

> 단, 5-D.3에서 게인단이 철회되면서 **이 절의 전제가 무너진다.**
> op-amp가 없으면 MUX가 ADC 샘플링 커패시터를 직접 구동하므로 Ron이 다시 중요해진다.
> → 5-D.3

- **소비전류 800uA가 결정적.** 49E 계열(4~6mA)은 96키에 403~576mA로 **USB 500mA 예산을 통째로 넘긴다.**
  이 항목 하나로 후보 대부분이 탈락한다. **96키로 올리면서 여유가 더 줄었다** — 80키 때는
  4.2mA 부품이 336mA로 아슬아슬하게 걸쳤지만 96키에서는 403mA로 MCU 몫이 남지 않는다.
- 감도 47mV/mT — DRV5053VA(90) 다음으로 높음
- **±35mT 선형 범위**가 키 스트로크(ΔB 5~30mT)에 정확히 맞는다.
  넓은 범위 부품(±120mT)은 감도가 낮아 오히려 불리하다.
- **1.6~5.5V** — 3.3V 단일 전원 그대로 사용. SS49E는 4.5V 최소라 레벨 문제 발생.
- **리스크: 재고 3,110개 = 32보드분(96키 기준).** 시제품엔 충분하나 양산 전 확보 필요.
  2순위는 DRV5053VA(감도 최고) 또는 HX6659ISO-D.

### 5-B.3 MUX 후보 비교

**8:1 MUX만 검토한다.** 16:1(74HC4067 / TMUX1316급)은 스텝 수를 줄여주지 못하는 데다
Ron·C_on이 원리적으로 크고(스위치 2배, 공통단 기생용량 2배), 게인단이 철회된 5-D 구성에서는
그 Ron을 ADC 샘플링 커패시터가 직접 물게 되므로 **후보에서 제외한다.**
96키에 필요한 8:1 MUX는 12개다.

### 5-B.4 게인단 op-amp — TLV9064IPWR (C779410)

| 항목 | 값 | 평가 |
|---|---|---|
| GBW / 슬루레이트 | 10MHz / 6.5V/us | G=4에서 정착 약 **0.8us** |
| 입력 노이즈 | 16nV/√Hz | 2.5MHz 대역 25uV RMS → **0.12 LSB. 무시 가능** |
| Iq | 538uA/ch | 12ch = 6.5mA |
| 전원 | 1.8~5.5V RRIO | 3.3V 단일 ✓ |
| 재고 / 단가 | 7,100 / **$0.178**(4000+) | TSSOP-14 쿼드, **3개 = 12ch로 MUX 12개에 정확히 대응** |

**정착 0.8us는 문제가 되지 않는다** — 4x 오버샘플링을 하면 세틀링 1회당 변환 4회라 상대 비중이 1/4로 상각된다.

재계산 (구성 A, 12 MUX, 8스텝 x 6변환/ADC, 12bit Ns=4 @50MHz, 4x 오버샘플, 세틀 1.5us):

```
8 x (1.5us + 4 x 6 x 0.36us) = 8 x 10.14us = 81.1us
```

세틀 1.0us 기준의 77.1us 대비 **+4us**. 125us 예산 내.
→ 5-A.10의 75~77us를 **약 81us**로 갱신.

### 5-B.5 회로 — 게인/오프셋 조정 가능 버전

```
[센서 96개]
HAL9303SO ──[1kΩ]──┬────────────────────► 74HC4051 입력
  (AVDD 3.3V)      └─[10nF]─ AGND
                    ↑ RC fc=16kHz. 노이즈 대역제한 + MUX 차지인젝션 흡수

[MUX 12개 → op-amp 12ch]
74HC4051 OUT ──[Rg]──┬──[Rf]──┐
                     │        │
                  (-)│        │
                TLV9064       │
                  (+)│  ├─────┘
V_ref ───────────────┘  └── OUT ──[100Ω]──┬──► ADC 핀 (PB0x)
 (HPM DAC0, PB08)                          └─[1nF]─ AGND
                                             ↑ ADC 샘플링캡 리저버 + 안티앨리어싱
```

```
V_out = V_ref x (1+G) − V_mux x G ,   G = Rf/Rg
릴리즈 시 V_out = 0 이 되도록 :  V_ref = V_rest x G/(1+G)
  예) G=4, V_rest=1.65V → V_ref = 1.32V   (DAC로 소프트웨어 설정)
```

**RC 상수 근거**: 1kΩ x 10nF = τ 10us.
1m/s 키 속도에서 지연 = 0.01mm(무시 가능). 100nF를 쓰면 τ=100us → 지연 0.1mm로 **분해능과 같아져 안 된다.**

> ## ⚠ 17차 정정 — 이 절의 RC 근거는 **불완전**하다 (→ 5-I)
>
> 위 계산은 **op-amp 게인단이 있는 이 절의 회로**에서만 성립한다. 게인단이 철회된
> 최종 구성(5-D.7)에서는 두 가지가 바뀐다.
>
> | | 이 절 | **정정 (5-I)** |
> |---|---|---|
> | ADC쪽 100Ω + 1nF | TLV9064가 구동 → τ=159ns **맞음** | 구동원이 `센서+1kΩ+10nF`. **1nF 실장 시 99 LSB 크로스토크 → DNP** |
> | 센서쪽 1kΩ | 필터 역할만 검토 | **MUX 스텝마다 재충전되는 저장소**이기도 하다. τ=10us가 세틀링 1.5us를 66배 초과 → **100Ω** |
> | "100nF 안 된다" | R=1kΩ 전제라 τ=100us | **R=100Ω이면 τ=10us라 이 반론은 해제된다** (5-I.4 대안 B) |
>
> **10nF 유지 결론 자체는 옳다.** 근거만 "차지인젝션 흡수"에서 "**전하 재분배 저장소**"로 바뀐다.

### 5-B.6 "대응 가능한 버전" — 3중 조정 수단

| 조정 대상 | 방법 | 이유 |
|---|---|---|
| **게인 G** | Rf를 0402 패드로 **G=2/4/8/16 저항 교체** | **자석/갭 확정 전에는 최적 G를 알 수 없다.** 필요 G = (VREFH x 0.9)/(감도 x ΔB). ΔB=5mT면 G=12.6, ΔB=25mT면 G=2.5 |
| **오프셋 V_ref** | **HPM5361 DAC0 (PB08)** 소프트웨어 설정 | 센서 개체차/온도드리프트를 재부팅 없이 흡수 |
| **게인단 유무 비교** | MUX OUT → ADC 직결 **0Ω 점퍼 패드** 병설 | 게인단 효과를 실측 검증. **시제품의 핵심** |

**핀 배치가 96키에서도 맞아떨어진다:**
8:1 MUX 12개 → ADC **12핀** 사용(ADC0측 6 + ADC1측 6), 남는 4핀 중
**PB08 = DAC0(V_ref 생성)**, PB09 = DAC1(예비), 나머지 2핀 여유.
(2.1절 매핑: PB08=IN11 → ADC1측, PB09=IN1 → ADC0측. 양쪽에 하나씩이라 배분이 성립한다)

> 3.2절 구성 B(MUX 16개, 6스텝)를 택하면 16핀을 전부 쓰므로 **DAC 오프셋을 못 쓴다.**
> 게인단이 철회된 최종 아키텍처(5-D.7)에서는 무관하지만, 이 절의 조정 수단을
> 시제품에서 평가하려면 구성 A를 써야 한다.

5-B절의 1순위 선정이 성급했다는 지적에 따라 재검증했다.
**결론: HAL9303SO 1순위를 "잠정"으로 격하하고, MUX는 TMUX1308 계열로 상향한다.**

### 5-C.1 HAL9303SO 저전류는 사실로 확인됨

조이스틱 홀/TMR 센서를 리버스엔지니어링한 Hackaday 프로젝트 로그에서:

| 항목 | 측정값 |
|---|---|
| Ginfull L4B 홀 스틱 소비전류 | **700uA (독립 실측)** |
| 해당 스틱의 칩 | **Hallwee HAL9303으로 추정** |
| 전압 사양 | 1.6~5.5V (typ 3.3V) — HAL9303SO 스펙과 일치 |

데이터시트 값(800uA)과 독립 실측(700uA)이 일치한다. **저전류는 마케팅이 아니다.**
저전력 홀 IC는 홀 소자를 duty-cycle 바이어스하거나 chopper로 저대역 동작시켜 이 수준이 나온다.

### 5-C.2 확인된 대가 3가지 — 정량 검토

**(a) 출력 구동능력 약함 — 검토 결과 문제 없음**

같은 로그의 관찰: *"상승 시간은 빠른데 하강 시간이 매우 느리다 (출력 커패시턴스 때문)"*.
5-B.5의 10nF 필터 커패시터와 충돌할 수 있어 정량 검토했다.

| 상황 | 필요 전류 |
|---|---|
| 키가 눌리는 중 (0.4V / 4ms) | **1.0 uA** |
| 스프링 복귀 최속 (0.4V / 5ms, 0.8m/s) | **0.8 uA** |
| MUX 차지인젝션 회수 (10pC / 125us) | **0.08 uA** |

아무리 약한 출력단도 uA 단위는 나온다. 조이스틱에서 문제가 된 건 그쪽 보드의
커패시터가 100nF~1uF 급이고 스틱 복귀가 스프링으로 훨씬 빠르기 때문으로 보인다.
**우리 조건과 2~3자릿수 차이. 10nF 유지가 맞다.**

> **10nF을 줄이면 안 된다.** 74HC4051 차지인젝션 10pC가 1nF에는 10mV를,
> 10nF에는 1mV를 만든다. 이 오차는 채널마다 결정론적이라 rest/bottom 캘리브레이션이
> 통째로 흡수한다. 커패시터가 클수록 유리하다.

> ## ⚠ 17차 정정 — **차지인젝션은 지배항이 아니다** (→ 5-I.1)
>
> 위 계산(Q_INJ)은 맞지만 **100배 큰 항이 빠졌다.**
>
> | 항 | 전하량 | 10nF에서 | 성격 |
> |---|---|---|---|
> | 차지인젝션 Q_INJ | 74HC4051 10pC / **TMUX1308A 0.8pC** | 1mV / **0.08mV** | 채널마다 결정론적 → **캘리브레이션이 흡수** |
> | **전하 재분배** `C x ΔV` | **1nF x 1V = 1000pC** | **93mV** | **이전 채널 값에 의존** → 캘리브레이션 불가 |
>
> 재분배 항은 "옆 키가 눌렸는지"에 따라 변하므로 rest/bottom 캘리브레이션이 흡수하지
> 못한다. 그리고 확정 부품은 74HC4051이 아니라 **TMUX1308A(Q_INJ 0.8pC @3.3V)** 라
> 차지인젝션 항은 12배 더 작다. **"캡이 클수록 유리"는 여전히 맞되, 그건 센서쪽(C56)
> 이야기이고 ADC쪽(C59/C60)은 정반대다** — 그쪽 캡은 매 스텝 재충전 대상이다.

**(b) 노이즈 — 원리적으로 불리한 것은 사실**

```
홀 전압      V_H ∝ I_bias × B
홀 소자 열잡음 √(4kTRΔf)  — 저항에만 의존
→ SNR ∝ 바이어스 전류
```

800uA 부품이 2.4mA 부품(DRV5053)보다 원리적으로 불리하다.
다만 우리 조건에서 상당 부분 상쇄된다:

- 필요 대역폭이 **16kHz뿐**이다(키 움직임은 수백 Hz). 저전력 홀 IC의 좁은 대역폭이
  여기선 오히려 유리하다 — 노이즈는 √Δf로 줄어든다.
- 2x 오버샘플링 + EMA α=1/4가 추가로 깎는다.

**정량 데이터가 없어 실측 전에는 알 수 없다.**

**(c) ★ 진짜 리스크 — 데이터시트 부재**

HAL9303SO의 **노이즈, 비선형성, 출력 구동능력, 대역폭이 전부 미공개**다.
LCSC 스펙 표에도 없고, 데이터시트 PDF는 4개 경로로 시도했으나 봇 차단으로 접근 실패.

LCSC가 공개하는 전부:
> 감도 2.1/4.7mV/Gs · 소비전류 800uA · 1.6~5.5V · ±35mT · 감도 온도계수 ±0.1%/℃ · rail-to-rail

**비선형성 스펙이 없다는 건 0.1mm를 노리는 설계에서 심각하다.**
LUT은 *재현 가능한* 비선형성만 보정한다. 개체차나 온도로 곡선이 흔들리면 대응 불가.

ΔB = 25mT = 250 Gs 를 4mm에 걸쳐 쓸 때  →  2 Gs = 0.032mm 불감대
```

래피드 트리거는 방향 반전 검출이 전부인데, 반전할 때마다 0.032mm의 죽은 구간이 생긴다.
up_sensitivity 0.1mm면 3배 마진이라 동작은 하지만 **0.05mm 설정은 못 쓴다.**
ΔB가 작아지면 더 나빠진다.

**홀 센서는 히스테리시스가 원리적으로 0이다** — 갈바닉 효과라 자기이력이 없다.
→ **래피드 트리거 키보드에는 홀이 원리적으로 유리하다.**
(조이스틱은 절대 위치만 쓰므로 TMR이 맞다. 용도가 다르다.)

추가로 TMR2615는 **X축(면내) 감지**라 자석이 수직 접근하는 키보드 구조와 방향이 안 맞는다.
SOT-23 홀은 패키지 면에 수직(Z축) 감지다.

### 5-C.4 센서 판단 수정

**1순위를 확정하지 않고 시제품에서 실측 비교한다.**

- 5-B.2의 "1순위 HAL9303SO" → **"1순위(잠정) — 실측 검증 조건부"** 로 격하
- **8키 시제품 보드에 SOT-23-3 풋프린트를 공용으로** 설계하여
  HAL9303SO / DRV5053VA / AH49E 교차 실장
  (세 부품 모두 SOT-23-3. **핀 배열 1=VCC/2=GND/3=OUT 여부는 반드시 확인**)
- 측정 항목: ① 정지 시 ADC 표준편차 σ ② 전 스트로크 출력 곡선(비선형성) ③ 10nF 부하 스텝 응답
- 판정 기준: σ ≤ 2 LSB (게인단 후), 곡선 재현성 ±1 LSB
- **데이터시트를 못 구하면 양산 부품에서 제외**한다

**DRV5053VA 전력 재검토** — 전류 3배는 감당 가능하다:

```
센서 96 × 2.4mA = 230mA + MCU 약 100mA + op-amp 7mA = 약 337mA
USB 2.0 500mA 안에 들어간다 (RGB 백라이트 없을 때)
```

96키로 올리면서 여유가 200mA → 163mA로 줄었다. RGB 백라이트를 얹으면 성립하지 않는다.

단점은 출력이 내부 레귤레이션(0~2V, Vq=1V)이라 **비율계측 트릭(5-B.7 ①)을 못 쓴다.**
대신 정밀 VREF가 필요하다.

### 5-D.2 ★ 비선형 계수 정정 — r = 0.106 → 0.227

축방향 원통 자석 온축 자계식으로 재계산했다.

```
B(z) = (Br/2) [ (z+H)/sqrt((z+H)^2+R^2) - z/sqrt(z^2+R^2) ]
R = 1.409mm, H = 3.387mm, Br(YX18 SmCo) ~ 0.87T
```

| z (자석 바닥 ↔ 센서) | B |
|---|---|
| 6.1mm (미압축) | **6.40 mT** |
| 5.6mm (0.5mm 눌림) | 7.92 mT |
| 2.1mm (완전압축) | **60.13 mT** |

```
ΔB          = 53.7 mT  (스트로크 4mm 전체)
평균 감도    = 13.4 mT/mm
상단 감도    = (7.92-6.40)/0.5 = 3.04 mT/mm
r = 3.04 / 13.4 = 0.227
```

| | 5-A절 가정 | **TI 실측 지오메트리** |
|---|---|---|
| 갭 | 5.0 → 1.0mm | **6.1 → 2.1mm** |
| ΔB | 25mT (추정) | **53.7mT** |
| **r** | 0.106 | **0.227 (2.1배 완화)** |

**자석에서 멀수록 곡선이 완만해진다.** 5-A절 가정이 지나치게 공격적이었다.
ΔB=53.7mT가 BA2(±40mT)를 넘고 BA3(±80mT)에 들어가는 것도 TI 선택과 일치한다 — 계산 검증됨.

### 5-D.3 재계산 — op-amp 게인단 철회

```
상단 LSB/0.1mm = 카운트 x r / 40      (r = 0.227)
목표 10 LSB → 필요 카운트 = 10 x 40 / 0.227 = 1,762   (12bit 4096의 43%)
```

| 안 | 구성 | 스윙 | 카운트 | **상단 LSB/0.1mm** | 오버샘플 후 | 스캔(96키) | 부품 추가 |
|---|---|---|---|---|---|---|---|
| **①** | **TMAG5253 UA5 단극(52mT)** ※ | 2.9V | 3,600 | **20.4** | — (1x로 충분) | **약 27us** | **없음** |
| ~~**②**~~ | ~~BA3 양극 + **VREFH 1.8V**~~ **✗ 12차 철회 — VREFH 최소 2.4V 규격 위반 (5-E.10)** | 0.81V | 1,843 | 10.5 | 14.8 (2x) | 43us | 레퍼런스+SPDT |
| **③** | BA3 양극 + VREF 3.3V + **4x** | 0.81V | 1,005 | 5.7 | **11.4** | 73us | **없음** |
| (참고) | Lucca DRV5053VA 직결 | 0.4V | 496 | 2.8 | 5.6 (4x) | — | — |

스캔 시간은 구성 A(12 MUX, 8스텝 x 6변환/ADC), 12bit Ns=2 @50MHz(t_conv 0.32us), 세틀 1.5us 기준:
`8 x (1.5 + N x 6 x 0.32)`. 구성 B(16 MUX, 6스텝)로 가면 각각 24 / 40 / 70us로 더 짧다.
**LSB 계열 수치는 키 수와 무관하므로 6차 값 그대로다.**

> ※ **10차에서 ①안의 변종이 UA5 → UA2로 바뀌었다.** 이 표의 "스윙 2.9V / 3,600 카운트 /
> 20.4 LSB"는 **앞면 실장(ΔB 53.7mT)** 전제다. 뒷면 실장을 채택한 9차 이후로는
> ΔB가 12.9~16.5mT로 줄어 UA5로는 7.9 LSB밖에 안 나온다. **최신 수치는 5-E.3을 따른다.**

**세 안 모두 목표(8~10)를 넘긴다. op-amp 게인단은 필요 없다.**

- 5-A.4 / 5-A.5 / 5-B의 "아날로그 게인 8배 필수" 결론과 **6절 리스크 12번을 철회한다.**
- op-amp는 **시제품 보험**으로만 남긴다 (0Ω 우회 점퍼, 5-B.6).

**부수 효과 — MUX 선택 근거가 바뀐다**

op-amp가 빠지면 MUX가 ADC 샘플링 커패시터를 직접 구동한다.
→ **5-B.1의 "Ron 무관" 논리가 무효가 되고, Ron·차지인젝션이 다시 중요해진다.**
→ **TMUX1308(Ron 59Ω) 채택이 오히려 더 강하게 정당화된다.** 상용 제품 선택과 일치.
→ 센서별 RC(1kΩ+10nF)는 유지한다. ADC 샘플캡은 10nF 리저버에서 Ron 59Ω를 통해
  충전되므로 τ = 0.3ns, 문제 없다.

### 5-D.4 EN 핀 멀티플렉싱 — 8kHz에는 부적합

아날로그 MUX를 없앨 수 있어 매력적이나, 기동시간이 예산을 깨뜨린다.

```
TMAG5253 기동시간 < 25us
 8스텝 x 25us = 200us  >  125us          ✗
16 ADC핀 x 6스텝 x 25us = 150us  >  125us ✗   (80키의 5스텝일 때는 125us로 여유 0이었다)
파이프라인 불가 — 같은 출력 라인 공유라 두 센서를 동시에 enable 못 함
```

**96키로 올리면서 16핀 구성마저 예산을 넘겼다.** 80키에서는 5스텝 x 25us = 125us로
이론상 딱 맞았지만, 6스텝이 되면 150us라 어떤 구성으로도 성립하지 않는다.

→ **아날로그 MUX 유지.** EN 핀은 **스캔창 밖 전체 셧다운(전력 절감)** 용도로만 쓴다.
스캔 27~43us + 기동 25us = 약 52~68us 켜짐 → 듀티 42~55% → **평균 전류 약 절반**.
TI 문서는 배터리 키보드/저속 스캔을 상정한 것으로 보인다.

### 5-D.8 실장면과 극성 — 뒷면 실장은 극성을 반전시킨다 (2026-07-26 9차)

**TI 극성 규약 (데이터시트 확인)**

> *"Magnetic flux that travels from the bottom to the top of the package is considered positive,
> which occurs when a **south** magnetic pole is near the top (marked-side) of the package."*

즉 **부호는 자석의 극성이 아니라 "패키지 기준 자속 방향"으로 정의된다.**
패키지를 뒤집으면 같은 자석이 반대 부호로 읽힌다.

**기하학**

```
[앞면 실장]                        [뒷면 실장]
   자석 N극↓                          자석 N극↓
   ─────────                          ─────────
      ↓ B (월드: 아래)                    ↓ B (월드: 아래)
   ┌───────┐ ← 마킹면(top) 위          ═══════════ PCB
   │ 센서  │                          ┌───────┐ ← 바닥면(bottom) 위
   └───────┘                          │ 센서  │
   ═══════════ PCB                    └───────┘ ← 마킹면(top) 아래

   자속: top → bottom                 자속: bottom → top
   = 음(−)                            = 양(+)
   → 북극(N) 감지 변종 필요            → 남극(S) 감지 변종 필요
```

**등가 명제: 패키지를 뒤집는 것은 자석을 뒤집는 것과 같다.**
`N극 하향 + 뒷면실장 ≡ S극 하향 + 앞면실장`

**결론 — 시장 조사(N극 하향 15 : S극 1)와 결합하면**

| 실장면 | 필요한 단극 변종 | 커버리지 | 비고 |
|---|---|---|---|
| 앞면 | **북극(N) 감지** | 15/16 | 게이트론 오로라(S극) 미지원 |
| **뒷면 (VENOM 방식)** | **남극(S) 감지** | 15/16 | 동일. 미지원 스위치도 오로라로 동일 |

**커버리지는 같다.** 다만 **주문할 부품이 정반대**다.
5-B/5-C/5-D.5에서 "완전 탈락"으로 처리한 **DRV5056(남극 전용)이 뒷면 실장에서는 유효 후보**가 된다.

**갭 페널티 — 실재하지만 5-D.5의 계산은 지나치게 비관적이었다**

뒷면 실장은 자석–센서 거리를 PCB 두께만큼(+ 패키지 높이) 늘린다.
5-D.2의 축방향 원통 자석 식으로 재계산하면:

| 구성 | z (미압축 → 압축) | ΔB | **r** | 상단 LSB/0.1mm* |
|---|---|---|---|---|
| 앞면 (TI 기준) | 6.1 → 2.1mm | **53.7mT** | 0.227 | **20.4** |
| 뒷면, PCB 1.6mm | 7.7 → 3.7mm | 16.5mT | **0.323** | **8.9** |
| 뒷면, PCB 1.2mm | 7.3 → 3.3mm | 21.5mT | **0.305** | **11.0** |

\* TMAG5253 UA5급 감도(약 54mV/mT), 12bit/3.3V, 1x 오버샘플 기준

**5-D.5가 놓친 것: r이 개선된다.** 자석에서 멀어질수록 B(z) 곡선이 완만해지므로
상단 감도/평균 감도 비율이 0.227 → 0.30~0.32로 올라간다.
ΔB가 69% 줄어드는 손실을 r 개선이 부분적으로 상쇄한다.

- **PCB 1.6mm에서도 8.9 LSB** — 목표(8~10) 경계선. **2x 오버샘플링하면 12.6 LSB로 여유.**
  스캔은 27 → 43us라 125us 예산 내다.
- **PCB 1.2mm면 11.0 LSB** — 1x로 목표 초과.
- 더 높은 감도의 단극 변종을 고르면 추가 개선. ΔB가 작아졌으므로 **좁은 범위·고감도 변종이
  오히려 더 잘 맞는다** (5-B.2에서 "넓은 범위 부품은 감도가 낮아 불리"라고 한 것과 같은 논리).

**불확실성 — 기준면이 어디인가**

TI의 "6.1mm"는 **센서 패키지 상면** 기준이다. 뒷면 실장에서 늘어나는 거리가
**PCB 두께만인지, 패키지 높이(SOT-23 약 1.1mm)까지 더해지는지**는 다이 위치에 따라 다르다.
후자라면 ΔB가 8.7mT까지 떨어져 **5.3 LSB로 목표 미달**이 된다.
→ **이 차이가 설계를 가르므로 TIMSS 시뮬레이션(7절 6번)으로 먼저 확정해야 한다.**

**뒷면 실장을 택하는 이유 (VENOM이 그렇게 한 근거 추정)**

1. **스위치 착좌면이 평평해진다** — SOT-23 패키지(높이 약 1.1mm)가 스위치 하우징·핫스왑 소켓과 간섭하지 않는다
2. **자석–센서 물리적 접촉 위험 제거** — 앞면이면 완전 압축 시 2.1mm인데 오버트래블·충격에서 닿을 수 있다
3. **조립 영역 분리** — 윗면은 소켓/LED, 아랫면은 아날로그(센서·MUX·필터). 노이즈 격리에도 유리
4. 대가는 갭 증가뿐이고, 위 계산대로 **얇은 PCB나 2x 오버샘플링으로 회수 가능**하다

**본 문서의 판단**: 뒷면 실장을 **기본으로 채택**한다. 조립·기구 이점이 확실하고
분해능 손실은 회수 가능하며, **무엇보다 상용 제품이 실제로 그렇게 하고 있다.**
→ 센서는 **남극(S) 감지 단극 변종**으로 주문한다. 리스크 22 갱신.

### 5-E.3 ★ VENOM 스위치 기준 범위 적정성 검토

VENOM은 FR4 **1.6mm** PCB에 뒷면 실장이다(5-D.6). X2SON 높이는 약 0.4mm로
SOT-23(1.1mm)보다 얇아 **갭 페널티가 리스크 30의 최악 가정보다 작다.**

5-D.2의 축방향 원통 자석 식(SmCo YX18, R=1.409mm, H=3.387mm, Br≈0.87T)으로 재계산:

| 케이스 | z (rest → bottom) | B_rest | **B_max** | ΔB | r |
|---|---|---|---|---|---|
| 앞면 (TI 기준) | 6.1 → 2.1mm | 6.40 | 60.13 mT | 53.7 | 0.227 |
| 뒷면, PCB 1.6 (패키지 무시) | 7.7 → 3.7mm | 3.65 | **20.12 mT** | 16.5 | 0.323 |
| **뒷면, PCB 1.6 + X2SON 0.4** | 8.1 → 4.1mm | 3.20 | **16.07 mT** | 12.9 | 0.343 |

**포화 여부 — UA2 기준 (73mV/mT, +39mT, V_Q 0.2V, 상한 3.1V)**

```
V_out(max) = 0.2V + 20.12mT x 73mV/mT = 1.67V   ≪ 3.1V     포화 없음 ✓
범위 사용률 = 20.12 / 39 = 52%  (X2SON 두께 포함 시 41%)
```

**분해능 — 변종별 비교** (12bit / VREF 3.3V, 상단 LSB/0.1mm = 카운트 x r / 40)

| 변종 | 감도 | 뒷면 PCB1.6 | 뒷면 +X2SON | 판정 |
|---|---|---|---|---|
| **UA2 (+39mT)** | 73 mV/mT | 1,492 카운트 → **12.0 LSB** | 1,166 → **10.0 LSB** | **★ 양쪽 다 목표(8~10) 통과** |
| UA5 (+52mT) | 48 mV/mT | 981 → **7.9 LSB** | 767 → **6.6 LSB** | **미달.** 범위가 과도하게 넓다 |
| UA1 (+20mT)* | ~142 mV/mT | **포화** (20.12 > 20) | 2,269 → 19.5 LSB | 마진 없음. 자석 편차에 취약 |

\* UA1은 특성표 미규정. 감도는 범위 역비례로 추정한 값이다.

**결론: TMAG5253UA2가 정답이다.**

- 5-D.3/5-D.7의 **①안 "UA5"는 오선택이었다.** 앞면 실장(ΔB 53.7mT)을 전제한 선택인데,
  뒷면 실장으로 ΔB가 1/3로 줄면 **더 좁은 범위 = 더 높은 감도 변종**으로 내려가야 한다.
  5-B.2에서 이미 "넓은 범위 부품은 감도가 낮아 오히려 불리"라고 적은 것과 같은 논리다.
- UA2는 범위의 41~52%만 쓰므로 **자석 편차·조립 공차에 2배 마진**이 있다.
- UA1은 분해능이 좋지만 포화 여유가 없다. **자석 Br 편차가 보통 ±10~15%임을 감안하면 위험.**

**⚠ 이 검토의 한계 — GEON 자석 사양은 비공개다**

위 계산은 **TI SLYA093의 일반 마그네틱 스위치 지오메트리** 기준이다.
**GEON Raw HE / Raptor HE의 자석 재질·치수·스트로크는 공개되지 않았다.**
VENOM이 지원 스위치를 2종으로 못박은 것 자체가 **ΔB가 스위치마다 다르다는 방증**이다.

- 자석이 더 강하면(네오디뮴 N52 등, Br 1.4T급) B_max가 SmCo 대비 **1.6배** → 32mT.
  UA2 범위(39mT) 안에는 들어오지만 **여유가 18%로 줄어든다.**
- 더 약하거나 갭이 크면 분해능이 목표 아래로 떨어진다.

→ **TIMSS 시뮬레이션(7절 6번)으로 부품 주문 전 확정한다.**
→ 시제품에는 **UA2/UA5를 같은 X2SON 풋프린트에 교체 실장**할 수 있게 설계한다.
  변종이 핀 호환이므로 **리워크만으로 비교 실측이 가능하다** — 이게 가장 확실한 대비책이다.

  핀이 존재한다는 것과 1.65V를 받아준다는 것은 다른 얘기다. → 리스크 34

**BA1을 쓰지 않는 이유**: 분해능은 BA1이 2배 좋지만 포화 여유가 20%뿐이다.
자석 Br 편차 ±10~15%와 조립 공차를 감안하면 **일부 키가 바닥에서 포화**할 수 있고,
포화는 캘리브레이션으로 복구되지 않는다. **BA2의 60% 여유가 옳은 선택이다.**

### 5-E.8 ★ 노이즈 재정립 — LSB가 아니라 센서 입력환산 노이즈가 한계다

**본 문서는 지금까지 분해능을 "0.1mm당 몇 LSB"로만 따졌다. 이건 틀린 틀이다.**
ADC를 아무리 잘게 썰어도 **센서 자체 노이즈보다 작은 자기장 변화는 읽을 수 없다.**

**상단 구간의 0.1mm가 만드는 자기장 변화**

```
상단 감도 = r x (ΔB / 4mm)
0.1mm 신호 = 상단 감도 x 0.1mm
```

| 구성 | ΔB | r | 상단 감도 | **0.1mm 신호** |
|---|---|---|---|---|
| 뒷면, X2SON (+2.0mm) | 12.87mT | 0.343 | 1.104 mT/mm | **0.110 mT** |
| 뒷면, SOT-23 (+2.7mm) | 8.71mT | 0.360 | 0.784 mT/mm | **0.078 mT** |

**센서별 입력환산 노이즈 (데이터시트 원문)**

| 센서 | B_N (pp) | RMS 환산 | **0.1mm 신호 / 노이즈** | 판정 |
|---|---|---|---|---|
| **TMAG5253UA2** | **0.12 mT** | 0.018 mT | **6.0σ** | **최고** |
| TMAG5253BA2 | 0.17 mT | 0.026 mT | **4.3σ** | ✓ 통과 |
| **DRV5053RA/EA** | **0.49 mT** (max 0.79) | 0.082 mT | **0.96σ** | **✗ 불가** |

> TMAG5253은 `B_N = B_ND x 6.6 x √f_BW` 공식이 명시돼 RMS 환산이 명확하다(pp/6.6).
> DRV5053은 pp만 주어져 pp/6로 보수 환산했다.

**판정 기준은 3σ다** (5-A.8: 0.1mm 신호가 노이즈 3σ보다 커야 채터가 없다).

- **TMAG5253BA2: 4.3σ** — 1x로도 통과. 4x 오버샘플링하면 8.5σ로 여유.
- **DRV5053: 0.96σ** — **신호가 노이즈에 묻힌다.** 4x 오버샘플링해도 1.9σ, 16x를 해야 3.8σ인데
  그러면 스캔 시간이 폭발한다. **0.1mm 분해능 설계에 쓸 수 없다.**

**★ 이것이 Lucca-58HE의 미스터리를 설명한다**

5-B.9에서 "Lucca-58HE는 DRV5053VA 직결이라 상단 1.3 LSB 문제가 실제로 존재할 구성"이라고
적었고, 5-A.1에서는 ATTACK SHARK의 *"저가 구현은 0.01mm를 표방해도 실제로는 노이즈를 감추려
펌웨어에서 0.1mm로 반올림한다"* 를 인용했다.

**두 관찰의 원인이 같다 — DRV5053의 0.49mT 입력환산 노이즈다.**
ADC 비트수나 게인단의 문제가 아니었다. 센서를 바꾸지 않으면 해결되지 않는 문제다.

→ **5-B.2의 "2순위 DRV5053VA", 5-C.4의 "SOT-23 교차 실장 후보"에서 DRV5053을 제외한다.**

### 5-E.9 ★ VENOM 호환 스위치 스펙 분석 (사용자 제공)

```
Compatible Switches
 - RAPTOR HE / RAW HE / Lucifer HE / GATERON KS-20, KS-20T 등
 - N-pole switch, 1600gs or less at bottom magnetic force
```

**① "N-pole switch" — 극성 분석이 확정됐다**

5-D.5의 시장 조사(N극 하향 15 : S극 1)와 5-D.8/5-E.1의 극성 반전 논리가
**상용 제품 스펙으로 직접 확인됐다.**

- VENOM은 **N극 하향 스위치만** 지원한다고 명시한다.
- 5-D.5에서 유일한 S극 스위치로 확인한 **게이트론 오로라는 지원 목록에 없다.**
  → **리스크 25("오로라 미지원 가능성")는 리스크가 아니라 업계 표준 관행이다.**
  VENOM도, 우리도 같은 선택을 하면 된다.
- 뒷면 실장 + N극 하향 = 양(+) → **TMAG5253U(남극 감지) 사용 가능**이 재확인됐다.

**② "1600gs or less at bottom" = 최대 160mT — 그러나 측정 기준면이 불명확하다**

이건 **호환 상한선**이다. 즉 VENOM의 센서는 1600Gs 스위치에서 포화하지 않는다.
문제는 **어디서 잰 값이냐**다.

| 해석 | 센서가 보는 B_max | 적합 센서 |
|---|---|---|
| (a) **PCB 상면/표준 기준점**에서 측정 | 뒷면 실장 센서는 **약 25~30mT** | **BA2(±40mT) / UA2(+39mT)** ✓ |
| (b) **센서 위치**에서 측정 | **160mT** | BA4(±160mT)뿐 — 감도 7.5mV/mT로 **분해능 붕괴** |

**(a)가 유력하다**:
- 5-D.2 자석 모델로 역산하면 N52 자석이 **z ≈ 1.5mm**일 때 168mT가 나온다.
  이는 **PCB 상면 근처** 거리다. 뒷면 실장 센서는 여기서 PCB 두께 + 패키지만큼 더 멀다.
- 같은 모델로 뒷면 실장 위치(z ≈ 4.2mm)를 계산하면 **25.5mT**로 떨어진다.
- (b)가 맞다면 VENOM은 BA4급을 써야 하는데, 그러면 0.1mm 분해능이 물리적으로 안 나온다.
  VENOM이 광고하는 0.16ms 레이턴시·래피드트리거와 모순된다.

**→ 하지만 추정이다. 스위치 1개를 가우스미터로 재면 즉시 끝난다.** 리스크 36.

**③ 다종 스위치 지원의 진짜 요구사항 — 동적 범위**

지원 목록이 4개 계열(RAPTOR/RAW/Lucifer/GATERON)로 늘면 자석 세기가 편차를 갖는다.
"1600gs **이하**"라는 표현 자체가 **상한만 규정하고 하한은 열어둔 것**이다.

설계 규칙은 두 갈래로 갈린다:

```
범위(포화)   ← 가장 강한 스위치(1600Gs) 기준으로 정한다
분해능       ← 가장 약한 스위치 기준으로 검증한다
```

- **포화는 캘리브레이션으로 복구되지 않는다.** 범위는 반드시 최강 기준.
- 세기 편차 자체는 **키별 rest/bottom 2점 캘리브레이션**(5-A.6 ③)이 흡수한다.
  이미 설계에 들어 있으므로 추가 작업은 없다.
- 다만 **약한 스위치에서 ΔB가 작아지면 분해능이 떨어진다.**
  지원 목록을 넓힐수록 이 하한이 설계를 지배한다.

**본 문서의 대응**: VENOM과 동일한 목록을 지원하는 데 **원리적 장애는 없다.**
다만 확정하려면 **지원 목록 중 가장 약한 스위치와 가장 강한 스위치 2종의 ΔB 실측**이 필요하다.
TIMSS는 자석 제원을 알아야 돌릴 수 있으므로, 이 경우엔 **실물 가우스미터 측정이 더 빠르다.**

**④ 센서 선택에 미치는 영향 — DRV5053이 여기서도 탈락한다**

DRV5053의 포화 자기장 B_SAT(= 0.8V / 감도):

| 변종 | 감도 | **B_SAT** | 1600Gs(160mT) 대응 |
|---|---|---|---|
| VA | 90 mV/mT | 약 9mT | ✗ |
| RA / EA | 45 mV/mT | 약 18mT | ✗ |
| PA / CA | 23 mV/mT | 약 35mT | ✗ |
| OA | 11 mV/mT | **73mT** | ✗ (최대 변종도 부족) |

해석 (b)라면 **DRV5053은 전 변종이 포화**한다. 해석 (a)라도 RA/EA(18mT)는
센서 위치 25~30mT에 못 미쳐 **PA/CA(35mT)까지 내려가야 하고, 그러면 노이즈 대비 신호가 더 나빠진다.**
5-E.8의 노이즈 결론과 합쳐 **DRV5053은 확정 탈락**이다.

### 5-E.10 ★ VREFH / VREFL 확정 — ②안 철회, 그리고 최종 구성

**HPM5300 데이터시트 Rev0.11 「4.12.1 16位模数转换 ADC 特性」 원문**

| 파라미터 | 기호 | 최소 | 전형 | 최대 | 단위 |
|---|---|---|---|---|---|
| 입력 신호 전압 | Vin | **VREFL** | — | **VREFH** | V |
| 참고 고전위 | **VREFH** | **2.4** | — | **VDDA** | V |
| 참고 저전위 | **VREFL** | **0** | — | **(미기재)** | V |
| 전원 전압 | VDDA | 3.0 | 3.3 | 3.6 | V |
| 입력 샘플링 용량 | Cs | — | 4 | — | pF |
| 샘플 스위치 저항 | Ron | — | **300** | — | Ω |

**① ★ VREFH 최소 2.4V — ②안이 성립하지 않는다**

5-D.3 이후 유지해온 **②안 "BA3 양극 + VREFH 1.8V + 2x"는 불가능하다.**
**VREFH는 2.4V 아래로 못 내린다.** 6차 개정부터 11차까지 이 전제가 검증 없이 끌려왔다.

→ **②안을 철회한다.** VREF 축소로 얻을 수 있는 최대치는 **VREFH = 2.4V**다.

**② VREFL 상한은 규정되지 않았다 — "보증 없음"으로 읽어야 한다**

최소값 0V만 규정되고 전형/최대 칸이 비어 있다. 절대최대정격 표에도 VREFL 항목이 없다.
`Vin = VREFL ~ VREFH`라고 쓴 것은 VREFL이 0이 아닐 수 있음을 시사하지만,
**상한이 없다는 것은 스펙이 없다는 뜻이고 곧 보증되지 않는다는 뜻이다.**

→ **VREFL = 1.65V 방안(5-E.6)은 "미확인"이 아니라 "미보증"으로 강등한다.**
   쓰려면 실측 검증이 필요하고, 양산 설계의 기반으로 삼아서는 안 된다.

**③ 그래서 VREFL을 건드리지 않는 구성이 필요하다 — 단극이 답이다**

단극(UA2)은 V_Q가 0.2V로 **이미 바닥에 붙어 있어 VREFL을 올릴 이유가 없다.**
양극(BA)만이 V_Q = VCC/2라서 VREFL 상승이 필요했던 것이다.

뒷면 실장 X2SON(ΔB 12.87mT, r 0.343) 기준 비교:

| 구성 | VREFL | VREFH | 카운트 | **상단 LSB/0.1mm** | 비율계측 | 판정 |
|---|---|---|---|---|---|---|
| **UA2, VCC=VREFH=3.3V** | 0 | 3.3 | 1,166 | **10.0** | **✓ 유지** | **★ 채택** |
| UA2, VCC 3.3V / VREFH 2.4V | 0 | 2.4 | 1,604 | 13.8 | ✗ 상실 | 이득 대비 손해 |
| BA2, VREFH 2.4V | 0 | 2.4 | 659 | 5.7 | ✗ | 4x 오버샘플 필요 |
| BA2, VREFL 1.65V | **1.65** | 3.3 | 958 | 8.2 | ✗ | **미보증** |
| ~~BA3, VREFH 1.8V (②안)~~ | — | — | — | — | — | **✗ 규격 위반** |

**④ 비율계측을 깨면서까지 VREFH를 낮출 이유가 없다**

VREFH를 2.4V로 낮추면 13.8 LSB로 오르지만, 센서는 3.3V 비율계측이므로
**5-B.7 ①번의 전원 드리프트 상쇄가 무너진다.** 별도 정밀 레퍼런스도 필요해진다.

센서와 VREFH를 **둘 다 2.4V**로 맞추면 비율계측은 유지되지만,
그 경우 카운트는 3.3V/3.3V와 **정확히 같다**(비율계측의 정의상 VCC에 무관).
즉 **비율계측을 유지하는 한 VREF 조작으로 얻는 이득은 0이다.**

→ **VCC = VREFH = 3.3V 공유 LDO 그대로 간다. 10.0 LSB로 목표를 이미 만족한다.**
   정밀 레퍼런스도, VREFL 버퍼도, 게인단도 필요 없다. **가장 단순한 구성이 정답이다.**

**⑤ 부수 확인 — Ron 300Ω / Cs 4pF**

ADC 샘플링 스위치 자체가 **Ron 300Ω**이다. MUX Ron(TMUX1308 59Ω)을 직렬로 더해도
총 360Ω이고, 센서별 10nF 리저버에서 충전되므로 τ = 360Ω x 4pF = **1.4ns**.
3-A.4에서 걱정한 Ns(샘플 클럭) 문제는 **10nF 리저버가 있는 한 발생하지 않는다.**

### 5-E.12 BA3 / BA4로 내려가면 무엇이 깨지는가

**핵심 사실: 입력환산 노이즈는 변종과 무관하다**

데이터시트의 출력환산 노이즈가 감도에 정확히 비례한다:

| 변종 | 감도 | 출력 노이즈 (pp) | **입력환산 = 출력/감도** |
|---|---|---|---|
| BA1 | 60 mV/mT | 9.2 mV | 0.153 mT |
| BA2 | 30 | 4.6 | 0.153 mT |
| BA3 | 15 | 2.3 | 0.153 mT |
| BA4 | 7.5 | 1.2 | 0.160 mT |

**센서의 자기 분해능 바닥은 어느 변종을 골라도 같다.** 변종은 출력 전압 배율만 바꾼다.
→ **신호와 노이즈가 함께 스케일되므로, 센서 노이즈가 지배하는 한 SNR은 변종과 무관하다.**

**그래서 깨지는 지점은 딱 하나 — ADC 양자화가 센서 노이즈를 추월할 때다**

뒷면 실장 X2SON 기준(ΔB 12.87mT, r 0.343, 상단 0.1mm = **0.110mT**), 12bit/3.3V(1 LSB = 0.806mV):

| 변종 | 0.1mm 신호 | 센서 노이즈 σ | 양자화 σ | 합성 σ | **SNR** | 전 스트로크 카운트 |
|---|---|---|---|---|---|---|
| **UA2** | **9.96 LSB** | 1.60 | 0.29 | 1.63 | **6.1σ** | 1,166 |
| BA1 | 8.19 | 1.73 | 0.29 | 1.75 | 4.7σ | 958 |
| **BA2** | **4.09** | 0.87 | 0.29 | 0.91 | **4.5σ** | 479 |
| **BA3** | **2.05** | 0.43 | 0.29 | 0.52 | **3.9σ** | 240 |
| **BA4** | **1.02** | 0.23 | **0.29** | 0.37 | **2.8σ ✗** | **120** |

(양자화 σ = 1/√12 = 0.289 LSB. 센서 노이즈는 출력 pp를 TI 공식대로 /6.6 하여 RMS 환산)

**BA1·BA2는 SNR이 거의 같다(4.5~4.7σ).** 센서 노이즈가 지배하기 때문이다.
**BA3에서 양자화가 개입하기 시작하고(3.9σ), BA4에서 양자화가 센서 노이즈를 추월한다(2.8σ).**

교차점은 출력 노이즈가 1.54mV pp일 때 — **BA3(2.3mV)과 BA4(1.2mV) 사이다.**

**깨지는 포인트 4가지**

**① BA4: 0.1mm = 1.02 LSB — 한 카운트다**

```
0.110mT x 7.5mV/mT = 0.825mV   vs   1 LSB = 0.806mV
```

상단 구간에서 **0.1mm 움직여야 ADC 값이 겨우 1 바뀐다.** 이 지점에서 무너지는 것:
- **래피드 트리거가 성립하지 않는다.** 5-A.8의 판정은 차분(`peak - d >= up_sens`)인데,
  임계값이 1카운트면 디더 한 번에 토글한다. **0.05mm 설정은 아예 불가능하다.**
- 전 스트로크가 **120카운트**뿐이다. libhmk의 내부 표현(0~255, 8bit)보다도 거칠다.
- **ADC 비트를 올려도 해결되지 않는다.** 3-A절 결론대로 ADC16의 ENOB이 12~13bit라
  16bit로 가도 실효 분해능이 안 는다.

**② BA3: 3.9σ — 통과하지만 마진이 없다**

3σ 기준은 넘지만 여유가 30%다. 여기에 아래가 겹치면 바로 무너진다:
- 자석이 약한 스위치(5-E.9 ③의 "가장 약한 스위치")에서 ΔB가 줄면 그대로 σ가 깎인다
- 리스크 30의 갭 최악 가정(패키지 높이 포함)이 현실이면 ΔB 12.87 → 8.71로 줄어 **2.7σ**
- **4x 오버샘플링으로 σ를 절반으로 줄이면 7.8σ로 회복된다.** 스캔 27 → 73us.
  이게 BA3를 쓸 때의 대가다.

**③ 오프셋 드리프트가 스트로크를 잡아먹는다**

V_Q 온도 드리프트 ±50mV(0~85°C, 단극 실측치 기준 추정)를 입력환산하면:

| 변종 | 입력환산 드리프트 | ΔB 12.87mT 대비 | 스트로크 환산 |
|---|---|---|---|
| UA2 | 0.68 mT | 5% | 0.21mm |
| BA2 | 1.67 mT | 13% | 0.52mm |
| BA3 | 3.33 mT | 26% | 1.03mm |
| **BA4** | **6.67 mT** | **52%** | **2.1mm** |

BA4는 **온도만으로 키 스트로크의 절반이 밀린다.**
자동 재캘리브레이션(5-A.8, 무입력 3초)이 흡수하긴 하지만,
**재캘리브레이션에 전적으로 의존하는 설계가 된다** — 연타 중에는 보정이 안 걸린다.

> 양극 V_QΔT는 데이터시트에서 확인하지 못해 **단극 UA2 값(±50mV)으로 추정**했다.
> 절대값은 다를 수 있으나 **변종 간 4배 차이라는 관계는 감도 비율에서 나오므로 유효하다.**

**④ ③안이 뒷면 실장에서 무너진다 — 미처 갱신 못 한 부분**

5-D.3의 ③안 "BA3 + 4x = 11.4 LSB"는 **앞면 실장 ΔB 53.7mT** 기준이었다.
9차에서 뒷면 실장으로 바꿀 때 ①안만 재계산하고 ③안은 그대로 뒀다.

```
앞면: ΔB 53.7mT x 15mV/mT = 0.81V → 1,005 카운트 → 5.7 LSB (4x로 11.4)
뒷면: ΔB 12.87mT x 15mV/mT = 0.19V →   240 카운트 → 2.05 LSB (4x로 4.1)
```

→ **③안도 철회한다.** 뒷면 실장에서 BA3는 4x 오버샘플링을 해야 겨우 성립한다.

**그럼 왜 BA3/BA4를 고려하는가 — 포화 보험이다**

B_max 16.07mT(뒷면 X2SON, TI 자석 모델) 기준 범위 사용률:

| 변종 | 범위 | 사용률 | 1600Gs=160mT 해석 (b)일 때 |
|---|---|---|---|
| BA1 | ±20mT | 80% | 포화 ✗ |
| **BA2** | ±40mT | **40%** | 포화 ✗ |
| BA3 | ±80mT | 20% | 포화 ✗ |
| **BA4** | ±160mT | 10% | **유일하게 생존** |

**여기가 리스크 36과 정면으로 만난다.**

- 해석 (a)(PCB 상면 기준, 센서는 25~30mT)라면 **BA2로 충분하고 BA3/BA4는 순손실**이다.
- 해석 (b)(센서 위치 160mT)라면 **BA4만 포화를 면하는데, BA4로는 0.1mm를 못 한다.**

**즉 해석 (b)가 사실이면 "뒷면 실장 + 강한 자석 + 0.1mm"는 동시에 성립하지 않는다.**
그 경우의 선택지는 세 가지뿐이다:

1. **지원 스위치를 제한한다** — VENOM이 "1600gs 이하"로 상한을 건 것이 바로 이 조치다
2. **센서를 자석에서 더 멀리** — PCB를 두껍게 하거나 스페이서. B를 낮춰 BA2 범위에 넣는다
3. 0.1mm를 포기하고 0.2mm 분해능으로 간다

→ **BA3/BA4는 "센서 선택"이 아니라 "설계 전제가 틀렸다는 신호"로 읽어야 한다.**
   스위치 1개만 가우스미터로 재면 이 분기가 즉시 닫힌다(리스크 36).

### 5-E.13 ★ 자석 재질 시나리오 x JLCPCB 재고 — 실질 선택

**JLCPCB 재고 순서 (사용자 확인): BA1 > BA3 > BA4 > BA2**

UA 계열은 유통 재고가 없고(5-E.6), 권장하던 **BA2가 하필 재고 최하위**다.
따라서 BA1/BA3를 진지하게 평가해야 한다. 그런데 **자석 재질이 이 판단을 지배한다.**

**전제 재검토 — TI의 SmCo는 TI의 모델링 선택일 뿐이다**

5-D.1에서 인용한 SLYA093 원문은 자석을 *"remanence equal to that of a **YX18 samarium cobalt**"*
로 규정한다. 그런데 **실제 HE 스위치는 대부분 네오디뮴(NdFeB)을 쓰는 것으로 알려져 있다.**
SmCo는 고온 안정성이 필요한 차량용에 쓰이고 단가가 높다. **확인 필요 항목이다(리스크 39).**

잔류자속밀도 Br 비율로 스케일하면:

| 시나리오 | Br | ΔB | B_max | 상단 0.1mm 신호 |
|---|---|---|---|---|
| **S** — SmCo YX18 (TI 모델) | 0.87T | 12.87mT | 16.07mT | 0.110mT |
| **N35** — 네오디뮴 (x1.38) | 1.20T | 17.75mT | 22.2mT | 0.152mT |
| **N52** — 네오디뮴 강 (x1.67) | 1.45T | 21.4mT | 26.8mT | 0.183mT |

**시나리오 x 변종 전수 판정** (뒷면 실장 X2SON, 12bit/3.3V, 1x 오버샘플)

| 변종 | 재고 | σ(LSB) | **S: SNR / 포화** | **N35: SNR / 포화** | **N52: SNR / 포화** |
|---|---|---|---|---|---|
| **BA1** ±20mT | **1위** | 1.75 | 4.7σ / **80%** | 6.4σ / **111% ✗** | 7.8σ / **134% ✗** |
| **BA3** ±80mT | **2위** | 0.52 | 3.9σ / 20% | **5.4σ / 28%** | **6.6σ / 34%** |
| BA4 ±160mT | 3위 | 0.37 | 2.8σ ✗ / 10% | 3.8σ / 14% | 4.6σ / 17% |
| **BA2** ±40mT | **4위** | 0.91 | 4.5σ / 40% | **6.2σ / 55%** | **7.5σ / 67%** |

**읽는 법**

- **BA2는 세 시나리오 모두 통과한다** (4.5~7.5σ, 포화 40~67%). 여전히 기술적 최선이다.
- **BA1은 자석이 SmCo급으로 약할 때만 성립한다.** 네오디뮴이면 **포화한다.**
  재고 1위라고 고르면 안 된다. **포화는 캘리브레이션으로 복구되지 않는다.**
- **BA3는 자석이 네오디뮴이면 5.4~6.6σ로 넉넉히 통과한다.** 포화 여유도 28~34%로 크다.
  **재고 2위이므로 실질적 1순위 대안이다.**
- BA4는 N52에서도 0.1mm가 1.7 LSB라 래피드 트리거 차분이 거칠다. 여전히 부적합.

**왜 강한 자석이 BA3를 살리는가**

센서 노이즈는 변종 무관 고정(0.153mT)인데, 자석이 강해지면 **신호만 커진다.**
양자화 σ(0.29 LSB)는 고정이므로, 신호가 커질수록 BA3의 약점(양자화 개입)이 희석된다.
**"넓은 범위 = 나쁘다"는 5-B.2의 원칙은 자석이 약할 때만 성립한다.**

**결론 — 재고 제약을 반영한 실질 권고**

| 우선순위 | 변종 | 근거 |
|---|---|---|
| **1** | **BA3** | 재고 2위. 네오디뮴이면 5.4σ + 포화 여유 28%. **자석 재질이 불확실한 지금 가장 안전** |
| **2** | **BA2** | 기술적 최선(전 시나리오 통과)이나 **재고 최하위**. 확보되면 이쪽 |
| 3 | BA1 | 재고 1위지만 **네오디뮴에서 포화**. 자석을 SmCo급으로 확인한 뒤에만 |
| ✗ | BA4 | 양자화 한계 |
| (최선) | UA2 | 유통 재고 없음. TI 직구/대리점 문의 대상 |

**BA3를 1순위로 두는 이유는 "불확실성 하에서 깨지지 않는 쪽"이기 때문이다.**
BA1은 자석이 세면 포화해서 **아예 못 쓰고**, BA3는 자석이 약하면 3.9σ로 **마진이 줄 뿐**이다.
그리고 3.9σ는 **4x 오버샘플링(스캔 27 → 73us)으로 7.8σ까지 회복된다.** 예산 안이다.
**깨지는 실패와 나빠지는 실패 중에서는 후자를 골라야 한다.**

**8키 시제품 대응**: BA1/BA2/BA3는 **모두 동일한 X2SON 4핀 풋프린트**다.
**리워크만으로 교체 실측이 가능하므로 세 종을 소량씩 확보해 한 보드에서 비교한다.**
이것이 자석 재질(리스크 39)과 1600Gs 기준면(리스크 36)을 동시에 닫는 가장 빠른 길이다.

**★ 경쟁 제품의 "0.005mm"는 측정 분해능이 아니다**

MonsGeek FUN68은 **"Continuous Rapid Trigger 0.005mm", "0.005mm 단위 작동거리 조절"** 을 광고한다.
우리 목표(0.1mm)의 20배다. 물리적으로 가능한가 — **불가능하다.**

```
본 문서 최선 구성(UA2, 뒷면 실장): 0.1mm = 9.96 LSB, SNR 6.1σ
                        →  0.005mm = 0.50 LSB, SNR 0.31σ
```

**0.005mm는 센서 노이즈의 1/3에 묻힌다.** 어떤 필터로도 복구되지 않는다.
따라서 이 수치는 **펌웨어의 설정 입력 단위**이지 측정 분해능이 아니다.
5-A.1에서 인용한 ATTACK SHARK의 지적(*"0.01mm를 표방해도 실제로는 노이즈를 감추려
펌웨어에서 반올림한다"*)과 정확히 같은 구조다.

→ **본 문서의 0.1mm 목표는 보수적인 것이 아니라 정직한 것이다.**
   경쟁 스펙시트의 소수점을 따라갈 필요가 없다. 6σ 마진을 갖는 0.1mm가 실사용 품질을 결정한다.

## 5-F. 확정 구성 타이밍 예산 — ~~BA2~~ **BA3** + TMUX1308APWR (13차, 15차 일부 정정)

> ⚠ **15차: 센서 변종이 BA2 → BA3로 바뀌었다** (5-G.6). **타이밍 예산은 전부 그대로 유효하다** —
> 변종이 달라져도 감도만 다를 뿐 변환 시간·세틀링·스캔 구조가 동일하기 때문이다.
> 이 절에서 무효인 것은 **분해능(LSB) 관련 언급뿐**이며, 시간 수치는 손대지 않는다.

설계 착수 구성이 확정됐다. **모든 수치를 이 조합 기준으로 재계산한다.**

### 5-F.2 단위 시간

| 항목 | 계산 | 값 |
|---|---|---|
| ADC 1변환 | (14 + 2) 클럭 / 50MHz | **320 ns** |
| ~~MUX 세틀링 (typ)~~ | ~~τ = (Ron 59Ω + 100Ω) x 1nF = 159ns, 12bit는 8.3τ~~ | ~~**1.5 us**~~ |
| ~~└ 최악 (Ron max 195Ω)~~ | ~~τ = 295ns x 8.3~~ | ~~2.5 us~~ |
| **MUX 세틀링 (17차 정정)** | τ = **R16 x C56 = 100Ω x 10nF = 1us**, ADC쪽 캡 DNP | **3.0 us** |
| CPU 1사이클 | 1 / 480MHz | 2.08 ns |

> ## ⚠⚠ 17차 정정 — 위 세틀링 식은 **틀렸다** (→ 5-I)
>
> `τ = (Ron + 100Ω) x 1nF = 159ns`는 **소스를 이상전압원으로 가정**한 식이다.
> 5-D.7에서 게인단을 철회한 순간 이 가정이 깨졌는데 식이 그대로 남았다.
>
> ```
> 실제 구동원 :  센서 ──[R16 1kΩ]──┬── C56 10nF ──MUX──[100Ω]──┬── ADC
>                                   ↑ 여기가 진짜 소스           └ C 1nF
> ```
> 1nF를 채우는 전하 `1nF x ΔV`는 **결국 C56에서 나오고**, C56은 R16 뒤에 있다.
> 지배 시정수는 159ns가 아니라 **`R16 x C56 = 10us`(66배)** 다.
>
> | | 이 절의 결론 | **실제 (5-I.2)** |
> |---|---|---|
> | ADC쪽 1nF | 세틀링 1.5us면 충분 | 1.5us 후 잔류 **99 LSB ≈ 0.44mm** |
> | ADC쪽 220pF | "충분하다, 세틀링 0.3us로 단축 가능" | 1.5us 후 잔류 **25 LSB** |
> | **ADC쪽 DNP** | 검토 안 함 | **0.42 LSB** (R16=100Ω, 1.5us) ← **정답** |
>
> **"1nF는 ADC 샘플캡의 250배라 충분"은 판정 기준부터 틀렸다.** ADC쪽 캡은 도움이
> 되는 게 아니라 **매 MUX 스텝 재충전해야 하는 부채**다. 캡을 키우면 샘플 시정수
> `τ_s = (Ron+R18) x (C_d + C_sh)`도 같은 비율로 커져 ADC 채널 크로스토크까지
> 악화된다 (220pF → 4.5 LSB). → 5-I.6

**CPU 부담 15.3us / 125us = 12.2%.** 인터럽트는 125us당 1회.

### 5-F.6 ★ 오버샘플링 재검토 — 버스트 평균은 거의 효과가 없다

> **13차 정정.** 3-A.3 / 5-A.7 / 5-F 초안의 "4x 오버샘플링 = 노이즈 1/2" 는 **틀렸다.**
> 평균이 노이즈를 √N으로 줄이려면 **샘플이 서로 무상관이어야 한다.**

**노이즈 상관 시간**

```
센서 대역폭 15kHz            → τ ≈ 1/(2π x 15k) = 10.6 us
RC 필터 1kΩ x 10nF          → τ = 10.0 us
→ ADC에 들어오는 노이즈의 상관 시간 ≈ 10 us
```

같은 MUX 주소에서 연속 변환하는 **버스트 오버샘플링의 샘플 간격은 320ns**다.
상관계수 `ρ = exp(−0.32/10) = 0.97` — **거의 같은 노이즈 값을 4번 읽는 것**이다.

| 방식 | 샘플 간격 | ρ | 센서 노이즈 저감 |
|---|---|---|---|
| **버스트 오버샘플 (스텝 내)** | 320 ns | **0.97** | **거의 없음** |
| 2회 스캔 / 프레임 | 62.5 us | 0.002 | **√2 (완전)** |
| 3회 스캔 / 프레임 | 41.7 us | 0.016 | **√3 (완전)** |
| 프레임 간 EMA | 125 us | 4e-6 | 완전 |

**버스트 평균은 ADC 자체 노이즈(백색, 무상관)만 줄인다.** 센서 노이즈는 그대로 남는다.

| 방식 | 센서 σ | ADC σ | 합성 σ | **SNR** | ADC 시간 | 프레임 |
|---|---|---|---|---|---|---|
| **1x** | 0.87 | 0.29 | 0.912 | **4.48σ** | 27.4 us | 42.7 us (34%) |
| 4x 버스트 | 0.87 | 0.145 | 0.882 | **4.63σ (+3%)** | **73.4 us** | 88.7 us (71%) |
| **2회 분산 스캔** | 0.62 | 0.20 | 0.645 | **6.34σ (+42%)** | 54.8 us | **70.1 us (56%)** |
| 3회 분산 스캔 | 0.50 | 0.17 | 0.527 | **7.76σ (+73%)** | 82.2 us | 97.5 us (78%) |

**4x 버스트는 46us를 더 쓰고 SNR을 3% 올린다. 명백한 낭비다.**
**같은 시간이면 스캔을 프레임 안에 분산시켜야 한다** — 2회 분산이 4x 버스트보다
**시간은 19us 덜 쓰고 SNR은 37% 더 좋다.**

**→ 권장: 오버샘플링 없이 1x로 시작하고, 노이즈가 문제되면 `분산 스캔`으로 간다.**
`ADC_LOOP` 미지원(6.1절)이라 어차피 버스트는 SW 반복이므로, 분산 스캔이 구현 부담도 같다.

**분산 스캔 = 스캔 주파수를 올리는 것과 같다** (2회 = 16kHz 스캔). 5-F.10 참조.

> (이유는 5-F.11 ④). VENOM의 **0.16ms 레이턴시는 우리 1x 구성(126us)과 같은 영역**이다.
> **1x 무필터로 시작하고, 부족하면 분산 스캔 → 그래도 부족하면 EMA 순으로 간다.**

### 5-F.10 ★ 스위치 1개당 스캔 주파수

**결론: 키 1개당 샘플링 주파수 = 프레임 주파수 = 8 kHz다. 96으로 나누지 않는다.**

```
1 프레임(125us) 안에서 96키 전부를 스캔한다  →  키마다 정확히 1샘플/125us
                                            →  키당 스캔 주파수 = 8 kHz
```

96채널을 **12개 MUX 병렬 + ADC0/ADC1 병렬**로 처리하기 때문에
"채널이 많아질수록 키당 샘플링이 느려지는" 시분할 구조가 아니다.
키 수가 늘면 **프레임 안의 스캔 시간(27.4us)** 이 늘 뿐, 키당 주파수는 그대로다.

| 지표 | 값 |
|---|---|
| **키당 샘플링 주파수** | **8 kHz** |
| 키당 샘플 간격 | 125 us |
| 키당 ADC 점유 시간 | 285 ns |
| **키당 점유율** | **285ns / 125us = 0.23%** |
| 전체 스캔 점유율 | 27.4us / 125us = 21.9% |

**스캔 주파수의 상한**

| 제약 | 주기 | **최대 스캔 주파수** |
|---|---|---|
| ADC 스캔만 (DMA 자동, CPU 무관) | 27.4 us | **36.5 kHz** |
| 스캔 + 키로직 전체 | 42.7 us | **23.4 kHz** |
| USB HID 출력 (HS bInterval=1) | 125 us | **8 kHz 고정** |

**즉 하드웨어는 키당 23kHz까지 스캔할 수 있고, USB 출력만 8kHz로 묶여 있다.**
(VENOM이 8kHz 폴링에 14kHz 스캔을 하는 구조가 이것이다 — 5-D.6)

**왜 8kHz인가 — 신호 대역폭 때문이 아니다**

```
키 스트로크 4mm를 1m/s로 누르면 4ms.  기계적 대역폭은 수백 Hz 수준.
8kHz 샘플링의 나이퀴스트는 4kHz  →  대역폭 여유가 10배 이상이다.
```

**8kHz는 신호를 재현하기 위한 것이 아니라 USB 지연을 줄이기 위한 것이다.**
따라서 **남는 샘플링 여유를 노이즈 저감에 쓰는 것이 합리적**이고,
그 방법이 5-F.6의 **분산 스캔**이다.

**스캔 주파수 선택지**

| 스캔 주파수 | 프레임당 스캔 | ADC 시간 | 프레임 점유 | SNR | 비고 |
|---|---|---|---|---|---|
| **8 kHz** | 1회 | 27.4 us | **42.7us (34%)** | 4.48σ | **기본. 가장 단순** |
| **16 kHz** | 2회 평균 | 54.8 us | 70.1us (56%) | **6.34σ** | 노이즈 문제 시 |
| 24 kHz | 3회 평균 | 82.2 us | 97.5us (78%) | 7.76σ | 상한 근처 |
| ~32 kHz | 4회 평균 | 109.6 us | 124.9us (**99.9%**) | 8.96σ | **여유 없음. 불가** |

**HID 출력은 어느 경우든 8kHz다.** 스캔만 빨리 돌려 평균한다.

### 5-F.11 왜 스캔 주파수를 올리면 SNR이 좋아지는가

**주파수 자체가 SNR을 올리는 것이 아니다.** 올라가는 것은 **출력 1회당 평균 낼 수 있는
독립 샘플의 개수**이고, 그것이 노이즈를 줄인다.

```
SNR 이득 = √N,   N = 스캔 주파수 / 출력 주파수(8kHz)
```

16kHz로 스캔해서 **16kHz로 그대로 출력**하면 SNR은 전혀 좋아지지 않는다.
16kHz로 스캔해서 **2개를 평균해 8kHz로 출력**할 때만 √2가 붙는다.

**① 왜 √N인가 — 신호는 더해지고 노이즈는 상쇄된다**

같은 키를 N번 재면 각 측정값은 `x_i = S + n_i` 다. S는 매번 같고, n_i는 매번 다르다.

```
N개를 더하면    신호: N x S      (선형 합산 — 매번 같은 값이므로)
                노이즈: σ x √N   (제곱합산 — 부호가 랜덤이라 서로 상쇄)
N으로 나누면    신호: S,  노이즈: σ/√N
→ SNR이 √N배
```

노이즈가 **랜덤이라서** 상쇄되는 것이다. 매번 같은 값이면 신호처럼 N배로 더해져 상쇄되지 않는다.
**이것이 "독립적이어야 한다"는 조건의 실체다.**

**② 주파수 영역 해석 — 노이즈 대역폭을 잘라낸다**

노이즈는 대역(15kHz) 전체에 퍼져 있고, 노이즈 전력 = PSD x 대역폭이다.
N개 평균은 차단주파수 약 `f_out/2`의 저역통과 필터로 동작해 **노이즈 대역폭을 1/N로 줄인다.**

```
노이즈 전력 ∝ 대역폭   →  1/N
노이즈 진폭 ∝ √대역폭  →  1/√N
```

**여기서 중요한 것은 신호를 안 다친다는 점이다.**
키 움직임은 수백 Hz 이하인데(5-F.10) 우리는 8kHz로 샘플링한다.
**대역폭이 10배 이상 남아돌기 때문에 잘라내도 신호 손실이 없다.**
남는 대역폭을 노이즈 저감으로 바꾸는 것 — 이것이 오버샘플링의 본질이다.

**③ 왜 버스트 오버샘플링은 안 되는가**

320ns 간격 4연속 측정은 **같은 노이즈 값을 4번 읽는 것**이다(ρ=0.97, 5-F.6).
새로운 정보가 없으므로 평균해도 그대로다.

> 천천히 흔들리는 저울을 **1ms 안에 4번 읽는 것**과 **1초에 걸쳐 4번 읽는 것**의 차이다.
> 전자는 같은 순간값을 4번 본 것이고, 후자라야 흔들림이 평균된다.

독립 조건: **샘플 간격 > 노이즈 상관 시간(약 10us).**
16kHz 스캔의 간격 62.5us는 이 조건을 6배로 만족한다.

**④ 분산 스캔이 EMA보다 나은 이유 — 같은 SNR, 훨씬 적은 지연**

둘 다 평균이지만 **평균 창(window)의 길이가 다르다.**

| 방식 | 평균 구간 | SNR | **군지연** |
|---|---|---|---|
| 1회 스캔 | — | 4.48σ | 0 |
| **2회 분산 스캔** | 프레임 **내부** 62.5us | 6.34σ | **31 us** |
| **3회 분산 스캔** | 프레임 **내부** 41.7us x2 | **7.76σ** | **42 us** |
| EMA α=1/2 | 프레임 **간** (125us x N) | 7.76σ | **125 us** |
| EMA α=1/4 | 프레임 간 | 11.9σ | **375 us** |

**3회 분산 스캔은 EMA α=1/2와 SNR이 같은데 지연은 1/3이다.**
분산 스캔은 **이미 지불하고 있는 125us 프레임 안에서** 평균을 끝내기 때문이다.
EMA는 프레임을 넘어가며 평균하므로 그만큼 지연이 쌓인다.

→ **노이즈 저감은 EMA보다 분산 스캔을 먼저 쓴다.** EMA는 분산 스캔으로도 부족할 때만.

**⑤ 한계 — 무한정 좋아지지 않는다**

- **1/f(플리커) 노이즈는 줄지 않는다.** 홀 소자는 1/f 성분이 크고, 이 성분은 상관 시간이
  길어 프레임 내 평균으로는 상쇄되지 않는다. √N은 백색 성분에만 적용된다.
- **온도 드리프트도 마찬가지다.** 이건 자동 재캘리브레이션(5-A.8)의 몫이다.
- **프레임 예산이 막는다.** 4회 분산 스캔은 124.9us로 125us를 꽉 채워 불가능하다(5-F.10).
- 따라서 실용 상한은 **3회(24kHz), 7.76σ**다.

### 5-F.12 분산 스캔의 구현 — 하드웨어 결정이 아니라 펌웨어 파라미터다

**"16kHz 스캔 + 필터"는 두 단계가 아니라 한 동작이다**

평균이 곧 필터다. 16kHz로 스캔만 하고 평균하지 않으면 SNR 이득은 0이다(5-F.11).
정확한 표현은 **오버샘플링 + 데시메이션**이고, 데시메이션 필터가 2점 이동평균이다.

```
스캔 2회 (t=0, 62.5us)  →  키별 2샘플 평균  →  8kHz 출력 1회
                            ↑ 이 평균이 필터. 별도로 추가하는 게 아니다
```

**"필터"라는 말이 가리킬 수 있는 두 가지를 구분해야 한다**

| | 데시메이션 평균 | EMA |
|---|---|---|
| 위치 | 프레임 **내부** (스캔 2~3회) | 프레임 **간** |
| 필수 여부 | **필수** — 이게 √N을 만든다 | **선택** |
| 지연 | 31~42 us | 125~375 us |
| 목적 | 오버샘플링 이득 실현 | 추가 평활 |

→ 16kHz로 가면 **데시메이션 평균은 반드시 따라온다.** EMA는 그 위에 얹을지 말지 별개 판단이다.

**★ 스캔 배수는 PCB 설계 결정이 아니다**

스캔 주파수는 **GPTMR 주기 + DMA 전송 길이**만 바꾸면 되는 값이다.
센서·MUX·배선은 전혀 달라지지 않는다.

→ **펌웨어에서 `SCAN_PER_FRAME` 같은 파라미터로 두고, 실측 후 1/2/3 중에서 고른다.**
→ **하드웨어는 지금 1x 기준으로 확정해도 된다.** 나중에 바꿔도 보드 재설계가 없다.

인터럽트도 **125us당 1회를 유지한다** — 스캔 2회를 DMA로 각각 버퍼에 채우고,
프레임 끝에서 한 번만 ISR을 타 평균 → 키로직 → HID를 처리하면 된다(4.3절 파이프라인 그대로).
평균 비용은 96키 x 약 3사이클 = 288사이클(0.6us)로 무시할 수준이다.

**⚠ 다만 레이아웃에는 영향이 있다 — 주소선 스위칭이 2배가 된다**

| 스캔 | MUX 주소 갱신률 |
|---|---|
| 8 kHz | 8스텝 x 8kHz = **64 kHz** |
| **16 kHz** | 8스텝 x 16kHz = **128 kHz** |
| 24 kHz | **192 kHz** |

5-B.7 ⑤번(주소선 격리)의 설계 기준을 **128~192kHz로 잡아 두는 것이 안전하다.**
아날로그 배선과 주소선을 나란히 두지 말고, 센서 어레이 아래 솔리드 GND를 유지한다.
**이건 지금 결정해야 하는 항목이다** — 나중에 스캔을 올리려면 레이아웃이 이미 감당해야 한다.

### 5-F.9 부품 메모 — TMUX1308A**PWR**

`PWR` 접미사는 **TSSOP-16(약 32mm²)** 이다. 5-C.5에서 TMUX1308을 권장한 근거 중 하나였던
**SOT-23-THN(8.4mm²) 대비 약 4배 크다.**

- **시제품에는 TSSOP가 옳다** — 리워크·프로빙이 쉽고 핸드솔더가 된다.
- **양산에서는 소형 패키지 검토 대상**이다. 12개 x 24mm² = 288mm²를 절감할 수 있다.
- 전기적 특성은 동일하므로 **위 타이밍 계산은 그대로 유효하다.**

## 5-G. 자석축 스위치 자속 스펙 및 센서 재선정 (14차 조사 / **15차 정정, 최신 결론**)

지금까지 이 문서는 자석 세기를 **TI SLYA093의 지오메트리 추정**에만 의존해 왔다.
이 절은 **스위치 제조사가 실제로 공개한 자속 스펙**을 모아 그 추정을 검증한다.

> **단위**: 제조사는 전부 **가우스(Gs)** 로 표기한다. **1 mT = 10 Gs.**
> 아래 표는 원문 Gs를 그대로 싣고 mT를 병기한다.

### 5-G.1 ★ 이 숫자들은 이미 "뒷면 실장" 값이다 (15차 정정)

> **14차 초판은 "제조사 값 = PCB 상면 기준"이라고 적었다. 이것은 틀렸다.**
> 그 전제로 계산한 감쇠 계수 0.393과 "뒷면 ΔB 18.3 mT"는 **철회한다.** → 5-G.5

**센서가 PCB 윗면에 있으면 PCB 두께는 자속에 영향을 줄 수 없다.** 자석과 센서 사이에
기판이 끼지 않기 때문이다. 그런데 TTC / Akko / Kailh는 **두께별로 다른 값**을 낸다:

| PCB 두께 | 초기 자속 | 바텀아웃 자속 |
|---|---|---|
| 1.2mm | 100 Gs | 640 Gs |
| 1.6mm | 90 Gs | **480 Gs** |
| **차이 (갭 +0.4mm)** | −10% | **−25%** |

**두께가 값을 바꾼다는 사실 자체가 측정 기준이 뒷면 실장임을 증명한다.**
자석 → PCB 관통 → 반대면 센서 경로이기 때문에 두께가 곧 갭이다.
업계가 뒷면 실장으로 수렴해 있다는 9차의 관찰(VENOM)과도 일치한다.

**따라서 아래 표의 1.6mm 열은 별도 보정 없이 그대로 설계 입력으로 쓸 수 있다.**

### 5-G.3 분포 요약 (PCB 1.6mm 뒷면 실장 기준)

| 항목 | 범위 | 중앙값 |
|---|---|---|
| 초기 자속 B_init | **9.0 ~ 14.4 mT** | 약 10.8 mT |
| 바텀 자속 B_bottom | **41.3 ~ 67.9 mT** | 약 52.5 mT |
| **ΔB (동작 스윙)** | **30.3 ~ 58.7 mT** | 약 41 mT |
| BA3 ±80mT 점유율 | **52 ~ 85%** (공차 최악 92%) | 약 66% |

**초기 자속은 9~14mT로 잘 모여 있고, 바텀 자속은 1.6배 벌어진다.**
설계는 **바텀 자속 편차**를 견뎌야 한다.

### 5-G.4 ★ 이 데이터가 우리 문서를 검증한다 — n = 1.65

5-A.2는 `B ∝ 1/g^n`에서 **n ≈ 1.6~3**을 가정했고, 5-D는 TI SLYA093의 지오메트리
(바텀 갭 **2.1mm**, 초기 갭 **6.1mm**)를 채택했다. TTC/Akko의 두께별 스펙으로 역산하면:

```
바텀:  640 Gs (갭 2.1mm) → 480 Gs (갭 2.5mm)      [PCB 1.2 → 1.6mm]
(2.1 / 2.5)^n = 480 / 640 = 0.750
n = ln(0.750) / ln(0.840) = 1.65
```

**그리고 이 n으로 초기 자속을 예측하면 — 이건 피팅이 아니라 독립 검증이다:**

| | 예측 (n = 1.65) | 제조사 실제 스펙 |
|---|---|---|
| 바텀 (2.1 → 2.5mm) | (2.1/2.5)^1.65 = **0.750** | 480/640 = **0.750** (피팅에 사용) |
| **초기 (6.1 → 6.5mm)** | (6.1/6.5)^1.65 = **0.9005** | 90/100 = **0.900** ✓ **독립 일치** |

자유 파라미터 하나(n)를 데이터 하나에 맞췄더니 **두 번째 데이터가 저절로 맞았다.**
동시에 이것은 **TI의 6.1 / 2.1mm 갭이 "1.2mm PCB 뒷면 실장" 조건임**을 뜻한다.
5-A.2의 비선형 모델과 5-D의 지오메트리가 **제조사 실측 스펙으로 함께 검증됐다.**

### 5-G.5 ★★ 14차 오류 정정 — 감쇠 계수 0.393 철회 (이중 계상)

14차 초판(및 그 근거가 된 **9차 5-D.8**)은 다음과 같이 계산했다:

```
[철회됨] 제조사 값은 PCB 상면 기준 → 뒷면 실장이면 갭 +1.6mm
         바텀: 64.0 mT x (2.1/3.7)^1.65 = 64.0 x 0.393 = 25.1 mT
         ΔB 54.0 → 18.3 mT   (9차 예측 16.5 mT와 "오차 11%로 일치")
```

**이 감쇠는 이중 계상이다.** 5-G.1이 보였듯 제조사의 1.2 / 1.6mm 스펙은 **이미 뒷면 실장 값**이고,
5-G.4가 보였듯 TI의 6.1 / 2.1mm 갭도 **이미 1.2mm PCB 뒷면 실장 조건**이다.
같은 PCB 두께를 두 번 뺀 것이다.

**9차의 "ΔB 53.7 → 16.5 mT"도 같은 오류다.** 출발점 53.7 mT가 TTC의 1.2mm ΔB
(640−100 = 540 Gs = **54.0 mT**)와 사실상 같은 값인데, 그것이 이미 뒷면 값이었다.
**두 값이 11% 오차로 "일치"한 것은 교차검증이 아니라 같은 실수를 두 경로로 반복한 결과다.**

| | 철회 전 (14차 / 9차) | **정정 후 (15차)** | 배율 |
|---|---|---|---|
| 뒷면 ΔB | 16.5 ~ 18.3 mT | **30.3 ~ 58.7 mT** | **1.8 ~ 3.6x** |
| 상단 0.1mm 신호 | 0.110 mT | **0.260 ~ 0.385 mT** | **2.4 ~ 3.5x** |

**신호가 실제로는 2~3배 크다.** 이것이 아래 5-G.6의 결론을 통째로 바꾼다.

**읽는 법 — 두 지표가 서로 반대로 움직인다**

- **점유율이 낮을수록 포화에 안전**하다 → Jade Ultra(52%)가 최고, KS-20(92%)이 최악.
- **SNR이 높을수록 분해능에 유리**하다 → GEON(13.9σ)이 최고, KS-20(9.4σ)이 최저.
- **KS-20만 두 지표 모두 꼴찌다.** 바텀 자속이 커서 범위를 잡아먹는데, 초기 자속은
  오히려 가장 낮아(9.2mT) 상단 기울기가 작기 때문이다. **비권장 근거가 이중으로 성립한다.**
- 반대로 **GEON Raw HE는 초기 자속이 홀로 14.4mT**라 상단 신호가 크다. 바텀은 54.0mT로
  중간이라 포화 여유도 확보된다. 성능만 보면 최적이나 **PCB 두께 미명시가 걸린다.**

> **계산법**: 각 스위치의 (초기, 바텀, 스트로크) 3값에서 `B ∝ g^-1.65`로 실제 갭을 역산하고,
> 상단(rest) 지점의 국소 기울기 `dB/dg = n·B/g`에 0.1mm를 곱해 "상단 0.1mm 신호"를 얻었다.
> TI 지오메트리를 그대로 쓰지 않고 **스위치별 스트로크를 반영**한 값이다.
> SNR = 상단 0.1mm 신호 / 0.0278 mT.

**포화가 왜 치명적인가** — 바텀아웃 근처 클리핑이라 "래피드 트리거는 상단에서 도니 괜찮다"고
넘길 수 없다. **5-A.6 ③번 2점 정규화가 bottom을 분모 기준점으로 쓴다.** 바텀이 잘리면
캘리브레이션 분모가 스위치·키마다 엉뚱하게 잡히고 거리 변환 전체가 틀어진다.
**상단 분해능이 아니라 캘리브레이션이 먼저 깨진다.** (5-E.11 "포화는 캘리브레이션으로
복구되지 않는다"와 동일한 논리)

**BA3는 전 기종을 담는다.** 최악(KS-20 공차 상한)이 92%로 유일하게 빡빡하고, 나머지는 52~83%다.

**갭을 더 벌려 BA2를 살리는 안은 기각한다.** 산술적으로는 PCB 1.9~2.0mm면 되지만
(TTC 기준 40/48 = 0.833 → 갭 2.5 → 2.79mm), ΔB를 깎아 분해능을 버리는 거래다.

### 5-G.6.2 BA3 전환의 실제 손익 — LSB는 줄고 SNR은 오른다

BA3는 감도가 15 mV/mT로 BA2의 절반이다. 그런데 신호가 2~3배 커졌으므로 상쇄된다.

| 기준 | 13차 확정 (BA2 + ΔB 18.3mT) | **15차 (BA3 + 실제 ΔB)** | 판정 |
|---|---|---|---|
| 전 스트로크 카운트 | 479 ~ 614 | **564 ~ 1,092** | **개선** |
| 상단 LSB / 0.1mm | 8.2 ~ 10.0 (주장치) | **4.8 ~ 7.2** | **저하** |
| 합성 노이즈 σ | 0.91 LSB (BA2) | 0.52 LSB (BA3) | — |
| **상단 SNR** | **4.5 ~ 6.1σ** | **9.4 ~ 13.9σ** | **★ 1.9 ~ 2.3배 개선** |

**"상단 LSB가 8 밑으로 떨어졌다"는 것이 문제로 보이지만, 아니다.**
5-E.8이 이미 못박았다 — **"LSB가 아니라 센서 입력환산 노이즈가 한계다."**
5-A.4의 "0.1mm당 8~10 LSB" 기준은 **σ ≈ 1~2 LSB를 전제로 3σ를 확보하려던 대리 지표**였다.
BA3에서는 σ가 0.52 LSB로 작아졌으므로 같은 3σ 기준의 요구 LSB도 함께 내려간다.
**직접 지표인 SNR로 보면 9.4~13.9σ로, 13차 최선(6.1σ)보다 넉넉하다.**

### 5-G.8 자석 극성 — 여전히 미확정 항목

9차/12차에서 극성이 실장면과 센서 변종을 좌우함을 확인했으나, **극성은 업계 표준이 없다.**

| 출처 | 내용 | 신뢰도 |
|---|---|---|
| GEON VENOM PCB 요구사양 | **N극 하향, 바텀 1600Gs 이하** | 높음 (PCB 벤더 명시) |
| Gateron 호환성 안내 | **N극 하향** PCB와 호환 | 중간 |
| Akko 한국 사이트 | "Astrolink는 **N극 하향** 구조. **S극 하향**만 지원하는 키보드에는 사용 불가" | 중간 |
| Akko 글로벌 Knowledge-Base | 자사 보드는 **S극 하향** 스위치 지원, "극성은 수동으로 뒤집을 수 있다" | 중간 |

> ⚠ **Akko의 두 공식 문서가 서로 모순된다.** 한국 사이트는 "Astrolink = N극 하향"이라 하고,
> 글로벌 KB는 "자사 보드는 S극 하향 지원"이라 한다. 둘 다 맞다면 Akko 보드에 Akko 스위치가
> 안 들어간다는 뜻이 되므로 **최소 하나는 틀렸거나 다른 세대 제품을 가리킨다.**
> (기존 부록 6의 "Akko = N-pole-down 명시" 기록은 한국 사이트 쪽 근거였다.)

**N극 진영과 S극 진영이 공존하고, 심지어 자석을 뒤집어 끼울 수 있다는 안내까지 있다.
제조사 문서를 근거로 극성을 확정하려는 시도는 여기서 포기하는 것이 맞다.**

- VENOM의 **"1600Gs 이하"** 요구는 우리 표의 최댓값 905Gs를 크게 상회한다
  → 상용 PCB는 **KS-20급까지 다 받아내도록** 설계된다는 뜻이다. Outemu 2800Gs가 이 한도를
  넘는다는 점도 그 값이 다른 기준으로 측정됐음을 시사한다.
- **조치**: 리스크 22/30에 묶어 **샘플 스위치 실측으로 확정**한다. 문서로는 결론 불가.
  가우스미터 1대와 스위치 3종이면 반나절이면 끝난다.

1. **자석 극성** — 제조사 문서가 서로 모순. 실측 필수 (5-G.8, 리스크 22)
2. **GEON Raw HE의 PCB 두께 기준** — 미명시. 1.2mm 가정이 틀리면 1순위 근거가 흔들린다

   보장하므로, 센서 다이가 그보다 더 멀면 전 수치가 함께 내려간다.
   **단 이번 정정으로 마진이 2~3배 늘어 리스크 30의 파급력은 크게 줄었다**
   (기존 "8.9 ↔ 5.3 LSB 통과/미달" 갈림 → BA3에서는 양쪽 다 SNR 6σ 이상)

UA2 측정 범위     : +39 mT

| 11차 | UA2 + **BA2 폴백** | UA 재고 미확보 |
| 13차 | **BA2** 확정 | — |
| 15차 | **BA3** | BA2 전 기종 포화 |
| **16차** | **BA3 유지** | **UA2/UA5/BA1/BA2 전부 포화 확정. BA3가 유일 해** |

### 5-H.4 남는 두 갈래

**① BA3로 확정하고 진행 (권장)** — 유일하게 전 조건을 만족한다.
문서화 완비, DigiKey 재고 확인, SNR 9.4~13.9σ. **시제품은 여기서 출발한다.**

**② HAL9303SO 실측 후 양산 전환 검토** — 단가 $13.6 vs $44.9, 전류 77mA vs 250mA로
**BOM $31 / 전류 173mA를 절감**한다. 96키에서 이 차이는 크다.
단 **범위·노이즈가 전부 미공개**라 다음을 실측해야 한다:

| 확인 항목 | 판정선 |
|---|---|
| 측정 범위(포화점) | ≥ 67.9 mT (5-G.2 최악) |
| 정지 시 입력환산 노이즈 σ | ≤ 0.09 mT |
| 비율계측(ratiometric) 여부 | VCC 변동이 출력에 비례하는가 |
| 출력 구동능력 | MUX 10nF 부하 스텝 응답 |

**UA3는 추적 대상으로만 남긴다.** BA3의 2배 감도로 같은 범위를 덮는 이상적 부품이지만,
TI 특성표에 규정이 없어 성능을 보증할 수 없고 유통도 안 된다. TI에 직접 문의할 가치는 있다.

## 5-I. 아날로그 프론트엔드 RC 전면 재유도 (17차, 2026-07-28)

> 회로도 실물(U39 센서단 / U3 MUX단) 검토에서 발견. **5-B.5 · 5-F.2의 세틀링 계산이
> op-amp 게인단 시절 식을 게인단 철회 후에도 그대로 쓰고 있었다.**
> 5-D.7/5-F의 부품 선정 결과는 유지되지만 **RC 상수와 세틀링 예산은 바뀐다.**

### 5-I.0 검토 대상 회로

```
[센서 96개]                          [MUX 12개]              [ADC 12핀]
TMAG5253BA3 ──[R16]──┬──────► Sx  TMUX1308A  D ──[R18 100Ω]──┬──► ADC
  (+3V3A)            └─[C56]─ GND       (Ron 120Ω)            └─[C59/C60]─ GND
                                        C_D(ON) 11pF
```

핵심 전제: **게인단이 없다.** ADC 노드를 구동하는 것은 op-amp가 아니라
`센서(ROUT 1.27Ω) + R16 + C56` 이다. 이 사실이 모든 계산을 바꾼다.

### 5-I.1 누락됐던 항 — 전하 재분배

5-B.5는 MUX **차지인젝션**만 계산했다. 지배항은 **전하 재분배**다.

MUX가 채널 k → k+1로 넘어갈 때, 드레인 기생 `C_d`와 ADC쪽 캡 `C_adc`는
**이전 채널 전압 V_old**를 물고 있다. 여기에 새 채널의 C56(=V_new)이 연결된다:

```
        C_adc + C_d                                  -t/τ_slow
ε₀ =  ───────────────── ,   err(t) = ΔV · ε₀ · e            ,   τ_slow = R16 · C56
      C56 + C_adc + C_d
```

| 항 | 전하량 | 성격 |
|---|---|---|
| 차지인젝션 Q_INJ (TMUX1308A @3.3V) | **0.8 pC** | 채널마다 결정론적 → 캘리브레이션이 흡수 |
| **전하 재분배** `C_adc x ΔV` (1nF, ΔV=1V) | **1000 pC** | **이전 채널 값에 의존 → 캘리브레이션 불가** |

**1250배 차이다.** 5-B.5는 작은 쪽만 계산했다.

### 5-I.2 수치 — ADC쪽 캡(C59/C60) 선택

전제: `C56 = 10nF`, `C_d = C_D(ON) 11pF + ADC핀·트레이스 4pF = 15pF`,
`ΔV = 1V`(BA3 15mV/mT, 바텀 67.9mT vs 인접키 rest → ΔB≈48mT = 0.72V + VQ 산포·자석 편차),
`12bit LSB = 3.3V/4096 = 0.806mV = 0.054mT ≈ 0.0045mm`

| C59/C60 | ε₀ | 스위칭 직후 | R16=1kΩ, 1.5us | R16=100Ω, 1.5us | R16=100Ω, 3us |
|---|---|---|---|---|---|
| **1nF** | 9.26% | 92.6mV | **79.7mV = 99 LSB** | 20.6mV = 26 LSB | 4.6mV = 5.7 LSB |
| **220pF** | 2.34% | 23.4mV | **20.2mV = 25 LSB** | 5.2mV = 6.5 LSB | 1.17mV = 1.4 LSB |
| **DNP** | 0.15% | 1.50mV | 1.60 LSB | **0.42 LSB** | **0.09 LSB** |

**현 회로도(R16 1kΩ + C59 1nF)는 99 LSB ≈ 0.44mm.** 옆 키를 누르면 이 키가 0.4mm
밀려 보인다. 래피드 트리거가 성립하지 않는다.

오차 < 0.5 LSB에 필요한 세틀링 (R16=100Ω, 전체 스캔 = 8 x (t_set + 1.92us)):

| C59/C60 | 필요 t_settle | 전체 스캔 |
|---|---|---|
| 1nF | 5.5 us | 61 us |
| 220pF | 4.1 us | 50 us |
| **DNP** | **1.4 us** | **28 us** |

**ADC쪽 캡은 필요 없다.** 캡을 달면 자기 킥백 회복이 오히려 느려진다
(220pF: 4pF/235pF = 1.7%를 τ_s=52ns로 회복 → 80ns에서 1.55τ → **4.5 LSB 잔류**).
캡 없이 `C_d` 15pF만 있으면 τ_s = 4.2ns = **19τ**로 완전 회복된다.

> ⚠ 초판에서 이 τ를 `(Ron+R18) x C_sh = 220Ω x 4pF = 0.9ns (91τ)`로 적었는데
> **C_d가 빠진 오류다.** 올바른 값은 `(Ron+R18) x (C_d + C_sh)` → 4.2ns typ / **20.6ns 최악**.
> 이 정정 때문에 Ns 판정이 바뀐다 → **5-I.6**

### 5-I.3 MUX 재판정 — Ron이 아니라 C_D

정정된 식에서 MUX가 들어가는 자리는 `ε₀`의 **C_d** 뿐이다.
Ron은 `τ_fast = (Ron+R18) x C_d`에만 나오는데 이건 ns 스케일이라 무의미하다.

| @3.3V | **TMUX1308A** | **TMUX1108** | 이 회로에서 |
|---|---|---|---|
| **C_D(ON)** | **11pF** typ / 40pF max | **65pF** typ | ★ **1108이 6배 불리** |
| C_D(OFF) | 7pF | 60pF | 〃 |
| Q_INJ | **0.8pC** | 2pC | 1108이 2.5배 불리 |
| Ron | 120Ω typ / 330Ω max | 4Ω typ / 8.75Ω max | **무관** |
| 누설 | ±1nA typ | ±5pA typ | 무관 (100Ω x 1nA = 0.1uV) |
| 제품 성격 | *Low ON-capacitance / **Optimized for high-impedance loads*** | *Low Ron / Low leakage* — 응용도가 **op-amp 버퍼 전제** | 1308A가 정확히 이 용도 |

| | ε₀ | R16=100Ω, 1.5us | R16=100Ω, 3us |
|---|---|---|---|
| **TMUX1308A** (C_d=15pF) | 0.150% | **0.42 LSB** | **0.09 LSB** |
| TMUX1108 (C_d=69pF) | 0.685% | 1.90 LSB | 0.42 LSB |

```
τ_fast = (Ron + R18) x C_d
  TMUX1308A : (120 + 100) x 15pF = 3.3ns
  TMUX1108  : (  4 + 100) x 69pF = 7.2ns   ← Ron을 30배 낮췄는데 오히려 느리다
```

**저Ron은 FET를 키운 결과이고 그 대가가 용량이다.** 5-C.4가 짚었던
"Ron·C_on이 원리적으로 크다"는 트레이드오프가 여기 그대로 적용된다.
**TMUX1308A 유지. 다만 선정 근거를 Ron → C_D로 바꾼다.**

### 5-I.4 확정 상수

| 부품 | 회로도 | **확정** | 근거 |
|---|---|---|---|
| **R16** (센서 직렬) | 1kΩ | **100Ω** | τ_slow 10us → **1us**. 유일하게 효과 있는 레버 |
| **C56** (센서 캡) | 10nF | **10nF 유지** | 저장소는 MUX **앞**에 있어야 한다. C56/C_d = 667배 |
| **R18** (MUX 출력) | 100Ω | **100Ω 유지** | ESD·전류제한. τ 기여 3.3ns로 무해 |
| **C59 / C60** | 1nF / 220pF | **둘 다 DNP** | 매 스텝 재충전 대상 = 순수 부채 |
| MUX 세틀링 | 1.5us | **3.0us** | C_d 최악(40pF max)에서도 0.5 LSB 아래 |

**대안 B (밴드제한 유지)**: `R16 = 100Ω + C56 = 100nF` → τ=10us, fc=16kHz 그대로이고
ε₀ = 0.015%로 **세틀링 없이도 0.19 LSB**. 다만 TMAG5253 데이터시트가
**직결 용량 상한 1nF**을 명시(9.2.3절)하므로 100Ω 아이솔레이션에 100nF은 검증이 필요하다.

**R16을 낮추면 fc가 15.9kHz → 159kHz로 밴드제한을 잃지만**, BA3 출력 노이즈는
`V_N = 2.3mVpp = 0.35mV RMS = 0.43 LSB`(6.6절 특성표)뿐이라 필터 유무 차이가 0.1 LSB다.
99 LSB와 바꿀 값이 아니다.

### 5-I.6 두 번째 크로스토크 — ADC 내부 채널 (17차 추가 검토)

5-I.2는 **MUX 채널간** 크로스토크만 다뤘다. 별개의 경로가 하나 더 있다.

```
ADC0 하나가 6개 핀을 순차 변환 → 샘플캡 C_sh(4pF)가 핀을 옮겨다닌다
   핀1 변환 → 핀2로 이동할 때 C_sh는 **핀1의 전압**을 물고 온다
```

이건 MUX 세틀링(3us)으로 해결되지 않는다. **세틀링이 끝난 뒤 변환 직전에 발생**하므로
오직 **샘플 시간(Ns)** 으로만 흡수된다.

```
              C_sh                                    -t_sample/τ_s
ε_adc = ──────────────  ,  err = ΔV · ε_adc · e                  ,  τ_s = (Ron+R18)·(C_d+C_sh)
          C_sh + C_d
```

> ### ⚠ 5-F.2 / 5-I.2의 Ns 판정은 틀렸다
>
> 앞서 `τ = 220Ω x 4pF = 0.9ns, 80ns = 91τ`로 계산했는데, **C_sh만 넣고 C_d를 빼먹었다.**
> 노드에는 드레인 용량 C_d가 함께 걸려 있고 둘 다 같은 R을 통해 충전된다.
> 올바른 τ는 `(Ron+R18) x (C_d + C_sh)`로 **4.6배 크다.**

| | C_d | R=Ron+R18 | **τ_s** | ε_adc |
|---|---|---|---|---|
| typ | 15pF | 220Ω | **4.2 ns** | 21.1% |
| **max (85°C)** | 44pF | 430Ω | **20.6 ns** | 8.3% |

**ΔV = 1.5V**(같은 ADC의 다른 MUX 채널끼리는 스윙이 더 크다) 기준 잔류 오차:

| Ns | t_sample | typ (19.1τ) | **max (t/20.6ns)** | 판정 |
|---|---|---|---|---|
| 2 | 40ns | ~0 | 1.94τ → 17.9mV = **22 LSB** | ✗ |
| **4** | 80ns | ~0 | 3.88τ → 2.56mV = **3.2 LSB** | △ |
| **8** | **160ns** | ~0 | 7.77τ → 0.052mV = **0.06 LSB** | ✓ |
| 16 | 320ns | ~0 | 15.5τ → 0 | 과잉 |

**Ns = 8 확정.** typ 조건에서는 Ns=2로도 문제없지만 **최악 코너(85°C, C_D 40pF max,
Ron 330Ω max)에서 Ns=4는 3.2 LSB를 남긴다.** Ns=8의 비용은 변환 360 → 440ns,
전체 스캔 41.3 → **45.1us(+3.8us)** 뿐이다.

`t_conv = (14 + Ns) / f_adc` (SDK: `conversion time ∝ (convert_clock_number + sample_clock_number) x 2^n`,
`hpm_adc16_drv.h:187`) → Ns=8, 50MHz에서 **440ns**.

**여기서도 ADC 핀 캡은 해가 된다.** 캡을 달면 C_d가 커져 ε_adc는 줄지만 τ_s가
같은 비율로 커져서 순효과가 나쁘다 (220pF: ε 1.7%, τ_s 52ns → 80ns에서 1.55τ →
**4.5 LSB**). 5-I.4의 DNP 결론이 이 경로에서도 유지된다.

### 5-I.7 세틀링 3us는 충분한가 — 전 항목 합산

| # | 항 | 시정수 | 3us 시점 잔류 (ΔV=1V) |
|---|---|---|---|
| 1 | MUX 전환 t_TRAN | — | 51ns typ / 54ns max, 세틀링에 포함 |
| 2 | 드레인 전하 재분배 (빠름) | (Ron+R18)xC_d = 3.3ns typ / 19ns max | 완전 소멸 (150τ 이상) |
| 3 | **C56 회복 (지배항)** | **R16 x C56 = 1.0us** | typ **0.09 LSB** / C_D max **0.27 LSB** |
| 4 | 이전 사이클 잔류 (7스텝 = 36us) | 36τ | 0 |
| 5 | MUX off 채널 누설 (7ch x 25nA max) | — | 7 x 25nA x 100Ω = 17uV = 0.02 LSB |
| 6 | **ADC 채널 크로스토크** | **τ_s = 20.6ns max** | **세틀링과 무관. Ns=8로 흡수** (5-I.6) |

**3.0us = 2.95τ_slow.** 최악 코너(C_D 40pF max)에서도 0.27 LSB로 판정선(1 LSB) 안이다.
여유를 더 원하면 **4.0us(4τ, 0.10 LSB)** 로 올려도 전체 스캔이 53.1us라 예산 안이다.
**단, 3 → 4us를 올려도 5-I.6의 ADC 크로스토크는 전혀 줄지 않는다** — 그건 Ns의 몫이다.

### 5-I.8 시제품 실측 항목

| # | 항목 | 판정선 |
|---|---|---|
| 1 | 센서 OUT 스코프 — 100Ω/10nF 부하에서 링잉 | 없을 것. 있으면 220Ω(세틀링 5us)로 |
| 2 | **같은 MUX의 인접 스캔 채널** 키를 누르며 대상 키 ADC 값 변화 | **< 1 LSB** (5-I.2 검증) |
| 3 | **같은 ADC의 다른 MUX 채널** 키를 누르며 대상 키 ADC 값 변화 | **< 1 LSB** (5-I.6 검증. Ns를 2/4/8로 바꿔가며) |
| 4 | 세틀링을 1.5 / 3 / 4us로 스윕하며 2번 값 변화 | 3us에서 평탄해질 것 (5-I.7) |
| 5 | C_D 실측 (11pF typ / 40pF max 중 어디인지) | ε₀·τ_s가 모두 여기 비례 |
| 6 | HPM5361 ADC 샘플캡 **C_sh = 4pF** 가정 검증 | 5-I.6의 전제. 크면 Ns를 더 올려야 한다 |
| 7 | ADC 채널간 격리(isolation) 스펙 | HPM5300 데이터시트 미확인 항목 |

**2번과 3번은 다른 현상이다.** 2번은 세틀링(3us)으로, 3번은 샘플 시간(Ns=8)으로
막는다. 증상이 비슷해서 한쪽만 고치면 나머지가 남는다 — **반드시 분리해서 측정할 것.**

### 6.1 HPM5361에서 **지원하지 않는** ADC16 기능 (확인 완료)

`hpm_soc_ip_feature.h`에 정의된 ADC16 기능은 다음 3개뿐이다:
`ADC16_HAS_MOT_EN`, `ADC16_SEQ_HCFG_EN`, `ADC16_HAS_BUS_MODE_EN`

따라서 아래는 **미지원**:

- `ADC16_HAS_ADC_LOOP` — 하드웨어 오버샘플링 없음 → SW 평균 필요
- `ADC16_HAS_DMA_SEQ16BIT` — 16bit 전용 DMA 없음 → 샘플당 4바이트
- `ADC16_HAS_DIFF_MODE` — 차동 입력 없음
- `ADC16_SEQ_STOP_POS_INT` — 없음
